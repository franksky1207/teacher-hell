### AVG區塊的實際鍵名示意

插入第4區指定位置的唯一 `avg` 程式碼區塊必須為**合法JSON**，有 `opening.Pxx`（其鍵與開場可見分頁對應）及`results.R1～R4.pages`；每個R有非空分頁。下例僅示範結構，不代表一篇完整可驗收的故事：

```avg
{
  "opening": {
    "P01": {"scene": "school:classroom", "enter": ["student_a"]}
  },
  "results": {
    "R1": {"pages": [{"speaker": "student_a", "text": "【本篇R1實際台詞】"}]},
    "R2": {"pages": [{"speaker": "student_a", "text": "【本篇R2實際台詞】"}]},
    "R3": {"pages": [{"speaker": "student_a", "text": "【本篇R3實際台詞】"}]},
    "R4": {"pages": [{"speaker": "student_a", "text": "【本篇R4實際台詞】"}]}
  }
}
```

### 單一原稿與分階段工作草稿規範

- **預建未開始草稿（Pre-build Unstarted）**：於工作分支預先建立的 `Gxxxx.md` 帶入原規劃已確定之標題、種子、四碼、四欄摘要、規劃題材標籤，並以 `【待填：階段一…】`／`【待填：階段二…】`／`【待填：階段三…】` 保留規劃配置與四碼因果參考；第4區開場、四選項（含 `emotional` 欄位）、`avg` 與第5區 `R1～R4` 均維持未完成佔位，對應 `驗收紀錄/evidence/Gxxxx.json` 狀態為 `prebuild-unstarted`（各階段 `not_started`）。規劃參考不得直接冒充已完成合法角色槽位或數值審查。
- **階段一工作草稿**：接續預建草稿完成第1～3區（固定資料、摘要、實際合法角色槽位與知情／權責條件）及第4區`### 開場`、`### 四個最終教師選項`；第4區`avg`與第5區`R1～R4`保留`【待填：階段二】`／`【待填：階段三】`佔位標記。六選三抽選證據、情緒洗牌與**四條「後果可行方向」**寫入本篇`驗收紀錄/evidence/Gxxxx.json`，不另建第六區、不建立第二套Markdown或龐大人物知情資料庫。
- **階段二工作草稿**：承接第1～4區既定事實（哪些人物已知情／未知情、已發生客觀事件、超出導師權責事項、共用事實），補齊第5區`R1～R4`完整正文、各結果獨有客觀後果、合法底層增減與58庫四狀態，並於`驗收紀錄/evidence/Gxxxx.json`補齊四R因果與非零變動理由；`avg`仍保留階段三佔位。
- **階段三定稿**：補齊第4區唯一合法`avg` JSON並清除所有`【待填】`標記，完成[04](./04-G品質與驗收.md)驗收。預建草稿及階段一、二之未完成工作草稿**不得冒充正式合格內容，亦不得匯出為已核准正式故事**。

**硬規則**：固定種子與四碼來自[`data/g1752-fixed-seed-assignments.json`](../../data/g1752-fixed-seed-assignments.json)，上述G0001四碼及示範標籤、選項情緒位置均非正式創作決定；真實標籤需依故事內容判定。恰四選項、恰一情緒；A→R1、B→R2、C→R3、D→R4，四R數值與因果依[01](./01-G數值與固定結果.md)及[04](./04-G品質與驗收.md)。六選三真實候選、四條後果可行方向（階段一）、四份R因果及非零變動理由（階段二）與各階段完成狀態放進本篇**驗收JSON**，不建第六區，不放入玩家故事。G不得有T的4×8矩陣、R5～R8或V3 A～E。
