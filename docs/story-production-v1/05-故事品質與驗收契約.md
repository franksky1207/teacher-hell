# 《教師荒謬地獄》｜故事品質、AVG 接線與驗收契約

> 本文件只定義**什麼叫合格、如何證明、失敗如何退回**；不再複述製作步驟。唯一操作順序見 [03 一條式主流程](./03-故事創作精簡SOP.md)，原稿固定欄位見 [04 五區塊格式](./04-五區塊故事稿範本.md)，人物及時間硬規則分別見 [01](./01-人物數值與四碼資格.md)、[02](./02-事件分類與時間資格.md)。機械測試、GPT 內容審查與瀏覽器目視是**三種不同的證據**，不能互相冒充。

## 一、完成狀態是逐關卡判定，不是單一「已完成」

| 狀態 | 合格時必須已有的證據 | 未完成時禁止宣稱 |
|---|---|---|
| **S1 原稿完稿** | 五區塊＋合法角色、四碼、四個選項、八 R、矩陣及對應語意 | 內容／AVG 已通過 |
| **S2 原稿核准** | 七項實質審查、合法數值、32 格因果、必要查重與實際執行的相關 CLI 證據 | AVG 已接線或已發布 |
| **S3 AVG 編排完成** | P 開場與八 R 有合法演出分頁、場景、人物、表情、特殊介面與配樂 | 立繪實測已通過 |
| **S4 內容與技術驗證** | 逐 R 對照原始事實與知情、全部頁面編譯、必要人物進退場及回歸測試 | Pages 已讀到最新版 |
| **S5 發布版本已確認** | 故事索引及單篇 JSON 的來源提交完全相同、AVG 測試版載入該稿 | 實際瀏覽器畫面全部通過 |
| **S6 演出驗收** | 對應故事及各 R 的關鍵場景、翻頁、立繪、訊息與配樂畫面證據，無待修硬錯 | 正式遊戲主引擎已接入 |
| **S7 正式遊戲整合** | 另經核准的主分支接線、真實玩家世界事件抽選／存檔／結算測試 | 當前工作分支單憑 AVG 就算 S7 |

**交付門檻**：使用者要求「一批故事 AVG 製作完成」時至少 S1～S5，且實際瀏覽器工具可用時應完成 S6；沒有工具就明列 S6 未驗而非偽稱已完成。要求「正式遊戲接線」才處理 S7，不能提前觸動 main。每篇以 ID、Git SHA、版本、證據路徑及最後一次驗收日期記錄，修稿後舊證據不得繼續冒稱有效。

## 二、原始故事：不得破壞的機械硬規則

| 關卡 | 必須成立 |
|---|---|
| 五區塊及類型 | 04 的五個 `## 1｜`～`## 5｜`、必填欄位、四欄摘要；T/G/P/H4 依02各走本身制度，T/G 正式種子不可被 P 借用 |
| 唯一故事 ID | 同一 Markdown、檔名、`story_id` 一致；正式 ID、已占用種子與配額不任意洗牌；一局同 ID 只出現一次（正式引擎待另接線驗收） |
| 人物與四碼 | 只用 2400 組既有 S 種子的原四碼；每碼有合法持有人及具體因果；無數值文字人物不可持碼或結算；玩家只用本人合法碼 |
| 四個行動 | A～D **恰四個實質不同且可行的教師行動**，只有一個 `emotional=true`、另三個 false；選項已完成的教師行動不得被 R 推翻 |
| 先行候選 | 先有一個合理情緒候選及六個互不重複的普通候選，實際隨機取三個，再實際隨機排列 A～D；候選與映射只保留在審查證據 |
| 八個 R | R1～R8 共用於 A～D，真正不同、客觀後果清楚、人物自主反應合理，不按好壞排序、不替其他教師或學生擅自決定 |
| NPC 數值 | 僅合法持有人及原四碼，單人單碼單 R 幅度 **−8～+8**；NPC 八 R 均值 ±3 限制**已取消**；警示要實質說明但非機械禁令 |
| 結果權重 | 每個 A～D 對八 R 各填 4／2／1／0；每列 0≤2、每欄 0≤1、每列至少一個非零；**0 只限客觀互斥，沒有 0 完全合法** |
| V3 四狀態 | **精神、熱忱、情緒、掌控**，先抽四組不重複 A～E 數值再反向寫八 R；每 R 最多兩個 0，各欄八 R 總和 −4、平均 −0.5；不能冒用已退役的體力版或 V2 門檻 |
| 時間與主題 | T 必須符合核定時間、合法前後窗口、配額、在籍及知情；不同 T 主題相同日期共享單日 6 篇創作配額。G 不可用通用情境冒充 T，P 不套用八 R |
| 禁止復活 | 已取消的 K 類／1.6、1.0、0.7 抽篇倍率不能恢復；**選哪篇故事的未定抽選配置**不得擅自補成等機率 |

### V3 四狀態的五個唯一合法組別

每篇從 A～E 隨機選**四個不同組別**，對應四種狀態；每組的八數值可隨機分配給 R1～R8，必須保持原組別多重集合，不能為故事文采反覆重抽。來源 `state_rules_version=3`；歷史版另依原版規格檢查。

| 組別 | 八個合法值（由高至低） |
|---|---|
| A | +1、+1、0、0、−1、−1、−2、−2 |
| B | +2、0、−1、−1、−1、−1、−1、−1 |
| C | +1、+1、0、−1、−1、−1、−1、−2 |
| D | +2、+1、0、−1、−1、−1、−2、−2 |
| E | +1、+1、+1、0、−1、−2、−2、−2 |

每欄總和均為 −4，等權平均 −0.5，**不是依選項權重計算期望值**。精神降低不自動表示熱忱降低，掌控不等於壓制或教師專業能力；每個非零狀態都要找到具體事件理由。NPC 單 R ±8 是另一個數值機制，不得混同。

### 4×8 的三十二格因果：不能拿數字倒推故事

1. 先列 A～D 教師**已完成**的客觀行動與八個 R 的必要前提，再對每格判「相容／敘事待補／客觀互斥」及「促進／中性／抑制」。
2. 逐格提出具體機制：4 為確有顯著促進、2 為自然可達、1 為有合理抑制但仍可達、0 為客觀互斥。**教師沒選某行動、另一人可能不配合、機率很低都不等於不可能**。
3. 檢查每列及每欄，權重只是相對值；每列以自己八項加總正規化，4／2／1 無固定百分比。每個 R 在不同合法行動下仍必須保持相同文字與數值。
4. 只要 R **原始故事、客觀後果或必要前提**改動，立即重審全部 32 格的相容性、方向與機制，合理的原權重可保留；若只修改第 4 區 AVG 演出且事實完全沒變，應核對不變項，不重抽教師四狀態或機械重判所有權重。
5. 正式證據每格至少包含 `choice`、`result`、`compatibility`、`causalDirection`、`reason`、`actionPreserved`、`weight`。不可以空泛的「合理」「有機率」取代具體因果。

## 三、GPT 必須真正審閱的七項品質門檻

| 證據鍵 | 通過標準 | 典型退件 |
|---|---|---|
| `storyAndRoles` | 校園情境、教師困境獨立；人物有其自身需要、職權、知情與合法身分，不硬套固定兩位學生 | 臨時背景人物擅自變常駐角色、教師知道不可能知道的事 |
| `fourCodes` | 原種子四碼都能指出具體情節作用與合法持有人，NPC 選角／增減因果可信 | 為湊四碼硬加毫無關聯的 NPC 數值 |
| `fourChoices` | 四個行動真有不同已完成事實／利弊；情緒行動自然可理解而非假錯項；六選三與映射一致 | 四選項只換語氣或教師行動變成別人的反應 |
| `eightResults` | 八 R 共享且轉折不同，人物有自主反應、事件有發展與合理收束；逐人逐碼與四狀態有因果，**不能替導師指定與可達選項互斥的後續行動** | 後段縮水、八 R 同義換語氣、每篇都由老師宣導原則結束、結果取消既成行動 |
| `causal32` | 三十二格逐一分析相容、方向、具體原因與實際權重 | 不可能結果硬填 1、為湊差異把 2 改成 4 |
| `timeAndLaw` | 核定窗口、當日校曆、學生在籍與資訊先後、法定程序及任課教師權責成立 | 活動日違規抽 T/G、導師擅改別科評分、私下資訊洩漏 |
| `duplicates` | 摘要及全文兩關與同池／相近 T/G 類型實質比對，整主題完稿合看全部故事 | 換姓名與道具卻重複相同衝突、選項、R 與數值機制 |

### 唯一字數與創作品質規範（適用開場 P、八結果 R 與 AVG）
 
**唯一計數法（創作、原稿檢查、AVG 驗收共用）**：只算玩家可見的**實際創作正文**（台詞、訊息正文、必要旁白；含標點、不含空白）。以下**全部一律算 0 字**，不得因其長度而提高開場或結局字數：
- **程式變數**：`{{student_a.name}}`、`{{guardian_a.name}}`、`{{teacher.subject}}` 等所有 `{{...}}`，包含大括號與變數名稱，**整段刪除、不換算任何實際姓名**。
- **AVG 演出／控制欄位及其值**：人物進場 `enter`、退場 `exit`、說話者 `speaker`、表情 `expression`、姿勢 `pose`、場景 `scene`、配樂 `music`、呈現方式 `presentation`；人物 ID、表情代碼、場景代碼、陣列符號等也不算。
- **技術結構**：P 頁碼、R 編號／標題與標籤、`avg` JSON 的鍵名與格式符號、Markdown 標記、程式碼與其他非正文欄位。

**先擷取正文再計數**：原稿開場合計所有 P 頁文字；結局各 R 只取「玩家可見結果」正文；AVG 只讀每頁 `text` 值並合計，**絕不能把整包 AVG JSON 序列化文字直接拿去計數**。正文裡的合法故事文字照常計入，即使恰好與技術欄位名稱同字（例如人物在台詞中說出「音樂」）。分頁不影響總字數。唯一實作 `scripts/story-visible-length.js`：`storyVisibleLength` 計正文、`storyAvgVisibleLength` 計 AVG 頁面 `text`，所有創作審核、原稿檢查與回歸測試須沿用，不另設第二種算法。
 
| 項目 | 計數後字數 | 審閱級距（不是機械合格證明） |
|---|---|---|
| **故事開場 P（全部 P 頁合計）** | 少於 90 | 優先複核是否缺事件起因、人物互動及教師困境 |
| | 90～109 | 加強審查完整度 |
| | **110～140** | 一般參考範圍 |
| | 超過 140 | 檢查節奏、是否重講已知資訊，非硬性違規 |
| **每個 R 結局** | 少於 70 | 優先複核 |
| | 70～89 | 檢查人物反應、轉折與收束 |
| | **90～129** | 一般參考範圍，達底線不等於內容合格 |
| | 130 以上 | 檢查節奏和資訊密度，**不是字數上限** |

**創作起點**：開場與每個 R **先以約 130 字構思**、依戲劇需要自然修訂；不是要求每篇硬到 130 字，更不能集體瞄準最低級距。內容完整的較短稿可以附實質理由保留；情節需要 150～200 字以上也可以，不能為求符合區間刪除人物交鋒。開場不設機械硬性下限；已驗收故事不因計數法修正自動判不合格。

**三項最高原則（開場／結局一體適用）**：①**不重複敘述**：每頁須有新資訊、人物反應、情緒推進、動作或必要收束；已說過的事不再讓旁白／下一個人再說一遍，八 R 不可僅同義改寫。②**人物對話優先**：現場對話、通訊／電話應符合角色在場與知情；能合理演出就不要用旁白代講，禁止角色朗讀第三人稱。③**字數不能掩蓋偷工減料**：不能瞄準 90 字、為湊約 130 字灌水，或後四個 R 越寫越短。字數警示只觸發**內容複核**，不能單靠字數、speaker 數量或檢查器通過宣稱劇情品質合格。每批統計開場、各 R、90～110 字集中情形和前後批差異，僅對確實缺戲者局部修稿並同步 AVG／因果驗收。

**七項是實質判斷，不是七個保證準確的程式分數**。僅格式正確、關鍵字找到、或機械腳本成功都不能代替逐篇內容審查。G01～G11 標籤須依完稿的題材實質複核：有依據的保留，漏貼的補上，僅因出現家長、設備或教師便貼的要移除；不為全庫比例硬湊標籤。

**六選三證據格式維持程式契約**：`ordinaryChoiceSelection` 含 `ordinaryCandidates`（ID1～6、各一個不同的普通行動）、`selectedIds`（三個不同合法 ID）、`finalChoiceMap`（A～D 恰一個 `"emotional"` 及三個抽中 ID）。這些資訊、`characterAudit`、`npcDeltaAudit`、`npcWarningReviews` 及 32 格證據放正式審查紀錄，不增第六故事區塊；現有證據檢查器有既定欄位與文字長度要求，**應直接依現行程式格式輸出，不得另造不相容 schema**。審核者與結論在既有 `reviewer`、`verdict` 欄位，證據必須對應現稿 Git SHA，不可用歷史證據冒充。

## 四、AVG 演出驗收：每一個結果的每一頁

| 類別 | 必須逐篇／逐 R 驗證的條件 | 可自動驗的範圍 | 必須另看劇情或畫面的部分 |
|---|---|---|---|
| **原稿不變** | 原第 5 區 R 文、客觀後果、NPC 增減、教師狀態、4×8 不因純演出改寫而變 | 與基準提交逐字比對 | 是否真的保留事件的相同含意 |
| **對話／旁白／重複** | 優先以合法角色的自然台詞推進；已演出的事件不逐頁重述，必要旁白才保留。R 第五區與 AVG 須是同一套事件 | `text` 非空、`speaker` 與 `presentation` 合法；直接分頁稿可逐字比對；字數僅依上節唯一計數法 | 逐頁確認對話自然、沒有重複敘述／空泛補字、事實與知情不被演出篡改 |
| **分頁** | P 開場與 R1～R8 可獨立翻頁、前一頁、回 R 首頁；每篇唯一 `avg` 必須在 `### 開場` 前，**不可把 JSON／程式區塊印到玩家 P 頁** | `results.R*.pages` 非空、R 隔離、演出標記位置與玩家可見文案掃描 | 是否把過多敘述塞進一頁、是否在正確位置斷頁 |
| **人物與立繪** | 現場說話／動作者須合理在場；退場後再出現須重新入場；遠端或單純被旁白提及的人不強制現場入鏡；NPC 同框≤2，各 R 獨立 | 合法角色 ID、登場狀態、進退場、同框人數 | 旁白焦點是否需要切換、遠端與現場的差異、表情與姿勢自然性 |
| **場景、特殊格式** | 背景、服裝、時段、表情／成人姿勢依情節；遠端通話用 phone/chat；家長不因被提及就站到教室 | 合法場景及表情、姿勢枚舉 | 電話與現場是否混用、演員位置及實際圖像正確性 |
| **人物知情／事件順序** | 誰先說、誰後來知道、親師秘密是否外洩、教師與任課教師是否曾真的見面 | 僅能檢查預先明列的情境斷言 | 逐 R 原文對照：順序與職權不可被台詞篡改 |
| **事件配樂** | 每篇只有一個 `music`，整個 P／R 不依結果換曲 | 音樂代碼與不存在逐 R 曲目 | 實際播放器能播、事件後回原情境音樂 |
| **正式資料版本** | 索引、故事 JSON 的 sourceCommit/sourceBranch 一致；不得用舊資料冒稱成功 | 不同版本拒絕載入、發布期自動重讀、CI | 真正公開網址能載入同一版故事及正確 R |
| **裝置與瀏覽器** | 手機／桌機、不同行動切換、場景畫面與翻頁按鍵功能 | 有相應瀏覽器工具才能跑自動 UI 測試 | 真實可見畫面；若未執行則標「待實測」 |

**真實工具邊界**：目前的多頁回歸 `test/story-preview-multipage.test.js`、人物連續性 `test/story-preview-cast-continuity.test.js`、版本核對 `test/story-preview-snapshot.test.js` 都不能推論所有 124 頁視覺內容已通過。批次量產時必須擴充**受影響故事的代表性情境斷言**；不能單靠「測試綠燈」或使用者逐張截圖來找問題。

## 五、批次驗收的證據格式與禁止交付條件

**每批最低要留下**（文字與 AVG 一併驗收，不是只計篇數）：
- 故事範圍、來源 Git SHA、各篇原稿／演出狀態、**逐篇開場字數、八 R 字數（程式變數均計 0、含各十篇平均與警示）、必要的短稿原因與重複敘述／人物對話審查、R 數、AVG 分頁總數**、合法角色與特殊場景。
- 原始故事與 AVG 的**400／480 等實際全部 R**逐筆對照：直接分頁的逐字一致率、改編台詞的事實對照；既成行動、八 R 差異、人物知情、因果、數值，是否純演出及第五區改動後 32 格是否重判。不得以抽樣取代文字全檢，也不得用字數過關取代語意審查。
- 所用的定向 Node 命令及真實通過結果、GitHub Actions 名稱／結果；**沒執行就填未執行**。
- 發布的索引與詳情 SHA 是否一致、測試網址的實際載入結果；如未能用瀏覽器操作，註明「僅已發布，瀏覽器待驗」。
- 具體修正故事、R、頁碼、原因，不能只填「已全數檢查」；若有仍待修的硬錯則此批不得封關。

**任何一項下列情況都不得標為完全驗收**：AVG 原始 JSON 外露、R 文字與 AVG 不同步或改編後事實變動、退場人物無合理回場卻參與現場情節、單批結局敘事明顯縮水而未複核、只跑完 Node 沒有內容審查；劇情誤將旁白變 NPC 台詞；人物在場／遠端通話違背故事；宣稱未發生的事件已完成；更改第 5 區卻沒有重核 32 格；故事索引與 JSON 版本不同；Actions 成功但未核對公開資料；明知仍有翻頁、立繪或畫面錯誤卻交給使用者逐頁修。

## 六、局部修稿與測試節制

**退件處理**：內容核心重複→回摘要與必要人物；四碼不合法→回人物／種子規劃；選項錯→重核該選項八格及相關 R；原始 R 事實改動→全 32 格語意重判；單純 AVG 立繪或旁白錯→只修相應 `avg` 頁並重跑該批定向測試與演出核對。**不因一個美術接線錯就重寫全篇八 R，也不因完成率高而放水**。

正式驗收按需使用 `npm run content:production -- audit` 與 `audit <ID> --evidence <JSON>`；創作階段分別採 `summary`、`choices`、`full`；只跑本批／本檔相關 Node 測試。不能為了驗證一個 R 重跑不相關三年模擬或無限制反覆啟動整套 CI。結果必須標註「已驗內容」「已驗資料」「已驗畫面」各自的範圍。

**最後提醒**：本契約適用 T/G 原稿及其 AVG 轉換。P 事件與 H4 仍依本身制度驗收，不可照抄 T/G 的八 R、四碼或教師 V3 生成公式；目前也不得自行宣告正式三年平衡已完成。
