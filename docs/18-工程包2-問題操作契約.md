## 單一權威與版本

唯一權威為已確認的 `facts[].data.causality`。沒有永久 `issues.status`，沒有文字推測、亂數 ID 或新結算器。`causality` 不存在時是合法舊事實，並未建立正式問題；存在時必須為嚴格白名單 `{version:1, operations:[...]}`，非空操作清單。未知版本、未知操作、未知欄位均拒絕。

## 識別與操作白名單

由 `src/runtime/issues.js` 匯出的函式定義正式編碼，JSON tuple 避免分隔字元碰撞：

- `issueId(factId,localKey)`：`issue:` 加上 `JSON.stringify([factId,localKey])`。
- `issueOperationId(factId,index)`：`issue-operation:` 加上 `JSON.stringify([factId,index])`；index 是 operations 的零起算位置。

同一事實 localKey 不得重複；同人物同 kind 可有任意不同 localKey／建立事實。後續操作必須引用完整 ID，不依人物、kind 或歷史分類配對。

| type | 其餘必要欄位 |
| --- | --- |
| open | localKey、kind、actors、details、evidenceFactIds |
| progress | issueId、expectedPreviousOperation、assessment、details、evidenceFactIds |
| close | issueId、expectedPreviousOperation、reason、evidenceFactIds |
| invalidate | issueId、expectedPreviousOperation、reason、evidenceFactIds |

文字／ID 均須非空。actors 是不重複、非空的實際人物 ID 清單，且必須屬於建立事實 subjectIds；人物真實性沿原世界驗證。此處先用人物清單，責任角色與見證／傳播作者綁定留工程包 3，不提前設計平行語法。

assessment 限 `improved/worsened/changed/uncertain`，不新增嚴重度。reason 為非空原因碼，由事件語意審查確認合法性；`close` 明確拒絕 `withdrawn`，撤回應使用 `invalidate` 指向那一件義務。程式不假裝能從任意原因文字辨識履約、畢業或家庭問題是否真的消失。

## 證據與生命週期

- open 建立 active 狀態，查詢回傳 `state:'open'`；progress 後仍 open，最新操作表達進展。
- close → `closed`；invalidate → `invalidated`。任何終止後的一般 progress、close 或 invalidate 均拒絕。可從 open 直接收束，不強迫製造一次 progress。
- evidenceFactIds 必須非空、不重複，只能引用本次承載事實或更早且已明列於本次 causeIds 的事實。承載事實本身是本次已確認的客觀證據，不是把自身放入 causeIds。
- 後續操作的建立根事實、最新操作所屬事實，若非本次承載事實，都必須列入 causeIds。原世界驗證要求 causeIds 嚴格早於本事實；缺來源、未來／自我 cause 均拒絕。
- expectedPreviousOperation 必須等於折疊當時的最新 operation ID；不能指向同根的舊進度或另一問題操作。
- 同一事實依 operations 陣列先後執行，可先 open 再 progress／終止；只能引用已處理的問題及前序操作，不能向後引用。
- 復發建立新 fact/localKey 問題，以 evidenceFactIds＋causeIds 引用舊根；不重開已終止 ID。事件結束、沉寂、畢業、離班均無自動問題操作。
- 本包驗證證據存在與因果結構；證據內容是否確實足以解決問題仍屬正式事件語意審查。未簽章本機紀錄也不構成外部來源認證。

## 查詢、歷史與交易

`projectIssues(world,{beforeOrder})` 回傳全部問題；`readIssue(world,id,{beforeOrder})` 回傳特定問題或 null。回傳包含 id、kind、actors、建立來源、details、最新操作、state、操作鏈與去重 evidenceFacts。結果為脫離權威的副本，可改副本但不會改世界。呼叫者傳入正常受檢的正式世界；這兩個查詢不是完整世界驗證器或 NPC 知情授權介面。

`storyHistoryView(world,{beforeOrder}).issues()/issue(id)` 共用相同折疊。只讀取 `fact.order < beforeOrder`，邊界限制 1 至 history.length+1；同 fact 的操作不提供半筆歷史截面，而以陣列順序驗證。無 revision／attempt 快取，因此同交易草稿與不同 attempt 不會共用索引；retry 保留開場中合法存在的歷史，不過濾掉 retained attempt 的合法根。

`validateWorldState` 在原 fact／history／人物／cause 驗證後必定折疊問題操作，交易輸出與 restore 均受檢。沿既有 detached draft、提交 ID 比對、revision 與驗證機制，不另開提交路徑。任何錯誤使整筆交易無可發布輸出；同 ID 相同請求回傳 duplicate，不新增事實或數值；不同 ID 重複結案仍因 terminal 拒絕。因果操作本身不呼叫數值結算。
