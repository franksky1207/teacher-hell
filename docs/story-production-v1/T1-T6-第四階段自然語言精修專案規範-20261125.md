## 0. 一句話總目標與完成定義

讓玩家讀到的開場、四個教師選項、八種結局與 AVG 文字，像**臺灣真實高中校園裡的人會說、會想、會遇到的事**；降低公文腔、輔導報告腔、AI 式整齊說理及刻意金句收尾。**只改善表達方式，不改變既定人物、事件、教師行動、客觀後果或遊戲機制。**

- **單一暫存分支、六批依序作業、每批分批提交及文字驗收；全部六批結束後才建立一次 PR、跑一次正式所需 Actions、合併一次 V1。**
- T1～T6 每個學期可在該批內按篇數分段施工，但不各開分支、不各開 PR、不各自合併 V1。
- 故事本來自然的句子保留。**不是每篇、每段、每個選項都必須改**；不為了產生修稿量而改壞原文。
- 不新增故事、不改編新的情節、不重寫既有抽選與結算制度。

## 1. 嚴格的讀取與修改邊界（最小讀取）

### 1.1 AI 實質閱讀的最小資料

每篇只擷取實際潤稿需要的文字，**不要把整份 Markdown 的五個區塊、數值欄位與因果矩陣通通餵進語言模型**。**原則每篇只做一次文字閱讀；先讀玩家可見開場、選項、結果，必要的說話者提示隨同擷取。AVG 原始 JSON 不必整包另讀一次；僅在同步時以精準定位修改 `text`，並於完成後機械比對。**

| 項目 | 本輪處理 |
|---|---|
| 故事 ID、必要背景／校曆時間提示 | 少量讀取，用來辨識篇章、保護時間語意 |
| 開場 P01～Pn 玩家可見原文 | 讀取、必要時改寫 |
| A～D「玩家可見短句」 | **逐項檢查**，必要時改寫；教師行動意義不能變 |
| R1～R8「玩家可見結果」 | 讀取、必要時改寫 |
| AVG 對應頁面 `text` | **不預先重複送 AI 閱讀**；寫回或局部差異疑點時才擷取，優先以定位替換及自動同步處理 |
| AVG 最少的 `speaker`、`presentation` 等身分／媒介提示 | 只用來分辨誰在說話、是現場對話或訊息；不研究演出系統 |
| 其餘故事摘要、四碼因果用途、種子、NPC 數值、教師 V3 四狀態、4×8 矩陣與權重 | **不作 AI 語意閱讀；不改寫** |
| 六選三選項證據、第一／二階段詳細審查、全庫查重、程式原始碼、大型測試實作 | **不主動讀取** |

> 機械性的原檔保留、定位修改、欄位差異比對或必要 SHA 計算，不等於把這些內容交給 AI 重新分析；工具可對未改欄位作**不透明比對**，但不得藉機展開數值／32 格因果重審。

### 1.2 允許修改

1. 開場和八結果的玩家可見**敘述、對話、訊息內文、必要旁白**；同步同篇 AVG 相應 `text`。
2. 四個選項的**玩家可見短句**，限等義、易懂、自然的表述調整；選項 A～D 身份、原本教師已完成的行動、情緒選項位置均保留。
3. 必要的純文字引文與原稿來源 SHA 同步（僅限原有工具要求、且真有引用該句者）；不重寫內部因果理由或審查結論。
4. 最小的本階段批次進度及異常處理紀錄。

### 1.3 禁止修改

- 故事 ID、標題所代表的事件、種子、篇數／配額、日期資格、角色槽位與身分、人物知情或在場事實。
- 四個行動的既成客觀事實、`emotional`、NPC 四碼與增減、教師 V3 精神／熱忱／情緒／掌控、八種客觀結果、4×8 的全部權重及相容性。
- AVG 非文字演出欄位：`scene`、`speaker`、`presentation`、`enter`、`exit`、`expression`、`pose`、`music` 等（除非另案明確核准；本輪遇到矛盾只記例外）。
- 遊戲程式、數值公式、抽選邏輯、原驗收 JSON schema、生成的故事匯出 JSON、`main` 與 S6 事件接線。
- 不為一句口語化而重做七項品質審查、全部 32 格因果、數值檢查或全庫內容查重。

**異常停止規則**：一句話若必須變更行動、關係、同意、付款、承諾、日期、媒介、知情先後、實際後果才能變自然，則**不直接更動事實**；先採用同事實的保守改寫，無法等義則保留原文，另記「超出第四階段範圍」。

## 2. 四種角色的自然口吻

### 2.1 臺灣高中生：首要精修對象

- 可用短句、停頓、猶豫、插話、直接反問、語帶保留、少量語助詞，**不必把原因、心情、責任及解法一次講完**。
- 真正會說「我不知道怎麼講」「可是這樣很怪吧」「我沒有那個意思」；也可能講得很有條理，依角色而異。
- 以班級、個性、關係親疏和當下情緒定語氣：內向者不必吵鬧，外向者不必每句吐槽，成績好也不表示只說書面語。
- 不刻意灌「欸、蛤、啦、靠」或熱門網路梗；不粗俗化所有學生，不假裝全班一個聲音。
- 不讓高中生大段宣講法律、同意、情緒覺察、人生價值或行政程序；**若情節真有必要，仍可自然提及正確概念**。
- 當年科技與校園語感以故事實際年份為準；通訊對話、群組留言、當面說話應有不同節奏。

### 2.2 導師／玩家

- 用臺灣高中老師私下實際會說的短、清楚、可執行話語；可關心、可直接、可無奈，不必每句都「理解並尊重你的感受」。
- 面對學生、家長、同事的語氣有差異；必要時正式稱呼和行政用詞可以保留。
- **玩家選項尤其要一眼知道自己做了什麼**：避免「採取適當措施」「提供情緒支持」「建立溝通機制」等空泛抽象詞；但不能把「傾聽」擴寫成「承諾協助」或「通知家長」。

### 2.3 家長、科任教師與行政

- 家長可以急、擔心、猶豫、客氣或不耐煩，依事件及個性而定；避免家長人人講出完整理性聲明。
- 科任與行政在正式窗口可較正式，私下談話應自然；職權、程序、對外承諾**不因口吻調整而改變**。
- 不把所有成年人寫成同一種「教導學生人生道理」口吻。

### 2.4 旁白

- 只交代必要場景、行動、觀察與轉場，不重複前一句人物台詞。
- 避免「這不只是……更是……」「真正重要的不是……而是……」「那一刻你明白……」等制式昇華。
- 可留安靜、尷尬、未說破或不圓滿的結尾，不必八個 R 都收一則教育金句。
- 不讓旁白替人物宣告無法證實的內心、未經證明的動機或全班共同共識。

## 3. 六學期的整體語氣演變（氛圍，不是刻板性格）

| 批次 | 時間 | 主要群體氛圍與對話提醒 |
|---|---|---|
| **T1** | 高一上 | 剛認識老師／彼此，說話較試探、客氣或拘謹；也有不熟而誤會、想融入卻說不出口的情況。不是每個高一生都幼稚。 |
| **T2** | 高一下 | 班級漸熟，敢開玩笑、吐槽、抱怨和表達自己的看法；關係與小團體逐漸固定。 |
| **T3** | 高二上 | 與導師互動更熟，對班級活動、同儕界線和自身選擇較有主張；說話可能更直接，少一點對老師的客套。 |
| **T4** | 高二下 | 熟悉中帶著現實壓力，升學、課業、活動、個人責任可能並存；能討價還價，也會有逃避與情緒化，不要人人突然成熟。 |
| **T5** | 高三上 | 對升學與未來有焦慮，有人嘴硬、有人沉默、有人對老師說話更直接；可以成熟但仍是高中生。 |
| **T6** | 高三下 | 與導師熟悉，有告別、選擇、鬆一口氣或不捨的複雜情緒；避免所有人忽然講人生哲理、做完美告別宣言。 |

- 六學期的變化是**群體氣氛**與師生相處的自然發展，不強制每篇成長、不為學生補寫跨篇記憶或固定個性。
- 有人從高一就直率，也有人高三仍害羞；**先服從該篇原本人物身分、情境與當下情緒**，再考慮學期感。

## 4. 學生對話／玩家選項的改寫尺度與例子

**判斷原則：更像真人說話，但不增加或減少客觀事實。** 下列為風格示意，不是硬套模板，也不代表已修改故事。

| 偏書面、偏制式 | 較自然的表達方向 | 保護事項 |
|---|---|---|
| 「我不是不領情，只是不希望你為了我花錢又跑來跑去。」 | 「我知道你是好意啦，可是真的不用特地幫我買，這樣我反而不好意思。」 | 不改成對方已同意或已拒絕全部協助 |
| 「我想留的是心意，怎麼弄到現在像我替他決定要買什麼？」 | 「我只是想幫他留一份而已，結果搞得好像我在幫他決定要不要買……」 | 不新增新訂單、付款或取消事實 |
| 「進行情緒支持與同理回應」 | 「先聽他把話說完」 | 原行動若不是單純傾聽，不能擅自縮減 |
| 「釐清代購付款和無法取貨責任」 | 「先確認誰付錢、沒辦法取貨怎麼辦」 | 不擅自決定誰負責 |
| 「確認當事人自主意願」 | 「先問問學生自己的想法」 | 不把詢問改成同意已取得 |

**玩家 A～D 必須逐項檢查，但非必改。** 保留 A～D 對應關係及「玩家已做的行動」，只是讓文字更易讀、更像導師當下可選的做法；避免抽象名詞堆疊，也避免新增後續承諾。

## 5. 篇幅政策

- **不再依開場／R 原先的上下限修句，不為過線補字或刪字。** 自然口語化後略長或略短均可。
- 以**原篇長度和敘事完整度**為基準，不設定新的硬性字數範圍。
- **不計算逐段字數變化百分比，也不建立字數統計工作**；只有肉眼明顯暴增、過短或損失情節時，才回頭看該處。
- 不得極端膨脹、斷裂式縮短、刪掉必要情節或造成後四個結局內容明顯縮水；重點是自然、完整、讀起來順。

## 6. 每個學期的實際作業（六批共用）

### A. 最小擷取與基準

1. 在同一暫存分支處理該 T 年段；記錄該批開始 SHA、故事 ID 清單及篇數。
2. 按篇精確擷取 P、A～D、R1～R8 與必要的角色／媒介提示；**AVG `text` 先不重複作語意閱讀，只於同步時定位處理**。不要一開始讀取整庫數值、矩陣、測試原始碼或詳細審查 JSON。
3. 先於 T1 選 **3～5 篇不同情境**建立語感基準，這算 T1 第一批的一部分，不額外開一輪流程；之後六批沿用同一原則。

### B. 逐篇文字精修

1. 先抓住原本事件與每一段正在表達的意思，**只對確實不自然的句子動手**。
2. 先改學生台詞，再改教師／家長／同事，最後改旁白、R 結尾與 A～D 短句；順序可隨情境調整。
3. 寫法遵守第 2、3 節：臺灣繁中、自然、不同角色不同口吻、符合學期氛圍；不過度口語化或塞熱門梗。
4. 原稿與 AVG 的對應文字同步；**不要改場景、進退場、表情、媒介型別或其他 JSON 控制欄位**。
5. 若已完成的選項行動、學生客觀反應、日期／知情／權責有任何改變風險，採保守等義稿或保留原句，另記例外。

### C. 同批集中做必要檢查（不是每篇重做一整套驗收）

以下六點**只是同一輪校稿時的六個注意面向，不是六次獨立掃描、六份報告或六套驗收**。改寫時順手注意，學期結束再作一次簡短抽看；不必每修改一句或每完成一篇就完整自驗。

1. **臺灣口語自然度**：高中生不像行政稿，老師／家長／同事不像輔導範本；不硬塞口頭禪。
2. **去 AI 制式感**：刪冗贅的解釋、套句、對仗、硬性教育昇華，避免八個 R 都有相同收束節奏。
3. **人物口吻差異**：不同人的語氣、熟悉度、情緒和說話長短有差異，不全班一個聲音。
4. **原始情節保真**：原既成教師行動、學生反應、同意／知情、承諾、時間、客觀後果與 R 間差異不變；**以語意對照，不檢閱數值／32 格**。
5. **原稿與 AVG 文字同步**：P、A～D、R1～R8 及對應 AVG `text` 不留新舊版混雜；必要時確認引文與來源 SHA。
6. **全批口吻一致性抽查**：只從本批前、中、後各選少量代表片段，檢查後段有無回到制式語言或過度灌口頭禪；**不因抽查而再次逐篇通讀整批**。

> 本階段檢查是**內容校稿**，不是 Node、不是權重分析，也不是重新做既有七大故事品質驗收。每批只需一次集中封關審閱；發現問題時針對相關篇章修正即可。

### D. 以機械方式保護非文字內容（不送 AI 審閱）

- 對照該批修稿前後，**只允許指定玩家可見文字、AVG `text`、必要引文和來源 SHA，以及本批記錄變動**。
- 對其餘區塊／欄位做**一次機械化未變更檢查**，**不展開其數值內容、不重新解釋因果、不重算權重**；能利用現有 Git 差異或既有簡單手段就不要另開發工具。
- 若偵測到非許可變動：先定位差異並回復；不是自動重新設計遊戲機制。
- 文字改寫會改變故事 blob SHA：**只在最終交付所需且既有驗收工具明確要求時**，批次最小更新證據來源 SHA／直接引文；不逐篇重新打開原審查 JSON、重寫因果證據或重審原驗收結論。若工具因歷史證據要求無法通過，先辨識最小必要修正，不自動擴大工程。
- 故事 Markdown 使用最小範圍補丁或精準欄位操作，避免整檔「重新生成」而意外洗掉其他欄位。

### E. 該學期提交與紀錄

每個 T 批次可有多個小批提交，但整批驗收完成才標記該學期封關。簡短紀錄僅列：

- 學期、故事 ID 範圍與實際篇數、起訖 SHA；
- 完成的玩家可見文字／AVG 同步範圍，主要口吻改善方向；
- 本批同一輪文字複查的簡要結論及具體例外（如有），**不逐項產生六份驗收證據**；
- 非許可欄位差異檢查是否乾淨；未完成者不得標示封關；
- 遺留待辦（如有），不要逐篇輸出冗長審查 JSON／機制清單。

**每批完成後不建立 PR、不觸發 Actions、不合併 V1。**

## 7. 全六批完成後的唯一正式整合

1. 確認 T1、T2、T3、T4、T5、T6 六份批次紀錄與六項內容檢查完成；確認非允許欄位未變。
2. 以既有最小手段跑**最終**文字同步、結構／差異檢查；正式晉升前再依 GitHub 既定流程執行**既有必要** Node／CI／Actions。這些只屬最終技術放行，**不得為本輪另建大型驗收工作流程、寫一套全新測試系統，或反向擴大語言潤稿的讀取範圍**。既有驗證若不接受已核准的純文字篇幅變動，先以最小調整處理，不擅改遊戲數值或重製故事。
3. 六批合成**唯一 PR**，base 僅 `content/events-production-v1`；相關必要檢查全部成功後，**只合併一次 V1**。
4. 不合併 `main`、不修改正式 S6 引擎接線。V1 合併後若出版工作流程自動觸發，需**另核對其實際狀態**，不可把 PR 綠燈等同 S5 已發布。
5. 若正式 V1 在六批施工期間另有其他提交，合併前應檢查差異與衝突，僅處理本次範圍的必要衝突，不藉機整合無關變動。
6. 若最終驗收失敗，只修具體錯誤並重跑必要檢查；**不回頭全面重製六學期故事**。

## 8. 明確的效率限制

- **非必要，不讀取。非必要，不分析。非必要，不重測。**
- 不把內容潤稿變成全庫結構研究、因果審核、數值重算、程式重構或大規模測試。
- 同批可分段改寫，**集中做一次精簡文字複查，針對明確問題處理**；不每做一篇便完整自驗。
- **禁止任務膨脹**：不要求每篇前後比較表、逐句修改解釋、逐結果評分、全庫語感報告、跨六學期人物口吻資料庫、新的自動評分器、完整字數統計或額外多輪回歸。
- **停止條件明確**：能等義自然化、文字同步、機械差異乾淨、本批抽查無明顯問題，就提交並進下一批；不追求無限精修或以「再多檢查一輪」當作完成門檻。
- 本文件是未來六批施工的唯一**專案專用口語精修參考**；不取代原有故事創作 SOP 的全部規格，也不授權更改那些規格。

## 8.1 工作量上限與例外處理（本條優先於可能被過度解讀的檢查敘述）

1. **每篇：一輪實質文字閱讀與必要改寫**；同篇需要查的說話者一併取得，不以研究完整 AVG、讀證據或數值作前置步驟。
2. **每學期：一輪簡短內容複查與少量前中後抽查**；六項標準同時考慮，不拆成六輪，不建立逐篇判分／逐項報告。
3. **非文字欄位：機械式差異保護一次**；不為證明未修改而讀懂每個欄位，更不擴大成數值及因果審查。
4. **例外才加查**：僅在出現無法保持原意、AVG 對不上、非許可欄位異動或既有驗證實際失敗時，讀該篇／該欄／該錯誤必要的最小部分。
5. **不開發新系統**：本階段不新增批次語意評分系統、複雜驗收工具、資料庫、架構改造；簡單文字擷取／替換以已有能力完成。若要新增大工程，必須視為另案，不是第四階段的默認工作。
6. **不提前做最終驗收**：T1～T6 六批過程不開 PR、不觸發 Actions、不跑大型 Node；最後只做一次集中正式技術放行與 V1 合併。
