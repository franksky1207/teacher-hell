# 第 18-A｜選項事件內容唯讀審查與 T／G 分類規範

> **2026-11-17 正式修訂**：稽核類別改用 `T1`～`T6` 與 `G` 七組，不再使用舊 128 題／每題 20 則／2,560 則最低配額。P 被動事件另案，不占 2,400。本文只規範**離線內容稽核**，不等於程式完成八共用結果引擎，也不自動將內容發布至正式玩家生涯。

## 一、輸入與合法分類

- **T1～T6**：高一上、高一下、高二上、高二下、高三上、高三下；**所有故事中涉及特定校曆／考試／活動／節慶／升學窗口／階段都必須歸相對應 T 學期**。不做 B 活動通用類，也不做 G 加時間窗口的變通。
- **G**：起因不需要特定校曆階段的日常事件，仍依法定／程序資格及實際人物、時間、地點執行。**E 舊碼**只供已存在引擎／工程示例相容，不得分配給新 2,400 則。
- **P**：不需玩家四選一，從目前選項事件稽核排除，內容與頻率另議。
- 數值種子 `S0001`～`S2400` 來源為 [已驗證的三層平衡種子](./事件四數值三層平衡種子2400組.md)；**數值出現次數、配對均勻程度不表示事件已創作或語意不重複**。七組事件篇數與數值種子分配仍待核定。

## 二、既有 CLI（仍在舊六欄故事契約的過渡期）

```bash
npm run content:audit
node scripts/audit-content.mjs --output work/content-audit.json
node scripts/audit-content.mjs --input work/content-batch.json --baseline work/previous-batches.json --output work/content-batch-report.json
node scripts/audit-content.mjs --input work/content-batch.json --strict
```

- 每筆輸入 `{story, definition, editorial, editorialReview}`；報告依 T1～T6、G 七組統計**草稿／結構合格／審稿完成／資源可解析／已登錄**，再報重複、重大因果問題、合法時空與數值持有者。
- **重要過渡限制**：`validateEventDefinitions` 目前仍使用 `coreCodes`／`additionalCodes` 六數值設定，`validateStory` 與 `story-variation.js` 目前也未採「每故事固定八共用結果」。所以此 CLI 通過只表示**現有工程契約有效**，不能聲稱已驗證新版 T／G 四種子、八共用結果與選擇前讀檔重新抽結果。
- 對正式新庫的完整核准要等未來工程接線，並確認事件級 R1～R8、四選項權重及合法零連結、原子結算、人物知情與存檔回放。既有工程示例 G-0001～G-0004 或其他 mock 不當成正式 2,400 篇完成量。

## 三、創作品質核對（不能被固定數值配額代替）

1. **四項種子與故事因果**是否真有關，無硬塞標籤；是否與原有 48 項數值及合法持有者一致。
2. **四選項差異**是否是玩家能合理採取的不同教師行動，而不是換句話說。
3. **八種共用結果**每個是否有真正不同的因果、合法結算欄位與必要知情，選項對不合理結果是否零權重；不要用「另一選項有變動」替某一結果的空效果掩飾。
4. **T 的年級／活動／考試／結果公布資格**是否符合最新固定校曆；G 是否不依賴特定活動窗口；受保護活動時段不能額外觸發事件。
5. **同輪使用過的事件 ID** 是否排除；跨 AI／跨批是否出現同一故事換姓名、換學期、換場景的偽新事件。
6. 正向、中性、負面、荒謬與溫馨事件能否維持合理多樣性，學生 40 人的自然曝光是否有足夠普通故事支持；不給每人硬配額，不新增需要特教支持框架的憑空診斷事件。

**審查成本原則**：每次只檢查本批必要的事件與直接受影響契約；不反覆重跑三年或 30 年完整模擬。若內容不能通過合法／因果驗證，回到創作修正，**不得簡化成「每項數值出現平均、每故事四選項」就算合格**。正式詳細 SOP 見 [17D](./17D-事件內容量產SOP.md)。
