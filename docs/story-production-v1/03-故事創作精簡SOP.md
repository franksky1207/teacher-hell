# 《教師荒謬地獄》故事量產V1｜03 GPT單篇創作精簡 SOP

> **2026-11-19｜第06批正式版（創作程序）**。本檔供單一GPT逐篇按順序執行；[04五區塊範本](./04-五區塊故事稿範本.md)是唯一可複製的Markdown填寫格式，[01人物持碼](./01-人物數值與四碼資格.md)、[02分類與時間](./02-事件分類與時間資格.md)是資格來源；**數值和因果正式驗收歸第07批[05](./05-故事品質與驗收契約.md)、帳本指令歸第07批[06](./06-種子與量產管理.md)**。離線工具負責機械檢查，GPT負責語意品質驗收。[返回總覽](./00-總覽與規格狀態.md)。

## 一、作者開始前只要知道的共同原則

1. **單一GPT負責**構思、查重、改寫、審查證據和文件交接；不需要第二AI，不新增多AI搶種子機制。但種子與正式故事仍須經既有**唯一帳本、修訂版及鎖定**處理。
2. **T先於G**：正式T故事共648篇、20個核定主題與108個不重複合法日期；T648已鎖定後才進入G1752。P/H4不使用T/G的2400種子與此四選一範本。每篇故事只可對應一個合法種子；同局同故事ID只觸發一次。
3. **T故事的活動前後窗口共用池**：活動前5個合法日創**30篇供這5天共同抽**，後2個合法日另創**12篇供兩天共同抽**；前後不互通。**單一日期的六篇是創作配額，不是每日播放六篇或每篇只能在歸屬日播放**；同一天不同主題重疊仍共用6篇總配額。日期表只讀[唯一T20表](../T1-T6-特定故事20主題與觸發日期.md)。
4. **K已取消，絕不可沿用**負1.6／中1／正0.7、舊正中負事件K分類或自行發明替代選篇倍率。四碼的**偏正／偏負NPC選角方向**另屬01人物規格；四選項對八結果的**4／2／1／0**仍屬05品質契約，不能三者混用。
5. 故事是**單篇獨立**的真實教師困境，不寫固定續集、不為臨時文字人物建姓名／ID／數值／下集。學生、校內教職員、當班家長按01常駐資格建槽位；其他班及校外人物只能作文字情境角色。
6. **五區塊故事稿與管理資料分離**：故事原稿只記基本資料、摘要、四碼與人物、開場四選項、八結果矩陣；六個普通候選的短句及三個中選編號、查重分析、七項內容審查證據、工具報告、版本與SHA放**另存審查／管理檔**，不得塞進04正式Markdown五區塊。
7. 只有固定五區塊稿件、摘要→choices→full的機械檢查、具體語意審查和正式lock都完成後，才能算正式製作進度。**測試fixture和口頭試作均為0篇**，不能冒充已鎖定內容。

## 二、十步可操作閉環：每一步都有輸入、產出和不合格回路

| 步驟 | 輸入與實際動作 | 當步必須產出的內容 | 失敗怎麼處理 |
|---|---|---|---|
| **1 類型與資格** | 確認T/G、20個T主題與合法「前／後」池、實際知情與人物職權；T原始資料讀02及T20表。必要G01～G11實質標籤可先暫貼 | 04第1區：`event_type`、T主題／窗口、必要條件與初步標籤 | 核心節點不具T資格→改合理G摘要或退稿；P或固定制度不可冒充T；活動日全日不抽T/G |
| **2 四欄摘要** | 不先寫選項／八結果；分別構思**事件起因、核心衝突、導師困境、故事獨特性**，由具體教師行動與取捨證明是獨立事件 | 04第2區四欄摘要，至少能指出相較既有故事的具體差異 | 缺獨立教師選擇、只有制度播報或只是換人名→在摘要階段重想，不浪費種子 |
| **3 摘要初審與propose** | 執行`--stage summary`機械檢查；GPT比對同批、先前候選與locked作品的起因／衝突／困境／獨特性，再用管理工具`propose`正式記錄暫稿 | 合格的摘要稿、相似候選及判斷理由、`draft_ref`和帳本`proposed`狀態 | 機械錯誤只修第1～2區；換皮則改核心抉擇、角色責任或退稿；**不能以檢索0相似就聲稱語意不重複** |
| **4 查種子與reserve** | 查固定2,400組表、帳本`available`及T配額，評估四碼是否都能真正支撐此困境，必要常駐角色是否能完整合法持四碼；使用`reserve`暫用並核對revision | 未占用S編號、對應**四個原碼**、明確選角方向、帳本`reserved`狀態 | 種子不合因果／角色→換可用種子或修摘要；沒有合格種子就**release／退回**，不得替四碼硬編劇情 |
| **5 角色與事實** | 建立真正需要的常駐數值槽位，核對本人四碼／在班／監護／職權／知情與時段；臨時人物只留文字身分，動態姓名及任教學科僅在合法槽位使用 | 04第3區：數值槽位表、無數值情境角色、四碼各自合法持有人及因果用途 | 某碼沒有合格持有人或人物資訊矛盾→改槽位／角色前提，若影響故事核心退回第2～4步；不得借用他人數值 |
| **6 四個最終教師行動** | **先發想1個有具體行動的情緒候選＋6個真正不同且合法的普通候選**；六普通候選去重後**隨機取3個**，再和情緒項核對差異、合法性與已採取事實。情緒項也有合理代價，不強制必敗／必勝 | 04第4區：開場與A～D**恰好四項、恰好1個`emotional=true`**，每項有短句、已完成的教師客觀行動、取捨；**獨立審查紀錄**留六候選簡短內容和中選三編號 | 六候選不足就補足合格候選；選出與情緒項重複則從剩餘合法候選重抽或局部重寫；**不能犧牲品質維持抽中結果** |
| **7 八個共用結果** | 從同一個起因、四種教師行動與合理NPC自主反應，設計R1～R8**實質不同、不照好壞排序**的共同結果，每個R的文字／客觀後果／合法結算均固定；四選項已完成的行動不得被R抹去。四狀態依[05正式契約](./05-故事品質與驗收契約.md)：先寫完整R1～R8發展與客觀後果→逐結果判斷體力／精神／熱忱／情緒影響→決定方向與幅度→完成8×4矩陣→驗零值、幅度、平均及分布；不合格回查數值與劇情因果，不得硬塞數字 | 04第5區：R1～R8各自結果文字、客觀事實、**原四碼合法NPC／玩家**的底層增減與玩家體力／精神／熱忱／情緒四整數 | 如果同一R無法合理對接多個選項，優先修R結果的共同事實，再評估改行動／前提；不偷寫四套R、不加四碼外底層值 |
| **8 32格因果矩陣** | A～D對同一組R1～R8逐格檢32條連結，使用**4（高）／2（中）／1（低）／0（客觀不可能）**，每列最多2個0、每欄最多1個0；每個0都有具體不可達理由，無0亦合法；每項R數值必須符合05的單R與八R等權平均及教師四狀態V2限制 | 04第5區完整**4×8矩陣**與全部0格個別理由；可達32格的因果自審結果另在審查檔 | 不合理優先改R、再改選項或合法前提；不能為省事設0或把真正不可能填1；超出05硬限制就退回局部重寫 |
| **9 機械＋GPT內容驗收** | 依順序執行`summary／choices／full`檢查；**GPT另外**逐項審查臺灣私校情境、人物四碼、四選項、八結果、32格、時間與法律、**完整稿再次跨批語意查重**；檢視四狀態V2零值、幅度、等權平均與分布報告，審查每項因果、是否為零上限無中生有及跨篇模式化；七類審查證據要具體，並附六候選簡短內容與三個中選編號 | 通過的五區塊Markdown、只讀機械報告、獨立內容審查檔（詳細欄位第07批05／06定稿） | 格式／數值錯誤只改相應區塊、重跑受影響階段；因果錯誤重看相關R與矩陣；語意換皮則回摘要／核心衝突。**機械pass不等於內容approved** |
| **10 正式鎖定／退回** | 確認GPT內容審核、原始稿與審查檔SHA256、帳本revision、種子唯一性與T配額，再預覽`lock`，符合後才依06工具程序寫入；正式故事ID**鎖定時自動配給帳本**，不提前手編 | `locked`故事ID與種子綁定、稿件／審查檔存檔路徑與SHA、正式計數與G01～G11有效標籤統計 | 未過先`revise`重審或`release／reject`釋放種子；**禁止以改寫已鎖稿檔或私改story_id來修問題**；不自動合併main或上架遊戲 |

### 重要：不要把「文件已說明」當作「工具已檢查」

- 稿件檢查器要求A～D恰一個情緒選項。鎖定時帳本檢查六普通候選、三個中選ID、A～D映射和正文情緒標記。隨機過程及候選的實質差異由GPT審查。
- T稿的 `required_window` 填池ID，帳本 `--date` 填獨立的配額歸屬日。池內日期及正式校曆資格可由工具查詢，故事當下的知情與在場仍須審查。
- `4／2／1／0`的零上限是**V1稿件硬性門檻**，4：2：1仍待正式遊戲平衡；數值限額（底層單R−8～+8、四狀態單R−6～+6，八R等權平均分別−3～+3、−2～+2）是機械稿件試作限制，**不能冒充已驗證三年通關率**。
- 正式`lock`必須持有實體稿件與審查檔路徑，`--apply --expect-revision N`才會寫正式帳本。作者不可把測試fixture、沒有檢驗的故事或對話稿當作locked計數。

## 三、GPT最少閱讀與實際交付格式

**開始一篇前**：讀本檔（03）、[04範本](./04-五區塊故事稿範本.md)；需要人物資格時查[01](./01-人物數值與四碼資格.md)，日期／T主題查[02](./02-事件分類與時間資格.md)及唯一T20表。只在**涉及查重、暫用種子或正式鎖定**時參照[06帳本說明](./06-種子與量產管理.md)；內容退件按[05](./05-故事品質與驗收契約.md)。

**T故事池開工／續作必讀（Chat／Codex共用）**：每次**開始、換池、換AI或中斷後恢復**某個T故事池（例如原預計30篇、先完成12篇後再次續作），在創作下一篇之前，都須重新開啟該池的`README.md`及其連結的`時段創作引導.md`，核對[唯一T20表](../T1-T6-特定故事20主題與觸發日期.md)的正式池ID與合法日期，並**即時查詢唯一正式帳本**及既有同池作品，確認有效`locked`、`revoked`、尚未完成的`proposed`／`reserved`與各日期剩餘配額，再接續原有十步流程及查重；不可依上次對話、進度報告或記憶推定完成篇數。**同一工作階段連續創作同一池時，引導完整讀取一次即可，不必每篇重讀**；若換池或開啟新的工作階段則重新讀取。此引導只供理解時段世界狀態與創作方向，**不新增題材配額、正式稿欄位、品質驗收關卡或帳本機制**。

**作者三階段交付**（是同一篇稿的逐步完成，不是三篇故事）：

- **摘要版**：04第1＋2區，附同批／跨批疑似重複候選的具體比對；只有摘要過關才建立正式候選。
- **選項版**：補第3＋4區，先已暫用四碼，交最終四行動；六個普通候選短句及中選三個編號放**獨立審查紀錄**而非五區塊正文。
- **完整版**：補第5區八共用R與矩陣、執行全部數值及內容審查；正式核准後才可`lock`並在帳本領正式故事ID。

**避免重工的修稿原則**：摘要不合法只動第1／2區；角色或種子不合只退回第3區並確認是否影響摘要；四選項重複只修第4區，且重新核對受影響的全部8格；一個R錯誤先改該R與所連四選項，不必整篇重寫；數值或零格不合法則局部修改再重跑`full`；若核心困境已被證明換皮，則**必須回到摘要重構**，不得靠換人名、加對話或小改字數矇混。

## 四、固定範本欄位與檢查指令（不可擅改）

以下命令是**現有工具**，不是新建的正式故事轉JSON工具；檔案路徑是使用者自行建立的稿件位置：

```bash
npm run content:draft-check -- --input work/your-story.md --stage summary
npm run content:draft-check -- --input work/your-story.md --stage choices
npm run content:draft-check -- --input work/your-story.md --stage full --json work/story-check.json
node scripts/manage-story-production.mjs status
node scripts/manage-story-production.mjs audit
```

- **不修改04的固定區塊標題／表頭／矩陣識別**，直到同步修改並驗收`scripts/story-draft-validator.js`及其定向測試。原可填範本已於第06批轉入04；**它是撰稿Markdown契約，尚不是正式JSON Schema、轉檔器、角色替換器或遊戲引擎**。
- `story_id`在核准鎖定前保持原「待配號」占位，不能由創作GPT提前編流水號；鎖定後**原稿不直接更改**，避免SHA失效，正式輸出ID由帳本提供。
- GPT須留存32格敘事因果、跨庫查重、動態人物在場與知情、日期與情節合理性，以及六選三過程的審查證據。
