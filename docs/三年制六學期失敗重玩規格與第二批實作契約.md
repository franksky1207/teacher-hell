# 三年制六學期失敗重玩：規格與第二批精準實作契約（2026-11-13）

> **狀態：第一批規格／靜態分析完成，第二批程式尚未實作。** 本決議只針對首發三年模式；原 30 年內部核心不因本批文件自動改寫。此文件是六學期重玩工程的集中實作契約，與 D04／D07／D05 頂端最新決議一致；舊「失敗回到當學年正式開學日」文字僅為歷史。

## 1. 使用者確定的玩法

- 原本失敗重試「整個學年」改為**當前學期**。一年兩個回復區段；僅改失敗回溯位置，**不新增學期通關、成功評級或額外成績結算**。
- 三個上學期：從該年**暑輔第一天**（當天第一個合法操作時段前）恢復。高一、高二、高三一致，包含暑輔與正式上學期。
- 三個下學期：在上學期最後一個實際考試日，所有當日事件、學業結算、學期回顧及必要確認完成後，**進入寒假／寒輔之前**保存檢查點；失敗重試從下一個正常遊戲時段接續，包含寒假、寒輔、正式下學期。**不要把下表的週六日期解釋為多一個操作日**。
- 檢查點之前已發生的真實人物、成績、學籍、能力、關係、事件、待辦、知情、歷史與年度成果保留；檢查點之後本次失敗嘗試的數值／歷史／收據／決策隔離；下一次嘗試仍有合理隨機事件變化，不能將前次已撤銷影響重複套用。
- 六月底的**年度成功、年度評級、年級／學籍轉換、高三 T4 結局及原三槽唯讀**照舊。上學期只有原本學期回顧；不是新增成功關卡。畢業考／五月高三學業關閉與六月教師年度結算仍分離。
- 三個本機存檔槽不變；檢查點是單一生涯存檔內部資料。不另建六槽、不另產生獨立生涯。正式遊戲尚未公開，現有開發測試存檔可作廢；**不需為舊格式測試存檔建遷移／回退相容機制**。
- 失敗判定條件不變，依原 11-C 職務與事件結果；只改恢復區段與顯示文字。不得將普通低分或申訴自動改成失敗。

## 3. 靜態資料流檢查：已確認現狀與必改邊界

本批只讀程式碼，未執行測試。以下為既有函式和實際限制，第二批不可僅替換日期字串。

| 位置 | 既有狀況 | 第二批契約 |
| --- | --- | --- |
| `src/calendar/calendar.js` 的 `positionFor`／`nextPosition`／`careerRange` | `serviceYear` 與 `openingId` 在高二、高三**秋季正式開學**才切換；`gradeAt` 已在暑輔切換年級 | **將重試檢查點與學年 opening 身分解耦**；不得只把 `openingId` 日期改為暑輔而破壞年次、年度證據／原始世界契約。必要的年級／課表轉換與時段順序必須合法。 |
| `src/runtime/annual.js` 的 `initializeAnnualObservations`、`openAnnualObservations`、`validateAnnual` 與年度證據 | 年度觀測起點及 `academic-opening` 歷史綁定原有秋季 opening，年度比較以 opening 起計 | **保留六月年度結算與教師年度評級語意**；如需讓觀測統計包含暑輔，需檢查影響並提出明確兼容處理，不能把重試檢查點冒充年度 opening 或新增年度結算。 |
| `src/runtime/transactions.js` 的 `advance-time`、`academic-opening`、`semester-review`、`forkWorldAttempt` | 秋季切換會更新 opening 身分；重試時要求失敗世界與快照的 openingId／schoolYearId 相同，歷史提交需要前綴一致 | 用**獨立學期檢查點標識／恢復契約**解除舊限制，維持可重現事件、唯一收據、CAS 與失敗嘗試隔離；不得靠偽造年度 opening 繞過驗證。 |
| `src/storage/session.js` 的 `execute`／`captureOpening`／`retry` | 只有 `payload.opening` 一份年度快照，原本依 openingId 變更捕捉，重試一律讀此欄 | 讓同一存檔維持**當前合法學期重試點**；在暑輔與上學期期末的原子邊界更新，失敗時讀正確快照；不可於讀報告／重讀／重新載入時重複捕捉或覆蓋。 |
| `src/storage/format.js` 的 `checkedSave`／`createSave`／`restoreSave` | 明確要求快照、世界具有相同 `openingId`／`schoolYearId`，年度觀測 baseline／導師連續性完全相等 | 區分**重試檢查點**與**年度 baseline**，以真實時間順序、身分及歷史前綴驗證；不削弱跨生涯、跨學期錯配或竄改防護。保留壓縮讀寫、CAS、三槽與 JSON 匯入匯出。 |
| `src/runtime/homeroom.js` 的 `failureResult`／`authorizeRetry`／`compileFailure` | 11-C 失敗仍是當年失去原導師班職務，授權與年度識別綁定 | **失敗判定不變**，調整 retry 授權可正確證明「本學期合法檢查點」；不使同一失敗憑證跨學期或跨嘗試重用。 |
| `src/runtime/reviews.js` 的 `semesterReviewData`／`acknowledgeSemesterReview` | 最後實際考試日產生學期回顧，閱讀確認與時間推進分離 | 下學期快照必須在**學期全部相關正式交易結束後**、進入假期前精確形成；讀取舊報告不重新生成快照。 |
| Web 存檔／失敗介面與必要測試 | 既有提示或失敗鈕可能仍寫學年起點 | 只改實際使用的「重試本學期」文字／操作連結，不新增存檔槽與大型 UI。 |

**觀察到的核心風險**：現行 `positionFor` 把高二／高三的 `serviceYear/openingId` 切換點設在秋季，`format.js` 與 `forkWorldAttempt` 又要求 openingId 相同。因此直接在 7 月保存 `opening`，到 8 月失敗時會因身分不符而失敗。第二批必須先在設計上拆開**年度觀測／schoolYear 身分**與**學期重試點**，以最小改動維持既有年度契約；不應把完整年度系統重寫成半年制。

## 4. 第二批 Codex 實作範圍

- **基準**：必須使用 Git 歷史清理後最新 `main` 建立乾淨工作副本，不得從歷史清理前的 `/workspace/teacher-hell` 舊 clone 推送／合併。
- 僅處理正式三年遊戲的學期重試快照生成、合法選擇與恢復；必要時最小修改跨年度識別和 save schema 的檢查；存檔進出與 UI 文案配合，其他玩法／30年保留核心／校曆原資料／學業公式／事件／年度評級／高三結局不變。
- 上學期三個檢查點設在暑輔第一合法操作前，下學期三個檢查點設在原本上學期正式結算後／假期前；**不用在每次開啟存檔、顯示回顧或日期切換時重複建立**。
- 快照包含完整已知與客觀歷史、學生／家長／教職員人物、48 隱藏欄位、NPC 關係、學業、學籍、校曆課表、進行中的事件與待辦、正確隨機與收據狀態；保留已通過學期及年度成果、失敗嘗試必隔離。
- 不必相容正式發行前的既有測試存檔，不做遷移功能；若改動存檔結構，仍須保證**新版**三槽、原子寫入、壓縮、匯入匯出與完成唯讀運作一致。
- 最小量測「代表性世界」新增／更新重試點的壓縮前後大小；不進行三年容量壓測或無關優化。不得因容量而丟棄必要世界資料。

## 5. **超輕量驗收硬性限制**

**僅五組定向測試**，可利用現有測試函式或最小合法狀態，直接跳到時間邊界，不准用逐日／逐節模擬走完一個學期。若同組含六個日期參數，仍算一組。

1. 三個**上學期**：2026-07-20、2027-07-19、2028-07-24 暑輔首次操作前捕捉；跨秋季 opening 後失敗可正確還原。
2. 三個**下學期**：2027-01-22、2028-01-21、2029-01-19 最後結算後、寒假／寒輔前捕捉；假期及開學後失敗可正確還原。
3. **全世界回溯與唯一性**：選定代表性失敗狀態直接重試，人物／關係／學業／歷史／待辦／未結程序／隨機與收據回到快照且撤銷失敗嘗試；新 attempt ID 唯一，不重複套用。
4. **完成成果與正式結局隔離**：上學期及先前六月年度成果保留；年度評級、成功交易、學期回顧與高三結局不被新增檢查點重做。
5. **新版存檔最小契約＋單筆容量**：當前世界與檢查點原子存取、JSON 匯入匯出、Gzip、三槽／唯讀關鍵狀態的最小驗證，以及一組代表性狀態的前後大小比較。

**禁止**：完整三年／30年、完整學期／學年逐日推進、全量測試、全套 CI、大型隨機種子／蒙地卡羅／平衡／效能壓力測試、建立大型驗收器、反覆執行已通過組。失敗只修正並重測失敗項與其直接相依測試；若發現範圍外缺陷，紀錄而不是擴張。不可自行把「全面驗收」當作交付條件，也**不設時間上限造成測試中途停止**。確有必要超出這五組時，先提出原因與成本並另取使用者授權，不能自行開跑。
