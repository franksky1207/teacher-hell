# 《教師荒謬地獄》學生立繪｜完整六圖優先製作 SOP v1.1｜大腿立繪與情緒姿勢
> **生效：2026-11-08。現階段最高優先的「新素材製作流程」。** 本規範優先於過往雙圖製作流程，適用後續學生美術製作與完整六圖預覽驗收。**先前雙圖 SOP 與已核准素材、JSON、預覽功能全部保留，作為既有成果與備用方案，不刪除、不批次重製。** 此次流程優先級變動不表示既有完整六圖候選已經使用者視覺驗收通過。
>
> 歷史雙圖規範：[15-B 正式美術原型規範](./15-B-正式美術原型規範.md)；真實製作／驗收狀態：[15-B 美術素材命名與製作進度簿](./15-B-美術素材命名與製作進度簿.md)。

## 1. 核心產出與人物基準
- 共 **40 位固定美術角色**（`student-001`～`student-040`），每位 **8 套服裝**，每套僅需 **1 張 RGBA 真正透明的 3×2 六表情人物立繪 PNG（優先採大腿構圖，不強制全身）**；理想總量 **320 張 PNG**，提供 1,920 個人物／服裝／表情畫面。新方案**不製作平靜母圖＋局部臉部貼片，也不需要定位 JSON**。
- **每位學生第一套一定先做「夏季制服完整六圖」**；完成技術檢查、使用者正式預覽確認後，鎖定該角色的**唯一外貌基準**。剩餘七套**每一次都直接以這張原始夏季制服六圖為人物參考**，不可拿第二套參考第三套，再逐套傳遞，避免外貌逐漸漂移。若該學生夏季制服尚未獲核准，其餘七套不宣稱有正式人物基準。
- 學生美術編號**與班級座號、存檔中的 NPC 身分無關**；一個學生美術編號代表穩定可辨識的同一角色。

## 2. 服裝八套及固定順序
| 次序 | 中文名稱 | 代碼 |
|---|---|---|
| 1（唯一外貌基準） | 夏季制服 | `uniform-summer` |
| 2 | 冬季制服 | `uniform-winter` |
| 3 | 夏季運動服 | `sports-summer` |
| 4 | 冬季運動服 | `sports-winter` |
| 5 | 夏季便服 A | `casual-summer-01` |
| 6 | 夏季便服 B | `casual-summer-02` |
| 7 | 冬季便服 A | `casual-winter-01` |
| 8 | 冬季便服 B | `casual-winter-02` |

- 制服及運動服遵循同校服裝基本樣式，各位學生維持不同的個人辨識度；便服可依各角色設定自由設計，符合臺灣高中生活感。
- **每套服裝都要有不同的自然姿勢**，與服裝及情境相符：制服端正、運動服輕鬆有活力、便服生活化只是方向，**不強制死板指定動作**。八套不做相同姿勢的機械複製，但也不為了差異刻意扭曲身體。
- **同一套服裝的六種表情可以搭配各自不同、符合情緒的自然姿勢**，不再限制六格必須沿用同一姿勢家族，也不限定只能小幅變化。例如生氣抱胸、驚訝抬手、難過低頭、害羞撥髮，都可作為劇情中的即時反應。可有中度甚至明顯的合理肢體動作差異；不因姿勢不同本身退件。需維持相同角色、同套服裝、合理的人物大小及對話出場位置，避免不合理的比例突變或跑到畫面另一側。

## 3. 角色外貌鎖定
- **必須穩定**：核心臉型及輪廓、五官比例、眼睛外形與瞳色、基本髮色、膚色、合理體型和年齡感、人物整體神韻。八套應一眼看得出是同一學生。
- **可自然變化**：髮型／瀏海整理、綁馬尾或辮子、髮飾／髮夾、其他配件、手勢、站姿、頭部角度與服裝相關細節。不得僅因髮夾消失、髮型或配件不同就判斷「變成別人」。
- 每次製作七套延伸服裝，都以**已核准的夏季制服原圖直接比對**；避免只靠文字敘述維繫人物一致性。

## 4. 圖片技術規格
- **單張六表情人物立繪圖集**，固定 **3 欄 × 2 列**；順序不可改：
  - 上排：`calm` 平靜｜`happy` 開心｜`angry` 生氣
  - 下排：`sad` 難過｜`surprised` 驚訝｜`embarrassed` 害羞
- **構圖優先採頭部至大腿附近的中長景（大腿立繪）**，臉部表情與上半身手勢清楚可辨，並呈現足以辨識服裝的裙裝／褲裝；不要求畫到鞋子或完整雙腿。可依角色或情境採合理近似構圖，但同一套六格應維持相近的取景尺度、頭部與身體比例及出場位置。
- **預定構圖與意外截斷須區分**：自然地在大腿附近結束是正確的中長景，不得以缺少鞋子判定失敗；頭、手、髮絲等原本預定呈現的部位若被格線意外切斷，或六格取景差異大到影響對話顯示，才需要修正。
- **PNG RGBA Alpha 真正透明**，不得把深色／白色／棋盤格當成透明，不得夾帶漸層背景、底板、場景、格線、文字、標籤、水印或美術規格圖。人物外的格子空白要透明。
- **檢查重點**：六格是同一人物與同套服裝、六表情清楚、姿勢符合情緒且自然、五官與手指無明顯破圖、邊緣無嚴重去背殘留、每格構圖與比例協調。**姿勢變化不是瑕疵**；只要配合劇情，不因抱胸、抬手、低頭、轉身等動作差異退件。容許不影響遊玩與辨識的像素及髮絲細節差異，不為微小瑕疵無限返工。
- 現有學生 001 夏季制服**測試圖**為 **1026×1536**，每格 **342×768**。此為**已試用尺寸而非所有圖片永久固定的解析度**；正式更高解析度須以同樣 3×2 整數切格、手機／電腦顯示及檔案大小測試決定。網頁使用圖片的實際寬高計算切格，不硬寫死學生 001 尺寸。
- 網頁按劇情指定的學生編號／服裝／表情，從對應圖集裁切大腿立繪；**採劇情觸發的瞬間切換**，而非將六格當作連續動畫播放。對話或事件推進時切換為符合情緒的手勢、站姿與表情，玩家會將其理解為角色反應；**不採交叉淡化**，避免不同姿勢疊成雙重人影。只需注意人物在畫面中的相對位置與視覺尺度維持合理。正式劇情接線仍另行驗收，不因預覽成功宣稱完成。

## 5. 命名與檔案位置
所有檔案沿用原有 `web/assets/characters/students/student-XXX/`，**不新增服裝子資料夾**。命名一律：
```
student-XXX-full-sheet-{outfit}.png
```
學生 001 八套範例：
```
student-001-full-sheet-uniform-summer.png
student-001-full-sheet-uniform-winter.png
student-001-full-sheet-sports-summer.png
student-001-full-sheet-sports-winter.png
student-001-full-sheet-casual-summer-01.png
student-001-full-sheet-casual-summer-02.png
student-001-full-sheet-casual-winter-01.png
student-001-full-sheet-casual-winter-02.png
```
**不要覆蓋或刪除舊 `base-*`、`face-sheet-*` PNG／JSON**；已通過的雙圖模式可繼續使用與比對。

## 6. 單套製作、檢查、交付與預覽 SOP
1. **夏季制服先行**：建立該角色的夏季制服 3×2 六表情完整人物圖。檢查 RGBA 真透明、六格、外貌、衣服、姿勢、表情、檔名；必要時直接修正未通過項目。**使用者核准後才鎖定為後續七套共同外貌基準**。
2. **其他服裝逐套製作**：每次都以**原始已核准的夏季制服完整六圖**為參考，先設計符合該服裝的整體姿態風格，再讓六表情依劇情情緒各自搭配自然姿勢，製作六格大腿立繪；與基準直接比對，避免人物逐套變化。
3. **自行檢查與修正**：檢查圖像真透明而非假透明、比例／切格正確、大腿構圖正常且無意外裁切、六情緒與服裝正確、外貌沒有變人、姿勢與情緒搭配自然；未通過則修正後再交付。技術檢查不能取代實際目視判斷；不要求使用者每輪催促繼續。若個別圖只有可忽略的小瑕疵，不追求不切實際的像素完美。
4. **獨立交付**：只交付**一張正式命名 PNG 下載連結**與該學生**既有 GitHub 資料夾網址**，不提供 ZIP，不新增 JSON 或多張分拆 PNG。下載連結須確實存在，不能虛構。
5. **使用者自行上傳 GitHub**：收到上傳完成訊息後核對實際 PNG；**只有使用者明確要求接入／更新預覽時**，才修改、部署網站，不能把「已上傳」當接線許可。
6. **唯一實測網址**：使用 `https://franksky1207.github.io/teacher-hell/preview/` 的「完整六圖測試」入口；兩組下拉選單分別選擇**學生 001～040（非座號）**、**八套固定順序服裝**，六個按鈕選情緒。尚無素材時顯示未製作；不能誤用雙圖代替。禁止對使用者給帶版本號／查詢參數或獨立測試頁的網址；部署時要核對真正在 `gh-pages:preview/index.html` 指向的新模組與對應素材。
7. **驗收分層**：依序記錄（a）候選生成與內部檢查，（b）使用者核准該學生夏季制服人物基準，（c）GitHub PNG 已上傳，（d）預覽站已接入，（e）使用者實際觀看六表情核准，（f）正式遊戲劇情人物接線／動畫測試。**未經使用者實看核准，不能標記新模式通過**。
