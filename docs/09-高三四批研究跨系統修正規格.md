## 1. R1｜高三時間軸與固定校曆

**已定案**：高三上4場學測模考（暑輔、9、10、12月）；高三下2場分科模考，限有資格且有準備需求者。模考只推進主要階段、不逐節操作、不計入校內平時或段考權重。高三上留校一二四五／週六七節自習；**高三下開學起僅一四留校且週六不安排自習**。正式英聽可能在週六，依個人報考與考試日型處理；其他學生不被強制視為應考。

**校曆模型**：
1. 在固定日曆或基於它的版本化高三學務投影中，分開表示「公開正式考試、報名與截止、成績公布、校內模考、校內升學行政窗口、個人甄試時段」；全校固定活動與個人事件不可混為同一日型。
2. 先以可重現、明示的學年度假設產生2026～2065遊戲窗口；**不得將已公布115/116年度考試日期冒稱2029或未來40年官方日期**。來源、假設版本與遊戲日期凍結策略需一併保存，舊存檔不能載入後偷偷換日。
3. 正式考試跨週末、國假、學校課表及學生個別考試資格須檢查衝突；無資格者不在考試中，教師亦不能同時被強迫執行互斥校務。
4. 高三畢業考**與其他年級第二次段考同檔期**（兩天），第一次段考仍同步第一次段考；高三不再於六月一般期末考接受第三次段考。高一、高二、高三上均維持原規則。
5. 高三下畢業考至畢典前仍是正常白天上課日，維持一四留校；畢典當日以特殊活動覆蓋原排課／晚自習；畢典後高三不上課。

**現碼缺口**：`src/calendar/fixed.js`目前高三畢業考無專用考期；`src/calendar/calendar.js`高三星期六與晚自習沿用全年規則、考試日僅依既有exams；`src/runtime/schedule.js`逐時段與quota需辨識高三下及典禮後日型。避免直接修改龐大的生成結果卻未同步生成來源／測試。

## 2. R2｜高三學業、學分與畢業資格

**既有保護**：A1 academic v2 源自目前普通型高中制度的遊戲版課程：修習182學分，最低取得總150、必修102、選修40，另檢核必修修習、科目與德行；已有個別身分及格標準、補考、重修／補修、學年採計、學分抵免、缺課源。正式資格不以「大學已錄取」取代；未符合畢業不能一律叫做延修，需呈畢業／修業證明／尚未完成及有根據的原因。A1原學業運作不可為新高三特例整套重寫。

**最小特殊分支**：
1. 僅高三下的單科學期成績 = 平時40%＋第一次定期評量30%＋畢業考30%。其他學期維持40%＋3次各20%；不為高三下造第三次段考或填假0分。分數、學分、名次及證據仍由同一academic journal與版本化讀取重建。
2. `src/academics/rules.js`的`semesterScore`現固定三段；`src/academics/learning.js`的`closeTerm`現要求四筆評量；`src/runtime/academics.js`的`academicInput('assess')`現依一般exams擇日。改為**同一種學期評量方案接口**，依「高三下」選兩考，非硬改所有學期或無條件放寬驗證。保留原academic v1精確重播；新政策版本遷移必須可驗而不可靜默改舊分。
3. **五月畢業考**完成→合法成績公布→補考、已有重補修成果及學年採計→正式畢業資格審查；每一節點有唯一來源與不可倒置順序。高三可能仍在校到六月初，因此須審查「考後白天正常上課」與法定修習完成條件，**不可在畢業考當日虛報已修畢後續節數**。校方補考窗口是遊戲合理假設，不能縮短法定重補修節數。
4. 學生五月學業關閉與教師學期回顧／六月年度成功／T4三年原子結局**分層**；六月末不得重新評分、送學分、重跑資格或建立第二次班級封存。對前期既有T4完成操作、CAS與還原防竄改做回歸。
5. 記錄逐科出缺席的曠課、事假及法規豁免；核准招生面試請假不等於一律公假，也不等於曠課；不得把全科總缺課平均後判三分之一門檻。畢典未核發證書者不得以「正常取得畢業證書」敘事。

**現碼缺口**：`src/academics/rules.js`、`src/academics/learning.js`、`src/runtime/academics.js`、`src/runtime/annual.js`、`src/runtime/transactions.js`、`web/notebook-academics.js`；D04的教師學期回顧結算原本依六月期末，需明確分離。A1現有學分系統、存檔codec與三年封存**重用**。

## 3. R3｜升學程序、學生分流與導師職責

**已定案原則**：導師可以輔導與提醒，不代替學生、家長選校或決定志願；成績受能力、準備與有限隨機波動影響；三年歷史影響學習歷程、備審及關係，但不能直接將「沒有獎項」判成失敗。升學路徑包含特殊選才、繁星、一般大學申請／分發、四技申請，軍警／海外／就業／未升學可用輕量摘要。

**最低有意義的程序契約**：
1. 個人有升學目標與考試資格；正式考試、學測／英聽成績、校內五學期合法校排與繁星推薦適格性各自可追溯。**轉入、轉出、休復學歷史**可影響同校修業資格；學校推薦本身不代表錄取。
2. 升學結果要分階段：報名／未報名、校內推薦、第一階段篩選、指定項目甄試／面試、各志願正備取、志願序登記、統一分發、報到／確認、依規定放棄／未放棄。不能只有`admitted=true`；同學生最多6個一般申請志願與四技申請的各自額度、學校限制、跨管道排他及第八類學群規則，均按**適用年度招生簡章**判定，未公告年度採明示可重現的遊戲假設。
3. 學習歷程及備審：從高一高二已有事件／活動／修課紀錄導出可用成果，搭配高三準備狀態與各校系截止／確認；不模擬真實上傳外部PDF或成立獨立履歷製作系統。
4. 已確認錄取者照常上白天課與畢業考；符合學校規定者可不參加其升學目的晚間輔導，自願協助同學，無強制再準備本人申請。請假、返校與面試撞期須逐人判定。
5. 班級升學氣氛是輕量衍生狀態，影響原96主題事件候選、對話與權重；**優先由既有學生節點及班級歷史計算**，不擴增玩家固定六長期能力＋六狀態或建立另一事件引擎。
6. 2029六月底三年結局只讀取**該日已知**錄取與分發，七月分科和八月分發保留待定，不得預先擲出錄取結果。

**現碼缺口**：`src/runtime/academics.js`僅有`gsat/stars/application/subject/other`粗月份窗，`subject`限定7月；要擴為版本化程序與可驗階段，不強制額外NPC、逐校招生名冊與數千真實大學校系。學業／事件／學籍／權限共用既有事實與交易規則，避免由事件文字直接改寫升學合法結果。

## 4. R4｜高三活動、畢業與三年歷史回收

1. **高二下已有三天兩夜畢旅**，高三不再加第二次畢旅。既有六月初畢業典禮保留。畢業照、團體照、畢冊、預演、整理教室、歸還物品、離校手續等可按校本假設合理分散到高三上／下，以少數校務時段或一般敘事表現；不把全部當作強制大活動。
2. 正式典禮是**特殊活動**：活動占用時段不抽新的96主題正式事件、不推進舊事件正式後續、不重複結算；典禮成果仍可一次性修改教師既有能力／狀態、NPC、班級關係與歷史，保留N1～N8的數值規則。不得在典禮日照常跑高三晚自習。
3. 畢典呈全班集體回顧與**少數具代表性學生**的個別告別，根據三年實際客觀歷史、人物觀點、知情與關係變化；不能寫死好學生感謝、壞學生改過、全班都領證、每人告別或每段都感動。轉出、未達畢業資格者是否出場取決於客觀參加條件，不竄改學籍。
4. **畢典後C方案特殊快轉**：按週推進到六月底，遇重要合法未結事項暫停；不以寒暑假每週1新事件額度替代、也不跑正常高三日課、週六自習或留校。行政善後、導師人際聯絡、私人生活與合資格持續事件可演出，無法因快轉自動解案。應先定義去重、時間前進、程序期限、狀態差額顯示及恢復快轉的驗證規則。
5. 三年最終結局沿用T4/11-E已完成的來源證據、真實學業資格、原班封存與已知未結故事；成績、結局、唯讀三槽資料不得因額外告別劇情被重算，N7不以畢業率再額外懲罰導師。
