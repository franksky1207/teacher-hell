# 第15批｜15-A 美術與音樂資源契約、原型規格（2026-11-07）

> 狀態：15-A 規劃與契約審查完成；**不代表完成素材、播放器或正式遊戲實作**。第15批工作分支 `feat/phase15-art-music-20261107`，尚未合併與部署。
> 權威規範：`docs/00-核心理念與已定案決策.md`、`docs/03-劇情與事件呈現.md`、`docs/06-介面與美術規劃.md`。本文件是實作細則，不推翻原規格。

## A1｜現況與不變契約

- `web/story-controller.js` 透過 `currentStory()` 取得正式 `readStory` 可見頁，`projectStoryScene()` 在 `web/story-scene.js` 投影為場景資料；`web/story-view.js` 與 `web/story-view.css` 顯示純 CSS 人形占位。現行 `story-scene` 只識別 `school:counselling-corner`，其餘回退「目前場景」；不得據此宣稱完成背景映射。
- 人物固定來源是 `world.numeric.evolution.world.registry.profiles[actorId].appearance.variant`（0～65535 整數）；現有畫面以 `variant % 6` 當占位色調。這**不是正式的外觀組合演算法**；不改寫其語義、不由此推定性格或隱藏資料。
- `page.cast` 為顯示基礎，最多 2 名 NPC，含 `actorId`、`position`、`expression`。電話不顯示遠端立繪；玩家導師不顯示立繪。說話者高亮，非說話者稍暗；旁白兩人正常亮度（後續實作須驗證）。
- 既有決策鎖定、回頁演出恢復、文字先行、已知資訊限制、三槽存檔、CAS、數值與校曆皆不得受美術影響。圖片／音樂載入失敗不能導致故事或存檔失敗。
- 在此階段不引入 3D、骨架動畫、即時 AI 生圖、完整資產下載中心、音效／配音、雲端存檔及額外人物 UI。

## A2｜資源契約（先作為建議的顯示層介面，不立刻寫入核心世界）

後續 15-B～15-D 在 `web/` 顯示層建立**靜態、可版本化的資源清單**，將故事情境／人物識別轉換為安全且存在的資產參照。原始事件與人物存檔不可直接保存圖片路徑，不接受由玩家輸入或事件自由文字拼接圖片 URL。

### 人物映射

輸入：`actorId`、`kind`、`appearance.variant`、當前**已知**的外觀歷史（若正式資料存在）、`expression`、`position`、正式情境服裝標籤（若有）。
輸出：有版本的 `visualKey`、相容的臉／髮型／身形／服裝圖層清單、可用表情、替代方案；不能回寫世界數值。

1. 採確定性且穩定的映射：相同既存人物、相同外觀版本與相同情境得到相同的部件；不得使用 `Math.random()`、畫面載入次數、即時日期或裝置尺寸影響外貌。
2. 優先不改既有 `registry.profiles` schema。若為正式髮型／眼鏡變動需要持久化新欄位，先另行提出相容性審查與舊檔遷移／預設規則，未經批准不得擴充存檔。
3. 畫風統一、半身彩色學生立繪；固定核心辨識特徵，允許合理小幅成長但不強制每年更換。同班低重複是畫面品質目標，**不保證**從單一 variant 與有限素材必然產出 40 張獨一無二組合。
4. 學生六表情 `calm/happy/angry/sad/surprised/embarrassed` 只表達故事所見；未提供表情時安全回退 `calm`。成年人共用深色剪影且個人辨識特徵穩定；多年後重逢的畢業生用沿襲原特徵的成年剪影。未知身分不可因圖片／替代文字被提前揭露。
5. 服裝沿用正式規格：制服、運動服、熱天／冷天便服；便服以少量共用款式及獨立服裝圖層配色，**不可整圖濾色**。情境沒有合法服裝標籤時使用中性且不矛盾的預設服裝，不可自行從隱藏心理或事件後果猜測。
6. 不可將人物名稱當作永久身分鍵：使用正式人物 ID。名字只用來呈現**當頁已公開**的內容。

### 場景映射

輸入：正式故事 `page.scene` 或合法日常場景資訊，加上當下時段與已知情境。
輸出：場景清單所定的 `sceneKey`、可用共用明暗／室內照明、載入失敗時的**中性**背景。
- 約 30 張為長期目標而非 15-A／15-C 一次性配額；按事件實際到訪頻率先做教室、教師辦公室、走廊、行政空間、校園角落、住家、校外基礎場景。
- 不製作晴陰雨三套天氣圖；白天、傍晚、夜晚優先沿用同背景的合理照明，夜間室內不得全黑。
- 不以「事件＝固定場所」取圖；醫院／法院等若無合理背景，**寧可中性背景＋文字，不以教室頂替**。無有效場景資訊時回退中性畫面而非猜測。
- `page.scene` 的合法標籤種類及遊戲主畫面的場所來源需在 15-C／15-D 接線前逐一核對；不擅改事件資料格式。

### 資產規格

- 每項資產以 manifest 指定：穩定 `assetId`、類型、相對路徑、版本、原始尺寸、必要的圖層錨點／相容組、替代物與授權資訊；路徑基於 GitHub Pages 子目錄相容的相對定位。
- 優先透明人物 WebP/PNG（按實際透明度與品質驗證），背景 WebP；尺寸與壓縮比例由小樣本實測後決定，**本階段不硬定所有圖片數量及尺寸**。
- 資產版本不同於存檔版本；舊人物辨識特徵與已儲存的外觀參數不得因新增圖片被任意重新映射。新舊版本相容策略列為 15-D 的必要檢查。
- 下載與解碼按需進行，當前場景與在場人物優先；限量預載，避免一開始下載全班完整組合。瀏覽器快取與組合快取要有容量與失敗降級；清除圖片快取**不清除存檔、人物資料或歷史**。

## A3｜15-B 的最小美術原型（品質門檻，不是正式批量交付）

- 用**至少 4 名測試學生形象**檢查性別／髮型／臉部輪廓／身形／眼鏡等具辨識差異，保持同一動畫畫風與臺灣高中制服；這些是原型樣本，非正式 40 人名冊。
- 至少驗證其中 2 名的六表情；驗證獨立的頭髮、臉部與服裝疊合、透明邊緣與定位。先測一套制服與一款便服配色，其他服裝由後續批次依結果擴充。
- 原型驗收畫面須包含：一人置中、兩人左右、普通說話／非說話亮度、手機直式與桌機橫式的同素材裁切；文字框與最多 8 選項不能使主要臉部無法辨識。
- 任何原型都需明確標示是測試素材，正式引用前另記授權與製作來源，不可引用未授權網路圖片作正式資產。
- **原型不寫正式世界／存檔，不建立整班人物。** 人物形象滿意且圖層相容後再決定擴大量與圖層組件細節。

## A4｜15-E 音樂接口預留（本批不實作播放器）

- 七類：一般校園、衝突、重大事情、在家、遊玩、溫馨感動、荒謬幽默；一類一首起步，取得符合公開網頁遊戲用途的授權與必要署名紀錄。音樂情境由**玩家已經看到**的場景／劇情氣氛選擇，不讀取未公開的風險、真相或 NPC 心理。
- 顯示層只接受有限 `moodKey`，使用靜態曲目 manifest 對應路徑。相同曲目不重播；曲目變更淡出／淡入；沒有合適資訊時選一般校園或當下合理曲目，不把未知危機透過音樂預告。
- 所有畫面小型開關及展開式音量控制；儲存開關與音量（應與正式存檔隔離）、首次有效使用者操作才嘗試播放，因 Safari 自動播放限制而失敗不得卡住遊戲。
- 不加入音效、角色配音、重大事件強制靜音、時間推進或自動對話。
