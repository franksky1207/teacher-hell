# 《教師荒謬地獄》故事量產 V3｜04 五區塊與 AVG 演出格式

> **T／G 新作、修訂及全面重寫均使用本正式五區塊範本**。第一區使用正式故事 ID 與種子欄位。單一GPT依[03 完整主流程](./03-故事創作精簡SOP.md)創作；人物[01](./01-人物數值與四碼資格.md)、時間[02](./02-事件分類與時間資格.md)、品質[05](./05-故事品質與驗收契約.md)、管理[06](./06-種子與量產管理.md)各有唯一責任。**此檔是Markdown撰稿範本，不是JSON Schema、轉檔器、遊戲引擎或已核准正式故事。**

### 已建立的離線檢查器（機械驗收）

目前可用 `scripts/check-story-draft.mjs` 檢查此範本填寫後的Markdown（**不能直接拿未填的範本當合格故事**）：

```bash
npm run content:draft-check -- --input work/your-story.md --stage summary
npm run content:draft-check -- --input work/your-story.md --stage choices
npm run content:draft-check -- --input work/your-story.md --stage full
npm run test:story-draft
```

- `summary`：要求第1、2區塊及第一區的正式 ID、有效種子與基本資料；`choices`：要求第1～4區塊；`full`：要求全部五區塊、八結果與矩陣。
- 程式讀取專案內正式2,400組種子表、20個T主題資料，檢查ID對照、角色持碼資格、選項與結果數量、NPC單次數值界限、V3四狀態分布及4×8權重與0數量；它**不自動判斷劇情好壞、32組真正因果、實際知情與在場或跨批內容是否換皮**。這些仍要由同一創作AI依SOP提供具體證據。
- 檢查器唯讀，輸出機械檢查結果。正式驗收依 05 另行完成 GPT 內容審查。

### 填寫與審查界線（不佔五區塊）

- **K已正式取消**：不填原負1.6／中1／正0.7事件K分類或倍率，也不可自行發明新選篇公式。四碼偏正／偏負是**NPC選角方向**，而矩陣4／2／1／0是**教師行動後的R結果相對權重**，均與K不同。
- **T故事合法窗口共用池**：活動前5個合法日創30篇、後2個合法日創12篇，各自在對應窗口共用抽選，不跨前後池；重疊T主題共用單日6篇創作配額。填`required_window`要寫**T20表對應池ID**，不得把配額歸屬日期當成唯一播放日；合法日只以[20主題日期表](../T1-T6-特定故事20主題與觸發日期.md)為準。
- **五區塊與各stage**：先填第1、2區跑`summary`，再補第3、4區跑`choices`，最後完成第5區跑`full`。保留五個`## 數字｜`標題、`### 開場`、`### 四個最終教師選項`、R1～R8與矩陣標題的**現有鍵名和格式**。
- **檢查器實際格式限制**：目前`合法底層增減`僅接受`無`或`student_a:1-1:+2; teacher:7-4:-1`等**整數形式**；玩家四狀態為四個整數。這只是當前**Markdown離線檢查器**的能力，不是宣稱遊戲內部數值永久只有整數；稿件型別變更須同步修檢查器與測試。
- **機械與內容驗收**：稿件檢查器強制恰一個情緒選項，正式審查工具可核對六選三證據及正文映射。因果、知情、候選實質差異與語意查重依05／06由GPT審查。
- 本範本保留`【待填】`作說明；**原始範本須填完後才執行完整驗收**。

## 填寫約定（不佔故事五區塊）

- 把全形方括號`【待填】`的提示換成真實內容；沒有必要的附加限制填「無」，**不可保留「待填」卻宣稱完稿**。表格欄名、五個區塊標題、A～D與R1～R8識別保持固定，便於後續轉JSON。
- **故事識別與種子**：`story_id` 從建檔起與檔名一致。依固定選種或可用清單填第一區 `seed_id`，第三區只列原四碼與角色因果。修訂或全面重寫時沿用原 ID、種子及既定分配。
- **任教科目代入**：所有 T／G 稿件共用 `{{teacher.subject}}`，可在開場旁白、對話、教師選項、結果敘述或電話、訊息、公告等玩家可見文字中使用。顯示時讀取開局選定並存於當局的九科之一，維持共用原稿、故事行動、因果權重與數值。情節仍為跨科通用，只在自然提到玩家科目時使用。閱讀器的科目選擇只用於預覽。缺少合法科目時保留原占位符。
- `{{teacher.name}}` 與已宣告的 `{{槽位鍵.name}}` 仍可記錄於原稿。姓名尚待正式身分資料接線。稱謂、親屬關係與職權依本局已知合法資料。
- **創作階段**先發想**1個自然情緒候選＋6個合法且實質不同的普通候選**，去重後**隨機選3個**；最終A～D恰好**1個`emotional=true`、3個`false`**。六普通候選的**簡短行動描述與中選三個編號**只放在獨立審查紀錄，不塞進五區塊正文。製作階段六選三不同於玩家畫面四格洗牌。
- **人物**：`teacher`表示玩家本人；常駐數值角色槽位鍵建議用`student_a`、`guardian_a`、`staff_a`等**稿件局部鍵**，不得自行指派實際人物ID。文字情境角色可以有台詞，**不建立姓名、ID、四碼、數值、性別欄位及跨篇出場史**；必要性別直接寫在文字裡。槽位只開真正需要的，不強迫固定學生／家長／教職員各一名。
- **結算簡寫（僅為撰稿習慣，非程式語法定案）**：`student_a:1-1:+2`代表槽位student_a的種子碼1-1增加2；`teacher:7-4:-1`代表玩家合法個人碼7-4減少1。**未列出的合法欄位視為0**；不准填非種子碼、非合法持有者或NPC→導師關係碼到teacher。四狀態固定順序為「精神、熱忱、情緒、掌控」，四個整數都要填。
- **本稿不抄驗收紀錄**：跨批查重證據、32格逐格審查報告、公式重算紀錄在正式驗收中另存；作者只在矩陣下說明**所有標0的因果不可能理由**。程式與單一創作AI可各查客觀／內容規則，不強制第二AI。
- **現行V3稿件硬規則**：四選項×八共用結果；相對權重只能`4/2/1/0`，每列最多2個0、每欄最多1個0；每R相同文字與結算，選項只影響結果機率，不直接結算底層。每個合法底層單次−8～+8、玩家四狀態依05的V3五組配置，**先隨機抽四組且不重複、排合法32格再寫八個R結果**；NPC八R平均±3限制已取消、四狀態固定−0.5。**這是稿件驗收規則，不代表已完成遊戲數值平衡或正式引擎接線。**

## 4｜玩家可見開場與四個行動

**AVG 演出標記**：在 `### 開場` **之前**放置全篇唯一的 `avg` JSON 區塊，不可夾在最後一頁開場後，避免玩家讀到原始 JSON；對應本篇現有 P 頁碼與完整 R1～R8。人物槽位需先於第 3 區定義；教師是第一人稱，同幕至多兩位 NPC。演出施工流程見 [03 主流程 D～F](./03-故事創作精簡SOP.md)，完工與退件門檻見 [05 AVG 演出驗收](./05-故事品質與驗收契約.md)。

```avg
{
  "opening": {
    "P01": {"scene": "school:classroom", "enter": ["student_a"], "expression": {"student_a": "embarrassed"}},
    "P02": {"expression": {"student_a": "sad"}}

  "results": {
    "R1": {"pages": [
      {"text": "老師，我把資料核對好了。", "speaker": "student_a", "expression": {"student_a": "happy"}},
      {"text": "你確認同學已完成手上的工作。", "speaker": null, "presentation": "narration"}

```

**此區塊僅示意 P01～P02 及 R1，正式交付必須覆蓋實際所有 P 頁與 R1～R8，不能只填範例就算完成。** 不需要表情變化的頁面可省略；對話應符合角色已知與在場，退場後再次現場動作要重新登場。現有故事不可為了湊範例而改動原有事實。

### AVG 演出資料的固定合法格式（本範本說明）

| 欄位 | 合法內容 | 使用原則 |
|---|---|---|
| `opening.Pxx` | 僅標記原始開場既有的 P 頁碼，文字來自開場正文 | 按 P 頁依序延續畫面狀態 |
| `results.Rx.pages` | **非空陣列**，內含逐頁演出物件；每頁必填非空 `text` | 新作演出可作忠於原文的對話／旁白改編，或直接將 R 原文分頁；直接分頁時須與第 5 區逐字一致（忽略空白）；改寫第 5 區時必須同步、重核因果；各 R 由相同開場末狀態重建 |
| 舊 `results.Rx` 單頁 | 原 `{scene,speaker,...}` 指令暫相容，文字仍用第 5 區原結果 | 舊故事能讀但不代表已完成 AVG 分頁；不能在舊單頁標記加 `text` 覆蓋原文 |
| `scene` | `src/runtime/story-scenes.js` 合法鍵，如 `school:classroom` | 劇情不換場可沿用 |
| `speaker` | 合法人物槽位、`teacher`、旁白 `null` | 與原文說話者相符 |
| `presentation` | `dialogue`、`narration`、`phone`、`chat`、`notice`、`email`、`news` | 按原文的資訊傳達方式設定 |
| `enter`、`exit` | 合法人物槽位的陣列 | 同幕至多兩位 NPC，換人先退再進 |
| `expression` | `calm`、`happy`、`angry`、`sad`、`surprised`、`embarrassed` | 對已在場的學生使用，可跨頁延續 |
| `pose` | `neutral`、`side`、`hand-on-hip`、`arms-open`、`gesture`、`weight-shift` | 對已在場的成人使用 |
| 事件 `music` | `school`、`conflict`、`serious`、`home`、`playful`、`touching`、`absurd` | 只填第 1 區，一篇一首，P／A～D／R 全程同曲 |

`avg` 頂層只能有 `opening` 與 `results` 兩個群組；使用多頁結果時，一個 `Rx` 物件**只能有 `pages` 一個欄位**，每頁的欄位限 `text`、`speaker`、`presentation`、`scene`、`enter`、`exit`、`expression`、`pose`。不能把 `pages` 與舊單頁欄位混用。**不使用頁面 `music`、第三人稱教師立繪、自訂服裝或數值結算欄位。** `results.Rx.pages` 不是獨立創作第二套結局：即使改編成台詞，也須涵蓋原 R 的已知事實、後果、人物反應與合理先後；不能替老師追加某個互斥選項才會做的行動。若實際改動第 5 區，須按 05 重新審查並同步 AVG，且檢查結果不洩漏 `avg` 原始碼。故事閱讀器原樣保留 `sourceMarkdown`，正式 AVG 從 Pages 匯出資料解析並核對 index 與 detail 的來源版本；以故事分支 Markdown 為來源，禁止直接修改生成 JSON。
