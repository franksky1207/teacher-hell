# G1752 專屬 SOP｜04 內容驗收、修稿與雙預覽交付

> **適用G四選四**。T的八個R、4×8權重、V3及相應審查不適用。故事真相只有一份正式G Markdown；內容、AVG、驗收證據、兩個公開頁面必須同版本。**新批次24篇整批晉升；已發布故事的後續修稿可按授權單篇晉升與更新，不等下一批。**

## 一、單篇驗收（每篇一次完整審查，修稿只複驗受影響處）

| 面向 | 通過條件 |
|---|---|
| 時間與角色 | 臺灣高中導師合理職權；符合G合法上課／寒暑輔日型；人物在籍、身分、知情、在場／合法遠端聯絡皆成立；不得假裝T專屬校曆節點 |
| 固定種子及人物 | 故事ID、S種子及原四碼與唯一映射完全一致；各碼有合法持有人及真實因果用途；無數值人物不持碼 |
| 教師選項 | 六個不同普通候選真實隨機抽三個，與一個情緒候選真實洗牌成A～D；四行動各有不同的已完成事實與代價，恰一情緒選項，保存抽選證據 |
| 四個結果 | A→R1、B→R2、C→R3、D→R4；各R延續自己的行動、具體後果及人物自主反應，且有各一份行動→結果因果理由；不出現R5～R8或權重矩陣 |
| 數值 | R各有58庫中合法且同篇互異的四狀態；NPC／玩家非零底層變動只用合法持有的原四碼、NPC每碼每R介於−8～+8；四狀態非零與底層非零均需有可追溯的故事理由 |
| AVG與原文 | 全篇唯一AVG JSON；合法speaker、scene、enter/exit、expression、pose、presentation、音樂與同場最多兩NPC；四R各自獨立；開場與結果的可見內容、行動及事實和原稿一致，不洩漏技術JSON |
| 跨篇獨特性 | 與已完成T/G及本批摘要／全文比對困境、教師處置及實際後果；只對疑似撞題者深入複查，不容許換皮及批次後段縮水 |

開場長度以約140字、每R約130字當作**品質警示而非硬門檻**；不為滿足字數灌水，人物語氣、場景、情節完整度優先。自然AVG以人物合理對話為主，不讓角色朗讀旁白。

機械驗證器必須檢查[03格式](./03-G五區塊範本.md)、四碼映射、四選四／58庫、AVG、可見正文與正式JSON，證據須標明故事ID及經核准的來源版本。**機械通過不能代替語意驗收。** G驗證器、G匯出器及兩種試演的支援尚待工程實作；不可宣稱已通過。

## 二、批次資料與驗收紀錄

- 每批24篇在`content/events-v1/G/Gxxxx-Gyyyy/`規劃及創作；正式故事檔名`Gxxxx.md`。規劃MD不計入故事。
- 批次下`驗收紀錄/evidence/Gxxxx.json`每篇一份；另有**唯一一份**`驗收紀錄/Gxxxx-Gyyyy-批次驗收報告.md`。驗收JSON保留六選三抽選、四R因果、非零數值理由、審查版本及實際結果；總報告只統整數量、錯誤、修正、查重、測試與來源版本，**不再另外堆疊多輪歷史審查文件**。
- 一批24篇全部具備合法故事、原文／AVG一致、審查證據及必要測試後，才可取得**使用者授權**一次晉升正式V1；草稿自驗、PR或CI成功都不等於已發布。
- 每批規劃前先讀取[06唯一標籤累計](./06-T648固定標籤基準與G動態統計.md)及[07故事規劃](./07-G故事主題與摘要規劃.md)。核准晉升時計入本批24篇最終有效標籤；規劃標籤不得提前入帳。

## 三、兩個正式預覽介面：首次發布及修稿都同步

| 介面 | 唯一入口與可驗證內容 |
|---|---|
| 故事全文預覽／閱讀器 | `https://franksky1207.github.io/teacher-hell/stories/`：搜尋G ID／標題、閱讀原稿／四選項／R1～R4及最新版內容 |
| 測試中心 AVG | `https://franksky1207.github.io/teacher-hell/preview/` → 測試中心 → AVG → G通用：依24篇批次選故事，觀看開場分頁、四行動及對應四R演出，含人物、表情、場景、特殊介面及音樂 |

**工程硬門檻（首批試產前）**：原`scripts/story-catalog.js`、`web/story-performance-preview.js`仍部分使用舊`G-0001`ID；`scripts/export-story-reader.mjs`目前只解析T八R和權重；`web/story-preview-picker.js`以50篇分組。必須讓兩介面及匯出器支援正式`G0001`～`G1752`與**G獨立四結果契約**，G選單依24篇批次，T/P保留既有行為。只選取**正式已完整發布**的故事，不能把規劃MD當故事。

**共用唯一來源與發布流程**：
1. G正式來源僅為經核准的`content/events-v1/G/…/Gxxxx.md`；只從該來源**產生**故事索引與單篇JSON，嚴禁直接手改`gh-pages/stories/data/`或複製第二份AVG故事稿。
2. **新批次**：24篇核准、獲授權晉升V1 → 重新匯出故事資料並部署 → 確認兩介面均有24篇且同一來源版本，故事全文可讀、AVG可播放四選四。
3. **已發布故事任何修稿**（標題、開場、選項、結局、數值、標籤、AVG台詞、立繪、場景、音樂等）：修改原Markdown及受影響驗收證據、複驗並獲授權晉升 → **立即重新匯出並發布兩處所需的故事資料**；不等下一個24篇批次。只改內容毋須無意義重建前端，但兩介面仍必須讀到最新資料；若改編譯器／UI／素材則另部署必要前端資源。
4. **版本核對**：故事索引、單篇JSON、發布記錄使用同一已核准來源版本；兩個公開頁都要實際開啟核對（含快取問題），只要一處仍舊版就算**本次預覽同步未交付**，不得冒稱成功。驗證已核准修稿的受影響頁與對應R即可；新批次查全部24篇。更動共用程式時只做必要T代表篇回歸測試，不重驗T648。
5. G試產`G0001`～`G0004`須兩處實際檢查；AVG各篇開場與R1～R4合計四個開場、16條結果路徑。四篇通過不取代第一批24篇交付檢查。

## 四、修稿／版本與統計

- **原稿修正**：只重驗受影響段落、選項、R、數值及AVG；若改教師客觀行動則重驗對應固定R；不因改一篇而重做整批或T648。新證據要對應新來源，不得沿用舊SHA冒稱現稿通過。
- **標籤入帳**：新批次24篇首次核准後依[06](./06-T648固定標籤基準與G動態統計.md)新增一次；已發布故事修訂若標籤變動，**替換原批次該篇標籤後重算**，絕不增加已驗收篇數；標籤不變則不增加任何計數。
- **交付狀態**：S1原稿與四R完成、S2語意／因果／數值核准、S3 AVG完成、S4編譯與定向驗證、**S5已授權發布且故事閱讀頁＋AVG均實際呈現相同最新版**、S6正式遊戲引擎／存檔／結算（另行授權）。S1～S4不得冒稱S5或S6。
