# 第18-A｜事件內容唯讀檢查器與 T／G 製作規範

> 2026-11-17 起停止使用舊 128 T 主題、每題 20 則、至少 2,560 則的稽核配額。**2,400 組四數值種子是新選項事件的全庫規劃，不是檢查器宣稱已完成的 2,400 則故事。** 被動 P 另議且不納入選項事件庫。

## 內容分類

- `T1`～`T6`：高一上、高一下、高二上、高二下、高三上、高三下的時間專屬事件。凡考試、活動、節慶、季節、假期、升學程序、學期階段等時間相關起因一律歸 T，**不做跨學期活動通用故事池**。
- `G`：不依賴特定時間階段的一般通用事件，仍有正常人物／時段／場地硬性合法資格。
- `P`：被動事件，尚未定義，也不進目前四選項事件檢查器。
- `E01-01`～`E12-08` 僅為內部尚有引用的歷史事件識別，不能再當成新作分組。退役的 `T01`～`T16` 完全不作新版類別。

## 唯讀檢查器操作

```bash
npm run content:audit
node scripts/audit-content.mjs --output work/content-audit.json
node scripts/audit-content.mjs --input work/content-batch.json --baseline work/previous-batches.json --output work/content-batch-report.json
node scripts/audit-content.mjs --input work/content-batch.json --strict
```

每筆輸入：`{story, definition, editorial, editorialReview}`。靜態檢查包含官方故事／事件結構、T／G 事件識別、資源／版號一致性、故事因果欄位、基本四選項及已有權重變體、跨批相似起因告警。獨立 AI 審稿需提供具體起因、教師責任、知情來源、不同後果的實質分析；字串相似度不是 AI 品質判定。

報告按 **T1～T6 與 G 七組**列出草稿、結構合法、已審閱、資源可解析、已註冊的數量；不再產出固定 128 主題的空白表或逐題最低篇數，亦不會自稱故事已發布到新生涯。

**注意現階段過渡限制**：此 CLI 暫時沿用現有 `validateEventDefinitions` 的六欄加權與 `validateStory` 的既有合法結果格式；新版「四數值 × 四選項 × 八共用結果」仍需後續工程契約實作，因此舊示範通過，只能證明舊引擎結構合法，不是新版完整驗收。使用者未要求時不啟動大量生成、不反覆跑三年模擬。
