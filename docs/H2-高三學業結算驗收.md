# H2 高三成績、學分與五月學業結算

本批基準為 H1 `061bf632607a5d3f9821329529f54086d89ebb5b`，只接學業、必要筆記本資料及六月教師結算契約。沒有改 H1 的考日／時段、固定40年資料、三年2026開局、30年核心，也沒有實作 H3 升學、H4 畢典後快轉或 H5 整體介面。

## 政策與版本

- 學習／課程／法規引擎保留 academic v1、v2，未改舊版本的學生分布、課程、及格標準、學分門檻或已保存分數。
- 新增獨立**學期評量政策** `senior-spring-403030-v1`：只適用 H1 校曆的高三下，round 0 平時40%、round 1 一段30%、round 2 畢業考30%。無 round 3、無補零。其他五學期與原固定校曆仍用原四筆評量／40-20-20-20。
- 唯一權重及輪次在 `src/academics/policy.js`；`semesterScore`、`assess`、`closeTerm` 消費相同契約。現行一位小數以整數十分位求和後四捨五入；舊 v1 一般學期的原浮點計算順序保留，避免改動舊史。
- 校曆 `assessmentCalendar` 提供政策ID、正式兩考、平時評量日期、成績關閉／公布／補救窗口、修習完成日、畢典與教師期末日。`academicInput('open')` 將本學期政策與窗口寫入日誌，重播校驗它們與保存的校曆版本相符。
- **舊 H1 開啟中的高三下**若尚無學期政策，可由 `adopt-senior-policy` 追加一筆有版本的接續紀錄；只接受未關閉且沒有 round 0／3 的原 H1 狀態，不改既有日誌或已有一段／畢業考分數。日末接點會自動辦理接續。
- 原校曆的舊三年檔／30年檔不套新公式。舊 academic v1、v2 的一般學期及結算逐筆重播，不遷移學分、課程或原結局。H1 既有 v1 日誌保留 v1 課程／及格及資格規則，新的兩考學期另以相同 H2 政策ID接入；正式新局仍為 v2。
- **不補造錯過的資料**：若 H1 舊檔已經越過平時評量日卻沒有該次平時成績，載入仍保留原史；接續不倒回日期、不代造平時分，也不允許用缺分關閉。這類缺少正式來源的狀態不能冒稱已完成新制結算。

## 2029 五月正式流程

| 時點 | 正式資料 | 保護 |
| --- | --- | --- |
| 4/6 一段最後考試時段後 | round 1 | 翌日才顯示當考成績 |
| 5/8 畢業考最後考試時段後 | round 2、round 0 | 不建立第三考 |
| 5/8 日末 | `close`：40/30/30正式分數 | 課程 `completed:false`，尚未授予修習完成資格 |
| 5/9 首次完成正常時段 | `release`：公布紀錄 | 此前遮住平時、學期、取得學分及可反推分數的總計 |
| 5/10起、畢典前審查窗口內 | 原 `support`、補考／重修／補修日誌 | 原及格／登錄規則，逐實際日期共用每人2節；不在假日、正式考試或特殊活動日安排本窗口補考／補救學習 |
| 5/31 最後上課日日末 | `complete-study` → `review` | 必須有5/9至當日所有必要在校節次／活動階段的真正 slot-complete；缺一即拒絕，不能以經過天數替代 |
| 6/1 畢典 | H4 可讀五月資格快照 | H2 不演典禮或將學生提前離班 |
| 6/29 教師期末 | 原學期回顧／年度成功／T4 | 消費五月來源，不再評分、送學分或重做學生資格 |

畢典前最後合法上課日與補救窗口是依本校固定校曆推導的**遊戲校務方案**，不是宣稱全臺法規一律5/31結算。原 A1 的至少隔兩日、最長30日補考窗，在這份畢典前資格快照中只採實際已完成的部分；未到期或未修滿者保留待辦與時數，不宣稱依法逾期或自動結案。重修個別指導每學分3節、達15名同課當日申請者專班每學分6節、補修每學分6節均沿原 A1，不為五月期限縮短。

`completed:false` 的 `earned` 是依已確認分數計算的條件值；正式累計、資格、筆記本及教師年度學分證據都排除未完成修習課程。筆記本顯示「待修習完成」，不把條件值當成已取得學分。5/31才以實際修習證據完成認列。

考後仍有正式出缺勤來源時，5/31逐科重檢曠課／事假扣除合法豁免是否達三分之一；必要歸零以 `attendanceAdjustments` 留證，原評量成績保留為 `assessedMark`、五月原關閉日誌不變。已依法完成的重修成果仍按原制度，不能用補考規避缺課零分。高三下學年採計等到修習與出缺勤確認後執行，不先給其他學期不存在的學分。

依據沿用 [A1正式查核](../simulation/results/academic-a1-20261105.md)：現行評量辦法§4、7、8、10～12、16、25、27及111課綱。維持182修習、總150／必修102／選修40、必修修習、國英與實作等條件及德行；不以錄取代替資格、不提高分數或硬編畢業率。未完成的補救不虛構時數或學分。

## 唯一來源、原子性與六月

- `finish-slot` 仍是原時間引擎的日末接點，負責兩考／平時、關閉、公布、補救、修習完成與審查；新操作全部是原 `academic` 日誌類型。
- `complete-study` 保存已完成節次的歷史 order 清單與區間；`review` 保存全部實際在班學生、入學來源、全部前置學業 order、個別資格及尚未完成補救。還原會重新驗證日型、名冊、次序、時數、數值與 RNG；同一天的轉出／轉入以既有學籍收據在該筆日誌之前的順序核對，只重建名冊參照投影，不改玩家歷史，不相信保存的資格布林。
- 五月最後一個日末由同一原交易完成修習與資格快照，經原 CAS 一次發布。故障不留半完成；同ID重送取舊收據、不同ID重做被拒絕。
- `readAcademicQualification` 對已有正式五月快照的學生讀取該來源；六月 T3／T4 亦沿此接口。關閉學業的資格／學分不在六月重算；尚未完成的補救方案保存在快照，沒有在六月因結局補發。
- `academicTermClosed` 依真正學期政策檢查完整評量；高三下還必須有五月修習／資格快照，不能以「有兩個分數」冒充 T4 前置完成。原教師 coverage、實際授課證據、兩次教師回顧、六月末邊界及原子 T4 仍然必須成立。
- 無教師五月學期回顧、無提前年度成功、無提前班級封存／教師任職結束或三年結局；六月原結算不新增第二條入口。

## H3～H5 承接

- `readSeniorAcademicReview(world, termId)`：版本1、termId、date、sourceOrders、outcomes。每人含 personId、qualification、pendingRemedies（kind、subject、已修／必要時數）。這是當時已知學業來源，不是升學資格或錄取結果。
- `readAcademicQualification`：沿用 A1 的 eligible／certificateEligible／incomplete 與原因、學分、德行及缺修資料；未完成補救另由 pendingRemedies 查閱，不把所有人叫「延修」。
- `readGrades`／筆記本投影：既有評量與學期資料、正式考試欄位及公布狀態；高三下只有一段／畢業考，修習未完成的條件學分不作取得學分顯示。未公布資料也不能藉切換舊學期取得總計。
- H4 應使用已保存的五月資格來源安排典禮呈現，保留未完成事項；H3升學、H4畢典後週快轉、H5整體畫面與完整自然三年驗收仍由後續批次處理。
