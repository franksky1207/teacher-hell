# S2 三年存檔容量與效能驗收（2026-11-05）

本批僅優化正式 IndexedDB 的實體存檔：原本的完整 v1 `world + opening` JSON，以原生 Gzip 無損壓縮後分頁存放。遊戲資料、人物差異、學生歷史、學業規則、事件、N6 收據、年度結算及結局均不裁減；手動匯出／匯入仍為原 v1 JSON。沒有 50% 或固定容量上限的驗收門檻。

## 來源與量測界線

開發基準為 `53bf641e946be75788956e51788ce619da7cd78f`，指定累積分支及 Draft PR #20。容量來源來自 [T4 正式報告](three-year-t4-20261105.json) 的三種真實連續三年 artifact；Easy 使用 run `41971561739`，Normal／Hard 使用 `41971866724`。來源包含原始 manifest、SHA-256、種子與重現 driver，沒有重新生成三年，也沒有以合成資料替代。

本機 artifact 下載遭 Azure blob 端 403；GitHub Actions runner 正常取得同一批原檔。完整來源 SHA-256、逐欄分布與原始量測另存小型 JSON 證據。大型 completed/world/opening 檔均留在 Actions artifact，不進 Git。

`completed.json` 才是完整玩家 payload；獨立 `world.json`／`opening.json` 是 T4 便於核對的拆檔，不另加進容量。`before-completion.json`、`latest-opening.json` 也是不同測試時點，不能和完成存檔相加。完成檔中的 opening 則是正式重試／年度連續性所需，必須保留。

## 方案與安全邊界

- 僅修改既有 storage adapter，沒有另一套 session／交易系統。實體 head 的 `format: 2, codec: gzip` 與遊戲 payload 的 `version: 1` 分開管理。
- UTF-8 輸入逐段編碼，避免切斷 surrogate pair；原生 Gzip 非同步處理後合併成最多 256 KiB 的二進位頁。沒有 Base64 儲存膨脹或 WASM／壓縮套件依賴。
- head 保留 token／generation／chunkCount，另記錄展開 bytes 及壓縮資料 SHA-256。讀取先檢查版本、頁型別／數量、SHA，再逐段解壓並限制不得超過宣告長度，最後執行原有完整 restoreSave 驗證與 detached clone。
- 壓縮準備、hash 與完整驗證都在 write transaction 外；transaction 內仍執行原 CAS、永久 generation、pages／head 同時替換與失敗回滾。壓縮失敗不會先清掉原槽；異步等待期間的競爭仍由最終 CAS 拒絕。
- 舊文字頁不改寫即可讀取；下次正常成功寫入才升級，失敗則保留原文及 token。無原生 gzip／解壓或 Web Crypto 能力時，新寫入沿用原文字格式；不能解讀現存 v2 的瀏覽器明確拒絕，不默默當成空槽或降級清檔。
- 手動 v1 備份仍可讀取、匯入、匯出；沒有修改三個槽、namespace、唯讀完成狀態或 memorial 規則。壓縮 checksum 是損壞檢測，並非玩家資料的密碼簽章；原有所有語意及交易驗證照常執行。

不先做跨 world/opening 的共用前綴、短鍵名或歷史裁剪。相同 ID 不保證內容相同，opening 是必要還原證據；共用結構需要額外重組／alias 隔離及版本分支。原生壓縮能處理重複鍵與字串，工程維護成本較低。S1 小來源的前綴加 gzip 沒有穩健額外收益；本批不拿該比例外推三年，也不以理論相同子樹 bytes 冒充實際可刪容量。

## 可重現流程

1. 讀取 [S1 分析](storage-s1-20261105.md)、T4 報告與目前 storage/runtime；先在 runner 下載原 artifact，逐欄歸因，再決定方案。
2. `node --max-old-space-size=6144 --expose-gc scripts/save-capacity.js attribute work/source` 產生互不重疊、精確加總的 UTF-8 partition，以及相同子樹、歷史類別、重複鍵／長字串、request 與 evidence 的診斷。診斷彼此可能重疊，不可再相加。
3. `node --max-old-space-size=6144 --expose-gc scripts/storage-s2.js work/source`：JSON 與 Gzip 各兩次全新程序，核對原檔 SHA、逐步時間、完整還原後全檔 SHA、階段記憶體與程序 maxRSS。
4. build 後執行 `node scripts/storage-browser.js --s2 --legacy` 和 `--s2`。前者只在暫時測試站以 `git show 53bf641:src/storage/indexeddb.js` 安裝精確舊 adapter；其餘程式及來源相同。每種方式使用全新 Chromium profile，測真實 IDB 寫入、讀取、實際頁面導航後恢復。這段舊 adapter 僅從 Git 取出作基準，不在正式程式保留第二套邏輯。
5. Easy 真實大檔另做 IDB 中斷、注入 QuotaExceededError、CAS 拒絕及每次故障後完整 payload hash 回讀。`three-year-checks.js` 重用真實完成前／後檔驗證終局重送、失敗原子性、竄改拒絕與完成後唯讀。
6. 小型 Chromium 契約額外驗證舊頁讀取／升級及升級失敗、三槽、跨頁競爭、刪除 ABA、壓縮準備失敗、備份恢復、未來版本拒絕；這些明標工程契約，不當作真實三年容量來源。

Node 的 JSON codec 控制組保留單一文字頁，不冒稱舊 IDB 的分頁／磁碟成本；實際舊分頁成本由 Chromium 舊 adapter 對照量測。Node 時間為同一 runner 的兩次獨立程序觀測，不混用不同硬體的數字。maxRSS 是整個測試程序高水位，階段 heap 是抽樣；Chromium RSS 為 250 ms 抽樣的程序樹合計，可能重複計共享頁。瀏覽器完整驗證 hash／唯讀探針也會影響整輪高水位及最大 heartbeat 延遲，不能把它們說成純解壓或手機峰值。IDB logical page bytes／head JSON bytes 與 `navigator.storage.estimate()` 的實體使用估計分列，後者含瀏覽器配置成本且非精確檔案大小。

## 驗收限制

- Gzip 降低持久化容量，解壓後仍需完整 world/opening；不宣稱人物或歷史的執行期 RAM 隨壓縮率下降。
- JSON stringify／parse、既有完整 world 驗證與 detached clone 仍有同步成本；非同步 codec 沒有消除整段主執行緒停頓。未為漂亮數字跳過驗證，也沒有引入大量狀態搬移的 worker 架構。
- 手動 JSON 備份容量維持原值；沒有在這批擴張備份 UI／檔案格式。
- 真實儲存 quota 依裝置與 origin 而異；故障測試注入 QuotaExceededError 驗證原子回滾，沒有把磁碟寫滿。storage.estimate 是觀測，不用預估可用空間取代真實 transaction 錯誤。
- 沒有 Safari／iPhone 真機、自然 30 年或長期手機記憶體耐久證據。完整三年狀態及重啟實測不能直接等同所有手機均流暢。
- 原 T4 每班 40 人僅 7 人有畢業資格的規則問題原樣保留，後續獨立處理。本批沒有開始 T5、合併 main 或發布網站。
