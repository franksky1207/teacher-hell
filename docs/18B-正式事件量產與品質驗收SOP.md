# 第18-B｜正式事件量產與品質驗收 SOP（現行統整版）

> **唯一有效的18-B量產操作規範｜2026-11-15**。本版取代本檔舊版的階段性提案、過期阻斷、Draft狀態與重複修訂。**已完成的工程能力不再寫成待實作**。正式故事欄位、校曆、數值和可用功能以現行`main`驗證器及 [17-D事件內容量產SOP](17D-事件內容量產SOP.md) 為準；檢查器操作以 [18-A工具規範](18A-事件量產工具使用規範.md) 為準。本文件中的編輯表欄位與L1～L5標籤**不是runtime欄位**，不能當成合法故事JSON。

## 一、量產目標與不可改動規則

- 16個大主題各8個小主題，共128個小主題；**每小主題至少20則真正不同的事件**，正式最低目標2,560則。**20是最低合格門檻，絕不是撰稿目標、探索終點或批次上限**。不同姓名、日期、背景、同故事不同選項／variants／後續頁，都不能額外計件。
- 以臺灣高中真實作息、校園權責、合法時段和必要制度研究題材，但事件人物與故事自行虛構；未證實的指控不得成為客觀已知事實。
- 每則正式事件符合既有17-D四選項、1～2個自然情緒選項、合法`replacement.requires`及實際候選資格。四種選擇必須有**實質策略差異**，不能只有不同語氣。
- 同一選項**可以**因學生、教師、既有歷史與合法權重產生多個合理結果；簡單選項也**可以只有一個結果**。不得「按下查詢就保證查到／按下協調就保證成功」，亦不得用毫無情境根據的機率反轉。
- 正向、普通、荒謬、壓力、困境故事均可自然存在；不設固定正負比或L級比例，不強制每篇跨日、開長期問題、加數值變化。
- 不改N1～N8、K倍率、六長期能力、48隱藏欄位、教師難度、每日事件額度、40人曝光、校曆、存檔或隨機機制；不另建一套故事／因果結算器。40人要有公平的實質互動機會，不可用危機灌曝光或硬性輪流出場。

## 二、唯一權威與目前已具備的工程能力

- PR #59、#61～#65已合併`main`：歷史截面與版本、已確認事實的具體問題操作、人物知情和定向關係、跨主題問題根候選／鎖定及最小存讀整合，均屬**現行已實作能力**。不得沿用「A～D尚未實作」「待分五個工程包」之類舊文字重新要求施工。
- 新式故事依正式`compilerContract:2`及已支援的`outcome.world`、`relationshipChanges`、`issueOperations`、`bindingContract:1`、`eligibility.issue`、`issueBindings`撰寫。若不需要這些功能，可採合法舊契約；**不能**為了統一格式改寫已確認歷史。合法性以`validateStory`、`validateEventDefinitions`及正式交易驗證為準，不由本文件自行擴欄。
- **事實／說法／分類／問題狀態分離**：客觀結果用已確認事實，人物說法用有來源的`claims`，`historyCodes`是歷史分類，不是未解問題開關。持續問題由合法`open/progress/close/invalidate`因果操作和事實投影重建，不新增可獨立修改的`issues.status`表。
- **證據與知情**：當事人、受影響者、實際見證者及接受傳達的人分別判斷。未在場者不因被提到名字就知情；沒有文件存取授權不能憑空取得機密。關係變化必須有真實接觸／合法資訊來源，方向由來源→對象明確界定，不自動對稱。
- **問題根與時間**：候選首次接納資格和已接納故事的延續資格要分清；續篇不能換根、換人或引用未發生的未來。外部終止、轉學／離班、合法接觸消失時要遵守既有拒絕或失效規則；時間經過本身不代表履行成功。
- **歷史資格**：依正式候選驗證契約，非空`eligibility.history`需用合法`cumulative`類型；`direct`不得為湊歷史條件直接塞入。跨主題要追蹤**同一具體問題**時，應用合法`eligibility.issue`綁根，不能憑相同學生、相同H碼或日期推斷為同件。
- **版本與資料完整性**：資源ID、definition、版本與抽選引用須能持久重播；已被存檔引用的版本不可以無聲修改。索引只是衍生資料，不能跨attempt、歷史截面或匯入世界混用；只有實際量測出瓶頸才評估最佳化。

## 三、L1～L5編輯因果分類（可複選、不計數、不成為引擎參數）

| 類別 | 適合用途 | 必須守住的界線 |
| --- | --- | --- |
| **L1 當次日常** | 小插曲、安慰、正向肯定、一般校務 | 可當天收束，不硬塞衝突、數值或後續 |
| **L2 人物／關係** | 學生特質或已知關係影響可選策略與後果 | 不能只換姓名；用正式數值碼及有證據的單向變化 |
| **L3 同事件跨日** | 前一日策略／實際結果影響隔日內容 | 沒有確認的結果不能寫成已完成；必要時分支，否則只敘述共同已知事實 |
| **L4 具體問題／跨主題** | 真正持續的待處理事項、跨其他主題合法追蹤 | 開根、推進、結案、失效各有確認證據；不把一般小事都拖三年 |
| **L5 多人物知情／傳達** | 隱私、說法、不同知情範圍及後續關係 | 傳達要有發送者、接受者與來源；謠言不等於事實 |

示範：T10-03-03素食餐可用L3+L4；13生日卡片用L2；20午餐交接用L5，必要時加L2。以上是**題材分類例子**，不是將隔離示範直接變為正式完成事件。

## 四、每則事件的編輯工作表（不是故事JSON欄位）

正式撰稿前先填可追溯的精簡骨架，最少包含：

1. **身分與來源**：主題碼、唯一事件ID、作者／版本、題材研究來源、虛構與制度依據、既有採納稿版本。
2. **起因與教師責任**：客觀已知／學生說法／仍未知，各自的知情來源；是否屬於導師合理權限，必要校安、性平、霸凌、健康或行政程序。
3. **人物與時段**：合法對象、學年、日型、時段、場景、當事人、受影響者、見證者、其他人不能知道的內容。
4. **四種策略與後果**：四格真正不同的做法與情緒表現，逐一列可能結果；何者為已確認、尚待查證或可能加權變體；哪些才適合改數值。
5. **因果結構**：L級與理由、是否開／推進／收束原問題、證據根、是否跨日／跨主題、前後人物狀態與關係變化。
6. **去重及審查欄**：同批及全部已接受baseline的相似ID；結構檢查、獨立語意審稿者與記錄、退修、複審、正式解析／候選／新生涯驗證狀態。

僅更換姓名、日期、立繪或表面情緒，若四策略、教師職責及實際結果幾乎等價，仍是**疑似換皮，不可新增事件計件**。不要求每個事件必須同頁數、同人物數或同敘事節奏。

## 五、單批正式事件製作的七步作業

1. **選主題與題材研究**：先核對128主題、臺灣學校情境和已接受內容，區分來源／推論／虛構。已有試產素材時優先挑出可沿用骨架及需退修處，不整批推倒重寫。
2. **開放式題材探索、骨架及跨批去重**：每個小主題先向不同人物立場、日常／正向／荒謬／壓力、教師責任、資訊落差、處理途徑、單日／跨日及合理結果等方向**主動持續發掘題材**，不得只列出20個構想就轉入撰稿。可先探索30～50個甚至更多候選作為工作方法，但**30～50不是硬性配額或停止點**；對全部候選比較客觀起因、教師職責、資訊、四策略及真實後果。實質重複者合併／淘汰並留下理由，其餘值得獨立存在的候選都保留撰稿，不為湊整數刪減。同批相互比，跨批以累積**已接受事件**的明確baseline比對；工具只提供疑似預警。
3. **設計人物、因果與結果**：逐篇決定L級、合法候選與時段、見證及知情界線、四種合理策略；需要時才加`variants/modifiers/replacement.requires`及具體問題根。數值改動要能說明因果，不是每篇必改。
4. **完成故事與必要安全處置**：依17-D正式契約逐頁撰寫。危險積水、刺鼻清潔劑、可能污染的餐點、危險進食競速、可能公開個資時，**不可省略的最低安全／隱私措施要在提供四選項前先完成**；四格是在安全底線之上的不同合理後續策略。清掃`early`僅是舊隔離測試假設，不能視為全校固定清掃時段的證明。
5. **精準結構驗證**：用現行`validateStory`、`validateEventDefinitions`及18-A稽核，檢查作者schema、候選資格、四選項、權重、時段、資料版本、相似事件。只有實際執行有紀錄才能標結構通過；工具成功**不等於**故事自然或因果合理。
6. **與撰稿分離的獨立語意審查與局部退修**：逐則查「起因→台詞→四策略→各個結果→跨日／跨主題」，特別查傳聞、知情、校務權限、數值意義、安全底線和是否套皮。審查必須留下事件ID、具體矛盾、修正內容及複審結論；**同一模型自我複查只能標自檢，不冒稱獨立審稿**。有缺陷只退該件，不重寫整批。
7. **批次玩法與版本交付**：檢查一整批是否重複同樣四句、同一結果、同一場景、同種情緒；保留正向／荒謬／普通日常。整理採納與待修數、疑似重複、實際測試證據、版本與未驗事項，等待正式接線放行，不讓作者自動發布。

**批次切分**：以**每輪4個小主題、每個小主題一次完整探索與製作**為預設管理方式，每個大主題分2輪、全案初步分32輪；這是管理分組，不是各輪只能交付80則。若四個小主題最後可保留27、36、23、41個實質不同構想，就應依品質流程製作127則，而非裁到80則。模型單次輸出負荷過大時可在**同一輪內**拆成較小撰稿單元，不要求使用者每20則重新指示。每小主題最低20個合格事件；不能因先有20個`engineering-test`就宣稱正式20／20。**小主題結案的停止條件不是達到20，而是完成多方向題材探索，並能說明尚未採用的候選為何重複、不適合、缺乏獨立價值或暫需另外研究**。保留探索數、去重／淘汰數、具體淘汰理由、撰稿數與正式接受數；低於20仍不合格，達到20但還有值得寫的候選仍繼續製作。使用者不必逐篇手動驗收。

## 六、品質門檻與紀錄狀態（不能跳級）

| 狀態 | 成立要件 | 不代表 |
| --- | --- | --- |
| `authored` | 有可追溯稿件 | 已通過結構或語意 |
| `structurallyValid` | 針對該版本有實際執行成功的合法性證據 | 劇情自然、人物行為合理 |
| `reviewed` | **與撰稿分離**的具體語意審稿、退修／再審紀錄 | 保證一切正確、已正式上架 |
| `resolverReady` | 正式資源能以指定ID／版本解析 | 已註冊可抽選 |
| `catalogueReady` | 合法候選定義已註冊、權重及資格驗證有證據 | 實際玩家已看到 |
| `publishedInNewCareers` | 新開生涯可合法抽到及接納的證據 | 所有長期分支或三年流程已全面測過 |

**正式可計數單位**：完成必要內容與放行條件的獨立正式事件ID。試產`engineering-test`、只在resolver供測的工程資源、同事件variants及未審稿，均不列入正式2,560件。若尚缺審稿或上架證據，標待審／未驗，而不是填`approved`或改`ready`掩蓋。

**不能放行的情況**：選項相似到僅換說法、沒有證據就推定他人有錯或問題已解決、未到場者突然知情、未有接觸就更動關係、不同結果其實相同、違反時段／校務程序、只選某格才有最低安全處置、未依版本契約改動已確認故事。需要依法處理的校安／霸凌／性平／身心危機，額外檢查實際程序。

**審稿執行者須具體記錄**：獨立AI或其他真正不同於撰稿流程的審稿者／來源、對應版本、逐篇實質理由。不宣稱本次PR #60或PR #66已有這種完整簽核。

## 七、精準測試、成本與GitHub規則

- 以本批故事內容／契約專項為主，必要因果案例**最多三組聚焦測試**；錯誤先定位，再只重測影響項目。不為證明一篇故事跑完整三年／30年、N1～N8、完整瀏覽器與手機矩陣、全部事件回歸或大量seed。
- 必須明確回報「已寫測試／確實執行／通過／失敗／未驗」及當次提交、指令、測試紀錄。工作流程建立、PR標籤或先前某次綠燈都不能取代對應版本的證據。
- 工具：`node scripts/audit-content.mjs --input work/new-batch.json --baseline work/previous-batches.json --output work/new-batch-report.json`。baseline需由作者提供**全部已接受**內容的明確範圍；CLI不會自行取得全庫，也不能靠字串分數自動刪除或核准事件。詳細使用法請參考18-A。
- 維持原來的分工：Chat可做題材、規格、撰稿、審查、GitHub小規模修改；Codex只在需大量工程實作時使用，均不得因方便而自行擴大測試。**不額外設全面GM測試中心**。
- 每批完成提供：主題／事件ID範圍、寫作與退修數、去重差異、結構／語意審查證據、實際通過的精準測試及未驗項、來源分支／PR、正式計件與是否上架。**沒有得到使用者明確授權，不自行合併、部署、升`ready`或發布**。
