> **製圖與驗收操作**：每次先遵守 [單張製圖驗收與交付標準流程](./15-B-單張製圖驗收與交付標準流程.md)，再依本文件決定唯一編號、狀態與下一張。
> **此文件是跨對話的唯一進度基準**。每次製圖前必須先讀此檔與 [B1～B23 美術規範](./15-B-正式美術原型規範.md)，並核對 GitHub 實際檔案。不得依對話印象猜測下一張、宣稱尚未驗收的素材已完成。最後更新：2026-11-07。
>
> 製作分支：`feat/phase15-art-music-20261107`；**不使用 Codex，除非使用者明確要求**。沒有使用者指示，不合併、不部署。

## 1. 唯一編號規則

編號採「資產類別＋三位流水號」，同一編號長期指向同一美術原型，不重用、不因更名而變更。

| 類別 | 代號／編碼示例 | 用途 |
|---|---|---|
| 學生原型 | `student-001`, `student-002` | **美術原型 ID**，不等於正式故事 NPC ID／座號；與正式遊戲 `appearance.variant` 之對應尚待 15-D 設計 |
| 成年人剪影 | `adult-001` | 同一可辨識成人原型 |
| 成年畢業生剪影 | `graduate-001` | 與畢業史的對應需另依故事權限處理 |
| 制服／運動服設計 | `uniform-001`, `sportswear-001` | 同校服飾共用母圖 |
| 背景場景 | `scene-001`, `scene-002` | 同一場景永遠共用此 ID，不因手機桌機不同而另編號 |
| 音樂 | `bgm-001` | 第15-E批獨立建檔，不與圖片共用流水號 |

- **編號以 001 起算，僅在確定開始新的原型時分配。** 不預先憑空登記 40 名學生、30 個背景或大量虛構素材。
- 角色名稱、人設、班級與學年不可寫入永久檔名，以免劇情資料變動時素材失效。
- 同一 ID 的每個表情／服裝是獨立檔案，**不是新的學生 ID**。
- `student-001` 目前僅是第一個製圖原型，**不代表已核准正式人物或正式學生資料**。

## 2. 統一檔名規則

一律小寫英文字母、三位十進位序號、連字號 `-`；不使用空格、中文、日期或隨意新代碼。檔案版本改以 manifest／Git 歷史記錄，不在每次修改時改名成 `final2` 或 `new`。

| 類型 | 母圖檔名示例 | 正式遊戲輸出（通過驗收後） |
|---|---|---|
| 學生中性基礎圖 | `student-001-base.png` | `web/assets/characters/students/base/student-001-base.webp` |
| 學生六表情 | `student-001-expression-happy.png` | `web/assets/characters/students/expressions/student-001-expression-happy.webp` |
| 學生髮型部件 | `student-001-hair-01.png` | `web/assets/characters/students/hair/student-001-hair-01.webp` |
| 學生服裝部件 | `student-001-clothing-uniform.png` | `web/assets/characters/students/clothing/student-001-clothing-uniform.webp` |
| 學生配件 | `student-001-accessory-glasses.png` | `web/assets/characters/students/accessories/student-001-accessory-glasses.webp` |
| 成人剪影 | `adult-001-base.png` | `web/assets/characters/adults/adult-001-base.webp` |
| 成年畢業生 | `graduate-001-base.png` | `web/assets/characters/graduates/graduate-001-base.webp` |
| 制服基準 | `uniform-001-master.png` | 服裝部件通過驗收後再依人物與用途另輸出 |
| 背景雙版本 | `scene-001-desktop.png`、`scene-001-mobile.png` | `web/assets/backgrounds/desktop/scene-001.webp`、`web/assets/backgrounds/mobile/scene-001.webp` |

- 六種正式表情代號固定：`calm`（平靜）、`happy`（開心）、`angry`（生氣）、`sad`（難過）、`surprised`（驚訝）、`embarrassed`（尷尬），不得另用 `smile`／`shocked` 當同義變體。
- **存放路徑決定階段**：`artwork/prototypes/` 未核准草圖；`artwork/masters/...` 候選或已核准母圖；`web/assets/...` 已通過可上線相容驗收的壓縮輸出。母圖路徑中的「masters」**不等於已核准**，仍以本進度表狀態為準。
- 對同一原型的一張完整人像，縱使透明，仍不得冒稱分層；必須在進度表分別標記母圖、可換臉表情、衣服部件、組合驗證的實際結果。
- 母圖重製但尚未核准時沿用原 ID 與路徑，由 Git 版本記錄；一旦核准需改版時先記變更原因、相容風險與核准紀錄。
- 不把同一場景橫向圖片裁切成手機版，必須各自獨立製圖。

## 3. 狀態定義與驗收紀錄

| 狀態 | 意義 |
|---|---|
| `planned` | 已排定，尚未生成 |
| `generated` | 已生成，尚未逐項驗收 |
| `needs-fix` | 檢查不合格，須修正或重畫 |
| `candidate-uploaded` | 候選素材已存在 GitHub，但尚未由使用者核准、未完成分層驗證 |
| `master-approved` | 關鍵母圖已由使用者明確核准（僅母圖合格，不等於可直接上線） |
| `integrated` | 已正式輸出並接線、通過對應遊戲顯示／相容性驗收 |

每一張素材更新時需記：**ID、檔名／路徑、尺寸、透明背景檢查、身份／畫風檢查、錨點與相容檢查、使用者核准、GitHub 存在狀態、尚待事項及下一步**。未確認的欄位記 `待驗證`，不臆測通過。

## 5. 每回合工作規定
