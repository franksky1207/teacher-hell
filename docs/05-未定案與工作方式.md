新ID由 `createId(kind, parts)` 使用**明確呼叫端提供**的非空字串tuple產生；
kind涵蓋career／attempt／cohort／class／enrollment／event／stage／fact／claim／result／effect／settlement。
例：`event:["career-key","attempt-key","event-1"]`。JSONtuple避免分隔字元碰撞，無時間／隨機／全域流水號。
呼叫端須提供正確作用域及穩定來源，ID函式本身不保證全世界唯一。原personId及舊attemptId保持opaque字串，
不能把新命名規約強套到舊數值資料。02負責生涯／嘗試／事件的真正識別分配與防重送。

事件封套1的必要欄位：

- `schemaVersion,id,definitionId,contentVersion,type,participantIds,stageId,facts,knowledge,results,choice`。
- type只允許direct或cumulative，原事件後續沿用實例／階段，不發明第三種新抽選類型。
- facts是 `{id,subjectIds,occurredAt}` 的客觀**引用**，不儲存完整真相內容。
  knowledge是 `{actorId,factId,claimId,versionId,sourceId,acquiredAt,believed}`；
  客觀發生不會自動給玩家知情，知道不等於相信。取得日期不能早於引用的客觀發生日，
  同日slot先後、真正接觸路徑及說法內容由02／07／08判定，尚未實作。
- results是 `{id,factId,subjectId,facet,effectIds,settlementId}`。一個事實可有多位當事人、
  多facet結果，分別有不同result／effectID；同一fact＋subject＋facet不可重複。
  多結果可以參照同一settlementID，但尚不驗證它與N6收據／commit存在對應，不執行效果。
- 同一封套內事件ID／結果ID／效果ID不可重複；跨事件可重用**一致**的事實引用，不得改寫其發生資料。
- choice可null；非null含nodeId、3～8個 `{id,emotional}` 選項及confirmedOptionId。
  至少一個情緒標記、確認ID須存在；只驗格式，不保證選項語意有意義、不鎖定選擇、不抽取結果。
- 封套內人物引用須存在於numeric人物／玩家；這是現階段適配邊界，未宣稱已支援全校輕量人物或封存資料庫。
  05若擴充人物權威目錄須顯式版本化／適配，不能刪歷史或重造自然人。

玩家知情投影、時段排序／占用、在籍期間重疊判斷、真實三年十屆輪替、未來日期合法性、

### 已實作：時間、亂數、去重及重試基礎

plan保存呼叫端明確提供的positions及cursor；同一天的slot以提供順序為準，跨日必須逐民用日，
年資／開學標籤只允許明確下一學年。所有時間推進只經advance-time，N4每日自然變化仍由原核心執行一次；
同slot多操作不重算每日變化，讀取／還原不推時間。plan.validation目前只接受unverified，
**不宣稱日期、上課、假期、時段或開學日已合法**。04須接正式校曆、驗證標記與可分段提供的時段，
不可將本批合成順序當40年日程，也不宜把40年所有時段每次全量掃描。

N4自然與N6結算亂數保留各自原snapshot；上層sample只使用Foundation.random已有命名串流。
所有抽樣在草稿中進行，成功才連同結果安裝；失敗、discard、重送均不消耗已提交亂數。
沒有Math.random或裝置現在時間播種。固定世界及相同操作可逐筆重現，JSON往返不重播歷史。

commits保存attemptId＋operationId、canonical完整請求、連續revision、history／N6收據ID與抽樣結果：
完全相同請求重送回傳原收據及目前世界，duplicate=true；相同ID不同內容拒絕CONFLICT；
新操作expectedRevision不符拒絕STALE；已失敗且未提交操作可以修正後再試。
事件實例／stage／operation／result／effect各有獨立ID；同一階段的event＋stage＋fact＋subject＋facet
也不得換result ID重算。真正的新事件或新階段可有新成果；呼叫端必須用穩定facet表達同一項邏輯成果，
不能靠隨意改facet繞過去重。這是正式內容驗證器06／07後續必須承接的語意責任。

`forkWorldAttempt(openingSnapshot,{attemptId,seeds:{settlement,streams}})`是明確的重試初始化基礎：
只從指定開學快照保留當時人物／歷史／位置，使用新的attemptId及明確uint32種子重建N6與所有上層串流；
原N4自然snapshot隨開學基線保留。舊N6收據封存在numericArchives，維持已通過年份成果的追溯，
當年失敗世界不會被帶進來。新嘗試可有不同抽樣，不暗中以時間產生種子。
它不是一般恢復入口，不執行學年失敗判斷或挑選快照；年度授權／重試操作流程屬11、快照持久化屬03。

### 96主題及內容契約

未來內容作者以同主題共用三項核心＋每小主題三項附加配置，登錄器驗證一致性。

`validateEventDefinitions(definitions)`驗證每個小主題：

- `coreCodes/additionalCodes/weights/directions`：3＋3個互異的48項字典代碼，六係數非負且和為1，方向為1／-1。
  相同主題在同一目錄及歷史登錄版本中的核心配置必須一致。
- `eligibility`與`repetition`獨立於內容、取值來源／傾向與執行結果；不把敘事、資格與結算塞進單一劇本函式。

### 正式介面與每日順序

所有寫入仍經`prepareWorldOperation`／既有`createStoredSession.execute`，沒有另一個世界提交入口。

| 介面／操作 | 責任 |
|---|---|
| `buildEventCandidates(world,definitions,{engineering:false})` | 純資格查詢，回傳day、candidates、rejected；不增累積、不抽亂數、不寫世界 |
| `weighEventCandidate(world,candidate,definition,binding,index)` | 解析六項合法持有者，保留rawWeight、k、exposureFactor、effectiveWeight供內部驗證 |
| `register-event-catalogue {catalogueId,definitions,bindings,engineering}` | 一次登錄不可覆寫的版本化候選metadata，保存在既有歷史／收據；不載入敘事資源、不抽事件 |
| `draw-events {catalogueId}` | 正式每日入口，引用已登錄目錄，鎖定當日決策及具體事件身分／合法時段；一天只能決定一次，包含0件 |
| `admit-event {eventId}` | 只能在鎖定日期／時段開啟已選事件；建立既有事件封套及初始stage，不再抽選 |
| `event-lifecycle {eventId,status,basisFactId}` | 已開啟事件在active／waiting／ended間合法轉換，需已連結客觀依據；ended不可再推stage／result／choice |
| `event-exposure {eventId,participantIds,basisFactId}` | 實質故事曝光：須為該事件的事實當事人，且事實已向玩家正式揭露；同事件／人僅一次 |
| `readEventContinuations(world)` | 內部後續資格起點：同eventId、目前stageId及狀態；特殊活動占用時段回傳空，後續不占新事件額度 |
| `eventIndex(world)`／`candidateConflict` | 當次世界的事實、H紀錄、曝光、主題／人物、定義與排斥索引及可檢查的排除理由 |

工程測試可明確使用`draw-events {definitions,bindings,engineering:true}`內聯小型合成目錄；
正式每日呼叫必須用catalogueId，不能每天將1,920定義再次寫入收據。
內部函式只在交易草稿操作，呼叫端不得把其變更直接發布為正式世界。

順序為：讀正式世界／校曆 → 檢查人物、客觀條件、H歷史、日期時段、冷卻／互斥 →
解析合法六項來源／零權重排除 → **完整合法候選池成立後才取events亂數串流** →
按日型決定新件數 → 逐件加權、重新排斥已選與不合法時段 → 保存事件保留、候選決策摘要、亂數前後狀態與收據 →
在保留時段正式開啟，交07執行。
`draw-events`不直接生成劇情、客觀事件成果或玩家知情；`admit-event`也不自行創造過往事實。

候選不足自然減少，不硬補；整日零候選／零權重不消耗抽選亂數。
重送同操作回原收據，新操作ID也不能重抽已決定日期。不得直接open正式定義繞過保留；
原synthetic／procedure／activity載體保留供01～05相容，但仍受原校曆渠道與保護約束。
保留時段未開啟前不能finish-slot跳過它；之後沿用原本未確認選項阻止時間推進的屏障。

### 資格、權重與曝光

人物來自第05批`readSchoolCandidates`、正式人物ID、當期學籍、照顧連結及仍有效的職務；
學籍行動資格沿用`enrollmentEligibility`。`student/caregiver/staff/player/reunion/contact`是查詢範圍，不是人格模板。
資格可明列日型／slotIds／日期區間、指定事實及當事人、H代碼最低次數及active／ended狀態、六項以外的必要底層門檻、
角色roleIds、active／former班級學籍、實際知情版本及相信狀態。
歷屆人物須有**當日contact事實包含本人及玩家**才可從reunion範圍入池，不能用舊學籍自動當成今天已接觸。
多人候選可指定companions，其本人與主角必須有當日真實contact依據；使用穩定ID及事實而非姓名去重。
一般其他班／校外NPC可經contact範圍與合法知情來源出場，不預載玩家未知的全校名冊。

`bindings`每定義一筆`{definitionId,sources,valence}`，六項sources指定participant、player-person／life／work／outlook、
classroom、school，或`kind|穩定持有者ID`（例如relationship／family／reputation）。
來源缺值不得補0／50；該候選記錄為來源不足，不強迫該人物具備全部48欄。
不使用12項衍生玩家面板回饋加權，亦不將歷史逐筆加分。

`B=weightedMean(方向轉換後的六項0～100值, 六係數)`；**K固定負面1.6、中性1.0、正面0.7**。
基本抽選權重為B×K；D07低曝光調整另保留獨立的exposureFactor，最終為B×K×exposureFactor。
曝光工程係數為`1+min(1,(當屆最高實質曝光數-本人曝光數)/10)`，只套用合資格當屆學生，範圍1～2，與正負中性無關。
這個係數與件數均勻分布是**可驗證的工程設定，並非使用者另行定案的玩法參數**；後續正式內容平衡仍須驗證。
候選／保留／背景提名本身一律不增加曝光；07須在真正已揭露的實質互動後提交event-exposure，不能為覆蓋率刷次數。
K與曝光都不直接改NPC、嚴重度、結算、玩家難度或保證負面事件發生。

### 日型額度、持續及去重

- 正式學期／寒暑輔上課日0～5；普通週末、國假及補假整日0～1。件數暫採合法範圍均勻抽樣，不是固定最大件數。

- 特殊活動占用slot排除新事件、正式後續與結算；全天活動的0額度亦涵蓋其私人時段，不能補抽。

  正常活動成果仍走原activity／N6渠道，不改其數值與歷史責任。
- 同日key、同主題／同參與者的未結事件、明列cooldownDays、相同定義／相同客觀前因、exclusionGroups分別有排除理由。
  直接與累積同主題同參與者互斥；抽中一筆立即更新後續候選排斥，不先抽完整列表再補救。
