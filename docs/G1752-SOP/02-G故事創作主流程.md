# G1752 專屬 SOP｜02 A～G 故事創作與 AVG 工作流程

> G的唯一操作順序。每篇在創作時就寫**自然AVG對話**，不是先寫長敘事再重新改編。每批24篇，詳[05管理](./05-G種子批次與試產.md)；合法五區塊詳[03範本](./03-G五區塊範本.md)，放行門檻詳[04驗收](./04-G品質與驗收.md)。

## A｜固定種子、資格、摘要與題材初篩
1. 從已建立的 [`data/g1752-fixed-seed-assignments.json`](../../data/g1752-fixed-seed-assignments.json) 固定映射讀取本篇`story_id`／`seed_id`及原四碼；**不得依劇情方便更換種子**。
2. 依四碼規劃能真正成立的導師困境，確認合法持有人、人物在籍／知情／職權、G合法日型及跨期可用性。G非T20專屬活動故事；未經依據不要寫必在某日發生的校曆節點。
3. 填四欄摘要：**事件起因、核心衝突、導師困境、故事獨特性**；對照既有T/G摘要查重。全庫先規劃題材方向，詳細四欄摘要依24篇逐批做；G01～G11採真實多標籤、不硬貼比例。
4. 一批24篇先產出[故事主題與摘要規劃](./07-G故事主題與摘要規劃.md)並初步複核，**不需T的創作時段規劃**；規劃合格才正式寫稿。建簡短教師處置分類索引；異常集中才定向改題，不設定選項類型比率上限。

## B｜候選行動、真隨機六選三、四條後果與數值
1. 先創作**一個自然可信的情緒候選＋六個互不重複的普通候選**（具體可執行，且不同不是只換語氣）。
2. 真正隨機抽六普通中的三個，再加情緒候選真實洗牌至A～D，恰一個`emotional=true`。若抽中的行動重複／不合理，**先修正候選池再重新抽選**，不能AI自行挑方便寫的三個。
3. 對每個A～D記下導師已完成的客觀行動、優缺點、人物自主反應與合理可發生的預期後果，分別固定R1～R4。
4. 依後果從58庫各挑一組合理的教師四狀態（每R總和−2、至少一正一負、最多一0，同篇不同）；再以四碼規劃合法NPC／玩家個人底層非零增減與原因。**數值要支持故事，不能強迫故事支持亂抽數值**。

## C｜直接寫可播放的AVG自然對話
1. 先安排真正的情境、角色知情與說話者；開場呈現困境而不洩漏隱藏結果。
2. 四個固定結局都應有明確客觀後果、人物自主反應、轉折和合理收束；不能每篇都「老師宣導原則後結束」。
3. **人物對話優先，旁白只在必要時用**；禁止角色朗讀第三人稱敘事、重複前一頁所說、用長旁白代替可合理演出的對話。
4. 從同一套AVG內容產生第五區必要正文，保證行動、結果、知情與數值原因一致；不要另外創作第二套衝突的故事。
5. 開場優先接近140字、每R接近130字；沿用既有唯一玩家可見字數計數法，均**非硬性上限／下限**，完整性優先、不湊字、不固定三頁。

## D｜正式AVG素材與資料
- 同一Markdown第4區`### 開場`之前放全篇唯一`avg` JSON；`opening.Pxx`、`results.R1～R4.pages`，每R分頁非空。
- 使用既有合法場景鍵、學生六表情／成人六姿勢、角色進退場與同場最多兩NPC；遠端用phone/chat；一篇一首合法配樂。**T已規範合理，不另創G專屬人物素材規則**。
- 四R各自從開場結束狀態獨立播放，教師第一人稱；人物退場後再次現場發言須有重新進場；通話或旁白提及遠端人物，不表示人物站在當前現場。
- 玩家畫面另洗牌選項時，內部A～D→R1～R4映射不可錯亂。

## E｜每篇一次完整語意驗收＋機械檢查
依[04品質驗收](./04-G品質與驗收.md)逐篇完整審查四選項、四R、四碼、數值、AVG、角色與時間／法律，再執行相關G定向機械檢查；編譯綠燈不能代替自然語意審查。

## F｜每24篇整批查重、局部修正
完成一個24篇目錄後，集中比較既有故事與本批全文、困境、選項、客觀結果與制式結尾，僅深入檢查疑似重複者；統計字數縮水和58庫配置使用頻率；發現錯誤按**實際影響範圍**修正與複驗，不重新審查整批無關故事。

## G｜24篇全通過、授權晉升與交付
在獨立暫存分支完成24篇內容及可用的測試，保留一份精簡總報告與必要機器證據，對應真實Git SHA；**全部通過並獲授權後一次晉升正式V1**。需要公開時依授權匯出、核對index/detail與版本；正式main故事選篇、存檔、結算屬之後獨立工程，未核准不得提前動。
