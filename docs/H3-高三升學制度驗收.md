# H3 高三升學制度與校曆整合

基準：H2 `309a6e7afbbd8e733926ab979411eda933f4286e`。本批不修改 H1 的既有校曆、時段索引、2026 固定開局，也不修改 H2 成績公式、五月學業審查或六月 T4 交易。

## 正式入口與權威來源

- `src/calendar/admissions.js`：`admissionCalendar(cohort, calendarVersion)`；招生程序的凍結遊戲日期與版本，不增加教師時段。四次學測、兩次分科模考直接引用 H1 的節點。
- `src/runtime/transactions.js`：既有 `finish-slot` 完成真實時段、校務及 H2 程序後，呼叫 `nextEntranceOperations`。每個到期程序是一筆既有 `academic` 日誌；不是另一個時間引擎或學生歷史。
- `src/runtime/entrance.js`：確認校曆／學業版本、當日完成證據、在籍名冊、來源事實、學校資格覆核及學生決定。模考必須有上午、下午的原始校務成果和完成紀錄。書審只引用當時已存在的修課、活動、個人事件來源。
- `src/academics/admissions.js`：版本化程序 reducer；資料投影位於 `academicState(world).entrance`。使用既有 personId，不建立第二套人物。學業日誌的輸入、結果與獨立招生亂數一起可重播。
- `src/runtime/academics.js`：`readAdmissions(world, personId?)` 是供事件、筆記本及後續 H4/H5 使用的公開投影。未公布學測／英聽／技能、書審與面試成績會遮蔽；七、八月不存在預擲結果。
- `src/runtime/event-candidates.js`、`story-content.js`、`story.js`：升學條件可供原事件候選讀取；個人應試、二階及第八類甄試日排除該學生的新事件和正式續篇。`entranceCatalogue()` 是可用原登錄／抽選流程執行的 E01-05 輔導代表事件，使用原配額與危機規則。
- `web/notebook-academics.js`：必要的升學進度、已公布結果、模考與待辦呈現；畢業資格仍讀 H2，不因錄取而改寫。

## 政策與日期

招生政策：`tw-senior-admissions-h3-v1`。只適用 H1 高三校曆、academic v2、三年模式的高三原班。來源政策獨立於 H2 的 `senior-spring-403030-v1`。

**2028／2029 的招生日期、抽象校系門檻、容量和模擬級分換算都是凍結遊戲假設，不是政府已公告的 2029 簡章。** 校系用大學甲／乙／丙、科技校院及學群表示，不冒用真實大學錄取名單或歷年錄取率。日常行政節點遇假日、校內考試或特殊活動會在版本內選取後續合法上課日；個人大考日期不取代全班課表。

## 個人差異與程序限制

模考使用現有各科 mastery、學習狀態、參與、出勤、既有成績及招生準備度，加上有界波動。正式學測逐領域計算，與模考分開；公布後同時提供 0–100 表現指標、各科 0–15 模擬級分及尺度標記。這是遊戲換算，不宣稱重現大考中心當年級分分界。英聽另有公布與等級；藝體校系另驗已公布技能成績。模考只調整升學準備，不寫校內成績、學分或畢業資格。

特殊選才使用能力、五學期可用學業、準備及學習狀態；書審使用歷年修課、已發生活動與個人事件的來源參照，不虛構獎項。面試有個別差異，導師輔導只提供有界準備影響，不保證錄取。招生使用日誌投影內的獨立亂數，不能消耗 H2 的學業亂數。

繁星用已結算高一上至高三上的五學期全校學業平均排名、在籍連續性與學生意願，不能只看一次段考。一般班預設第一、二、三、八學群；其他類別須有學校已覆核的群別資格，不因興趣或單次術科表現就變成藝才／體育班。第一至三類共用推薦序，第四至八類分開；每校每群最多二名。保留原學業引擎的輕量全校排名身分，以可重現的校內推薦意願模型保留其他班名額，不生成完整全校 NPC，也不偽造其正式學測或錄取結果。第一至七類有第一／第二輪；第八類須先篩選、另行甄試後才公布錄取。

一般申請最多六志願；四技另有六志願及各抽象學校上限二志願。學生可經本人來源決定同時保留四技備案；預設不強迫雙報。第一階段、書審／面試、公布、志願排序、分配及確認分開。正取／備取／未錄取原始公布值保存於 `publishedStatus`，後續確認、遞補、放棄不改掉原始成績和公布值。所有管道只允許一個有效確認錄取；已確認其他志願不會再次取得有效確認。

繁星第一至七類錄取即限制一般與四技申請，放棄不撤回該限制；第八類篩選通過排除同校醫學志願，第八類錄取後限制申請分配。已確認特殊選才須先於期限內放棄，才可轉往其他合法路線。可依實際未錄取、放棄、意願轉往分科、技職、就業、重考或其他輔導；不預設全班同管道，也沒有硬編錄取率。

學生調整策略／志願序／放棄未確認志願用 `entrance-decision` 事實；放棄確認錄取用 `entrance-withdraw`；學校群別資格用 `entrance-eligibility` 且須 `reviewed: true, scope: 'school'`；準備輔導用 `entrance-guidance`。都走既有事實與學業操作，不能由教師操作直接指定錄取。

## 相容與資料安全

- 舊 academic v1／v2 的日誌和既有粗月份 `admission` 記錄原樣重播，不改公式或重算舊結果。
- 原校曆、30 年模式或 academic v1 不啟用新政策。已有本屆舊升學結果者保留原招生契約，整屆不混套新程序；舊 `admission` API 仍可續用其原政策。
- 相容的 H1／H2 存檔在高三下一個真實日末留下明確 `entrance/init` 版本紀錄。只處理此後真實完成的節點；不補造已錯過的模考、報名或正式成績。尚未高三不增加招生紀錄。
- 部分新程序存檔直接由原日誌續播；已完成 nodeId 不可重算。公開結果是 detached projection，不提供未公布分數。
- 每個招生日誌結果保存本階段個人明細與招生亂數末態，推薦另存校排／競爭依據；重播逐欄比對，不能只憑種子重新解釋已公布結果。
- 逐前綴還原名冊及已知 enrollmentId，避免後來的同日轉入、轉出或跨屆變動污染早先招生輸入。補充 `seniorRosterAt().knownEnrollmentIds` 不改 H2 原有 people／enrollments。
- replay 驗證校曆、政策、人物、完成時段、來源事實、書審來源及結果。來源只可使用當時日誌前綴；相同輔導／資格覆核來源不可重送套用。
- 沿用既有 prepare／CAS／publish，寫入失敗不發布草稿，舊 revision、篡改與重算拒絕；沒有放寬存檔驗證或重建玩家歷史。

## H4／H5 承接

`readAdmissions(world, personId?)` 提供政策、接手日、已完成節點、個人意向、模考、已公布考試、五學期推薦依據、志願各階段、正備取原值、有效確認、放棄、準備及未來待辦。學生轉出不刪歷史；新轉入只從正式接入日起參與。

六月 `subject.officialScore` 與 `subject.distribution` 必須是 `null`；`pending` 可包含 `july-subject-exam`、`august-distribution`。不得拿準備指標冒充正式成績或錄取。

畢業典禮另讀 H2 的 `readAcademicQualification`／`readSeniorAcademicReview`；錄取與高中畢業是兩條資料軸。正常課表、畢業考、六月教師結算和 T4 邊界均不由招生狀態改動。本批沒有畢典後快轉、最終結局介面或 Pages 部署。
