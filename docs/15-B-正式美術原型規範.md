> **自 2026-11-07 起，本文件完整取代所有舊 15-B 紙娃娃、完整六表情 PNG、挖空底圖、跨服裝共用表情及頭部座標固定等製作規則。** 舊規格不再有效，也不作為驗收依據。未來若要改規格，再由使用者決定並直接修訂本文件。
> **適用範圍**：學生角色立繪與六表情素材；其他介面、音樂、劇情、存檔、背景圖的獨立規範不受影響。任何仍在別處出現的舊學生美術描述均以本文件優先。
> **唯一進度表**：[15-B 美術素材命名與製作進度簿](./15-B-美術素材命名與製作進度簿.md)。每次開工前先查 GitHub 的實際圖片和此進度表，不猜測完成數量。

## 1. 核心產出

每位學生 **8 套服裝**，每套只需：
1. **一張完整平靜母圖**：透明背景 RGBA PNG（calm）。
2. **一張六表情圖集**：透明背景 RGBA PNG，含 calm、happy、angry、sad、surprised、embarrassed 的**局部臉部覆蓋貼片**，不是六張全身圖，也不是 AI 一次畫出的六格參考拼版。
3. **一份 JSON 定位資料**：不算圖片，記錄圖集切格及對應母圖的貼回位置與版本。

目標：**40 人 × 8 套 × 2 張 PNG＝640 張正式 PNG**，另有 **320 份 JSON**，可呈現 **1,920 種服裝／表情組合**。中間美術測試圖片可暫存，不必正式上架或永久保留；不再需要保存另五張完整全身表情圖。

| `casual-winter-01` | 冬季便服 A | 各人不同 |
| `casual-winter-02` | 冬季便服 B | 各人不同 |

學生 **40 個外貌固定可辨識**，不同存檔可配上不同姓名、性格及關係；同一存檔的人物身份與外貌須穩定。**同一人即可**：以人物基本特徵（臉部整體輪廓、五官比例與神韻、膚色及合理的體型辨識度）判定一致性。**髮型、綁髮方式（含馬尾）、髮長整理、瀏海變化、髮飾、髮夾（不論銀色或任何顏色）、配件、站姿與手勢皆屬可變裝扮，不是必須複製的固定辨識特徵，也不得單憑它們不同就判定「變成另一個學生」或要求重畫。** 不要求八套頭部座標、髮絲或姿勢完全相同；可依不同服裝與情境自然改變裝扮。仍須避免核心臉型、五官比例與神韻顯著變成別人。**每套服裝各自製作自己的表情圖集與定位 JSON，不跨服裝共用貼片**。日系校園 AVG 美術風格，符合臺灣高中生活感；不要把正常細微差異誤判成「不是同一人」。

**重要判定禁則（2026-11-08 使用者明確更正）**：製作下一套母圖、選圖、比對或驗收時，不能以「原圖有銀色髮夾、新圖沒有」「原圖披髮、新圖綁馬尾」「髮飾或髮型不同」等理由直接退件。先比較真正的人物基本特徵；變更裝扮本身不構成失敗。此前若有把髮夾、馬尾或特定髮型列為硬性限制的口頭判準，全部作廢。

## 2. 唯一命名與目錄

正式成品放 `web/assets/characters/students/student-001/` ～ `student-040/`，每位學生**一個資料夾**，8 套全部平放該資料夾，無須再分 `base/`、`expressions/`、`hair/` 等層。
美術來源的母圖另保留於 `artwork/masters/students/student-001/` ～ `student-040/`。來源與部署用圖的相應母圖內容應保持一致；**遊戲僅讀取 web/assets**。

以冬季制服為例：
- `student-001-base-uniform-winter.png`
- `student-001-face-sheet-uniform-winter.png`
- `student-001-face-sheet-uniform-winter.json`

其餘學生改三位數編號、其餘服裝改上述八種代碼。圖集**固定 3 欄 × 2 列**，第一列 `calm | happy | angry`，第二列 `sad | surprised | embarrassed`。同一張圖集的六格**完全相同尺寸**，但不同套衣服的臉部格大小、座標可不同。**圖集由程式在六格實測合格後打包**，無標題、字樣、格線、背景裝飾；不得把 AI 直接生成的六宮格示意圖當正式貼片。

## 3. JSON v1（每套獨立）

```json
{
  "version": 1,
  "studentId": "student-001",
  "outfit": "uniform-winter",
  "base": "student-001-base-uniform-winter.png",
  "sheet": "student-001-face-sheet-uniform-winter.png",
  "canvas": {"width": 1024, "height": 1536},
  "face": {"x": 405, "y": 205, "width": 223, "height": 184},
  "sheetLayout": {
    "columns": 3, "rows": 2,
    "order": ["calm", "happy", "angry", "sad", "surprised", "embarrassed"]
  },
  "transitionMs": 180,
  "baseSha256": "c924c604731a451ee916f7167d8085c6c066ceb4a220c7ad4f2b75cb73e09fd3"
}
```

**以上數值為 student-001 冬季制服已上傳素材的資料，不是其他服裝通用數值**。製作下一張時須重新量測 `canvas` 與 `face` 整數、計算原圖 SHA-256；不可複製冬季座標或編造 SHA。JSON 來源檔有額外狀態／備註欄位時，應與使用者當前驗收結果同步，不得把較早的測試註記誤當最新結論。`transitionMs=180` 是暫定切換值，動態測試後再決定。

## 4. 每套服裝必跑的完整 SOP

1. **取圖／事前檢查**：只讀該套正式平靜母圖，核對人物、透明背景、畫布大小、Alpha 邊緣、風格與服裝。不要用其他套的表情或其他角色替代。正式使用者核准的母圖不因個別表情問題重畫。
2. **辨識臉部位置**：分析這張母圖的眉、眼、鼻、嘴、臉頰與髮絲遮擋，建立自己的覆蓋範圍和安全遮罩，先確定貼回座標，再進行製圖；不得先亂生圖再猜位置。
3. **從同一張 calm 母圖完整重新製作五表情**：happy、angry、sad、surprised、embarrassed。**不能因過去 student-001 happy v2 已成功，就在 SOP 驗證時跳過 happy。** 過往成果僅供參考美術品質，不取代本次流程。
4. **每張對位融合**：只改必要的眉眼、口形、臉頰與表情膚色；仍保留原人物辨識和合理臉型。可使用局部遮罩與柔和邊緣、必要的覆蓋底色，務必遮掉舊平靜五官，**不得直接硬貼其他圖片的不相容整張臉**；裁切儲存可以是矩形，但不能讓其邊界看起來像生硬補丁。
5. **逐表情覆蓋驗證**：將平靜完整人物圖＋新表情局部貼片實際合成看效果；檢查人物是否變臉、眼嘴是否重影、位置是否正確、背景是否真正透明、眼眉嘴是否自然。可接受玩家正常顯示下不明顯的少量髮絲接縫與像素色差；**不能接受明顯變臉、雙眼／雙嘴、嚴重錯位及破圖**。避免為微瑕反覆生成浪費額度；只有該表情失敗才修該表情。
6. **打包與最終核對**：六種情緒合格後，抽出同尺寸六格，由程式生成**唯一一張** 3×2 Sprite Sheet 及對應 JSON；重新從**正式圖集**切格疊回母圖逐一檢查，不能僅拿生成的六臉參考拼版宣稱通過。
7. **先交付素材、使用者自行上傳，再依明確指令接入既有預覽站（2026-11-08 最新流程）**：六表情與 JSON 完成技術及內部視覺檢查後，**先提供可直接下載的正式命名 Sprite Sheet PNG、定位 JSON，以及對應學生的 GitHub 資料夾網址**；使用者自行在該資料夾上傳，**不提供 ZIP、不新增服裝子資料夾**。使用者通知上傳完成後，先核對 GitHub 實際檔案；**只有使用者另外明確要求「併入／接入預覽網址」時，才修改既有 `/preview/` 的「立繪預覽」並部署**，不可因素材產生或上傳就擅自接線。接入後由使用者透過「學生編號（非座號）→中文八套服裝→六表情按鍵」實際看效果；不另開小型測試頁。修正未通過的表情後，如使用者先前已要求本次預覽修正作業，依同一任務持續修正與部署供確認。驗桌機／手機、切換、透明與快取，並逐步驗證單人／雙人正式演出。先用即時切換避免五官交叉殘影；180ms 尚未驗收，預覽通過不等於正式劇情／動畫接線通過。
8. **入庫與紀錄**：在進度簿分別標記「母圖核准／六表情素材備妥／預覽站實測驗收／正式劇情與動畫接線」。**預覽站透過程式即時修正成功，不等於 GitHub 原始六表情 PNG 已被永久修正**；後續若把校正烘焙回正式圖集，須核對顯示結果一致，並避免同一校正套用兩次。GitHub 上傳或發布成功均不等於視覺驗收，只有使用者實看確認才算。

## 6. 六表情共同陰影防治與母圖一致性驗收（2026-11-07 新增）

**根因**：student-001 冬季六表情貼片共用相同 Alpha，但部分非平靜表情帶入不屬於情緒的深灰色臉頰／下顎光影。這是「表情來源 RGB 與原 calm 母圖光影不一致」，不是 JSON 座標或網頁 CSS 所致。**只修其中一種表情或直接拿另一張臉的輪廓貼回，都不是可重複 SOP。**

今後每一套雙圖強制遵守：

1. **錨定同套 calm 母圖**：六格合成後，不需要變動的肌膚、臉側與下顎光影應維持母圖原像素；唯有眉眼、嘴、臉紅、眼淚、汗珠及有意設計的情緒光影可以改。**先分析表情差異，再製作貼片**；避免直接使用另一張完整人臉的環境陰影。
2. **六格共同驗收**：相同局部幾何、合法貼回區、Alpha 遮罩及相容的膚色；逐格對照 calm 母圖，而不是有問題只修最明顯的 angry。確認 calm 合成與母圖一致，防止整張臉歪移、雙重下顎、雙眼、雙嘴。

4. **區域必須隨人與衣服校準**：即使演算法相同，每套臉部大小、位置、輪廓、臉側角度可不同，不能把 student-001 冬季的固定座標或右臉遮罩直接套用到全部 320 套。新增角色需先確認鼻、眼、嘴、下顎與保護區，並按其膚色建立中性肌膚判別；深色皮膚、不同打光都不能套硬編的 RGB 門檻。
5. **自動檢查＋人工目視**：比較六格修前／修後在中性肌膚的異常暗化、確認 Alpha 完全不變、PNG 尺寸一致、五官保持及貼回座標準確；再用完整人物正常顯示大小看六種表情是否自然。不可只憑消掉深色像素就宣布品質通過。

### 6.1 本次正式採納的根因與兩階段處理原則

- **第一層：共通光影問題**。五種非平靜臉部貼片與 calm 母圖的膚色／臉頰陰影不一致，即使 Alpha 遮罩相同，覆蓋後仍可能出現暗影。以**該套自己的母圖**作為中性膚色與光影基準，對六格執行相同的候選區域判定，檢查並減少不必要暗化；保護五官、原下顎外線、原本表情需要的腮紅或淚痕。
- **第二層：舊五官殘影**。即使陰影變淡，原 calm 母圖的嘴角、眼線仍可能穿過新的表情貼片。這不是繼續調淡陰影就能解決；需要確認新表情的五官保護區、舊五官殘留位置，於**不動新表情、臉型與下顎外輪廓**的前提下，對殘留線條局部遮蓋或以鄰近乾淨膚色補綴。只拿 calm 臉頰直接蓋回去會把舊嘴角也一起帶回，不可當成最終方法。
- **六格共同驗收，單格剩餘問題精修**：先跑同一套共同檢查，若只有某一情緒仍有可辨識殘影，才在該套已量測的五官保護區外做最小範圍修補。此修補是**個別校準資料**，**不是可以複製至全班的固定座標或皮膚色閾值**。不要把 student-001 冬季 angry 的 223×184 局部位置、遮罩或補色位置直接套到別人。
- **品質底線**：髮絲些微接縫、正常顯示下不明顯的細微色差可以接受；**明顯黑色臉頰殘影、嘴角重影、五官錯位或臉型被移動不算通過**。先找根因及共同規則，不為小瑕疵無止盡重生整個人物；必要的殘影仍需修至使用者實看核准。
- **永久化待辦**：現行 `web/face-sheet-normalize.js` 會在預覽顯示時執行通用六格校正，以及**僅適用 student-001 冬季制服**的 `repairAngryWinterCheekPixels`；日後確定正式資產處理方式時，應採素材預處理輸出已校正的 PNG，或確保執行時校正只做一次，避免重複修補。不可憑冬季個案成功就宣稱整套批次工具已適用全部 40 人。
