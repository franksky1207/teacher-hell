### 資料與數學契約

- 每份 record 為一個明確持有者／情境的普通 JSON 物件：合法代碼對應有限 `number`（含真正的0）或 `null`（適用但尚未設定）；沒有該鍵表示不適用。非法代碼、undefined、NaN、Infinity、越界、繼承欄位容器、getter、symbol及隱藏欄位均拒絕，缺值不補0或50。
- 持有者身分、對象、權責、時間與歷史由上層結構管理；N1不猜哪些NPC必須持有哪些欄位。`createRecord`明確指定適用碼；`setValue`可設定尚未設定的適用欄位，`updateValue`只接受已設定值。讀取時驗證整份record，損壞資料不因本次未讀到就被忽略。
- 所有儲存與內部運算使用 IEEE-754 binary64，不逐步取整。`numericValue`嚴格驗證0～100；`clamp`僅供明確要求限界；`applyDelta`先驗證舊值與有限delta，再依上下界差額飽和，避免極大變化相加溢位。多個delta依呼叫順序逐次更新，飽和後順序可能影響結果，核心不自行合併或重複結算。
- 顯示專用 `roundForDisplay`採 `toFixed`後轉數字，允許0～6位；半值依實際binary64值取整，不宣稱十進位精確計算。顯示值不得寫回儲存。小數累積仍有機器誤差，不以強制每步取整掩蓋。
- `normalizeWeights`接受非空稠密陣列的有限非負相對權重，0保留為0；空集合、全0、負值與非法值拋錯。先除最大權重再以Neumaier補償加總，避免原始總和溢位；正權重若正規化下溢成0則明確拒絕。結果和在浮點誤差內為1。
- `weightedMean`計算 `Σ(value × normalizedWeight)`，所有來源值（含零權重者）都須合法，長度須一致。最後僅限制求和舍入誤差。它不自行翻轉方向或判斷語意，呼叫端須明確綁定來源，不得隨意混加不同意義。
- 機率用0～1，`toProbability`只做0～100除100。非法機率拋錯，不默默限界。
- PRNG採Mulberry32、uint32種子（0也合法）、state每次加 `0x6D2B79F5`並做32位混合；狀態週期2^32，非密碼學用途。固定演算法版本與黃金向量，無隱含時間或亂數來源；上層應保存／注入各串流實例與呼叫順序，不隨意重新播種。
- `next`為32位離散均勻網格 `[0,1)`；`integer`為兩端包含的安全整數，區間寬度最多2^32，用拒絕抽樣消除模數偏差。`uniform`為 `[min,max)`，退化區間回傳端點；不支援溢位區間，過窄區間若舍入成上端點則明確拋錯（此情況已消耗一筆亂數）。
- `chance(0/1)`及退化範圍不消耗亂數；其他判定消耗一筆，整數拒絕抽樣可能消耗多筆。`weightedIndex`是一般權重索引抽樣，不含遊戲規則；空／全0權重拒絕，零權重永不入選，尾端求和舍入回到最後正權重。受32位網格與binary64限制，極微小機率的實際抽樣精度有限，不保證每個正權重在有限樣本內出現，也不截除正常極端結果。

### 長期能力公式、底層可行性與精確240

每列依正式02文件的來源順序取值；反向欄位先做 `100-x`，再使用下列正整數相對權重。
所有來源都有非零影響。沒有年資因子、面板輸入或額外補償欄位。

| 能力 | 按正式來源順序的權重（每列合計128） | 主要因素 |
|---|---|---|
| 教學能力 | 120,2,2,2,2 | 溝通熟練 |
| 班級經營 | 1,2,1,1,120,1,2 | 群體影響力 |
| 溝通協調 | 1,120,2,2,1,2 | 同理心 |
| 行政應對 | 120,1,2,2,3 | 執行熟練 |
| 危機處理 | 120,2,2,1,1,2 | 判斷熟練 |
| 情緒調適 | 120,1,2,2,3 | 學習適應 |

公式為 `A_i = Σ(w_ij × oriented(x_j))/128`。以一項主因素120/128及多個補充因素區分專長，
避免來源高度重疊導致所有能力幾乎相同；這是可測試的工程選型，不宣稱心理測量真實性，
也不代表每種0～100且總和240的任意面板向量皆可實現。沒有以角色原型更換權重。
所有底層值均能在後續自由改變，能力本身可依同一公式達0及100；初始化可行切片的端點受共享來源限制。

八個底層因素的聚合權重由上述同一換算表程式推導，不另保存一套係數：
`3-1:125, 3-2:128, 3-3:125, 3-4:129, 1-3:127, 6-1:122, 1-4:8, (100−1-2):4`。
令其他七個已定向因素獨立均勻抽取整數0～100，解
`3-2 = [30720 − Σ(otherColumnWeight × orientedValue)] / 128`。
只有解不在0～100才拒絕本次底層抽樣，不因能力強弱、分布形狀或先前樣本拒絕／補配額。
每次最多256次嘗試，耗盡明確拋錯，沒有無限重試或偷偷改用中庸模板。
`initialFromFactors`可檢查明確底層組合；不接受任意目標面板向量，也不修補不可行資料。

數學保證：`ΣA_i = Σ(columnWeight × orientedValue)/128 = 30720/128 = 240`。
七項為整數，解出的3-2是1/128格點；面板是1/16384格點，相關整數運算遠低於2^53，
乘加及六項總和均可由binary64精確表示。因此測試用實際未取整值 `===240`，不用epsilon、四捨五入或顯示補差。
外部明確初始化因素同樣限1/128格點，驗證八項來源及實際加權約束；運行中的current不受此初始格點限制。
逐列測試確認N1既有正規化對本批所選權重輸出精確的二進有理係數；直接沿用，不另寫正規化或更改N1核心。

獨立整數卷積驗算：七因素的101^7＝107213535210701組等機率提案中，
42549022279028組可行，理想獨立抽樣接受率0.3968624129；256次全拒絕機率約6.12×10^-57。
這是理想均勻模型的計算，不是有限PRNG獨立性證明。實測10,000組使用25,646次提案，最多18次即得到合法解。

### 固定六狀態與聲望來源

來源以 `{playerId,schoolId,person,life,work,outlook,evaluations}`保存：
`person`為個人特質與狀態，`life`為個人感受到的生活／支持，`work`為當前工作需求與可用支援；
這些不是N3整個家庭、班級或學校的客觀生成結果。`outlook`明定玩家→學校，
evaluations每筆明定來源→玩家，兩個方向的不滿5-4互不覆蓋。
所有數值記錄重用N1合法碼、0～100及缺值驗證；缺值仍不自動填0／50。

六狀態也是相同來源表的加權平均，只有抗壓對平均額外使用 `clamp(mean/75×100)`：

| 狀態 | 正式來源順序的權重 | 初始底層如何推導 |
|---|---|---|
| 體力 | 4,4,2,2,2,2（合計16） | 疲勞／工作負荷／家庭負擔0，時間餘裕／生活穩定／人力支援100 →100 |
| 精神 | 2,2,2,4,2,2,2（合計16） | 上述來源加憤怒／焦慮0 →100 |
| 抗壓 | 1,1,1,4,4,4,1（合計16） | 生活穩定／個人感受家庭支持／人力支援100，占12/16，平均至少75，換算100 |
| 聲望 | 4,4,4,2,2（合計16） | 各定向評價先依正式五來源換算，再依來源weight平均，暫用先驗30與50 →40 |

### 隨機分布與家庭有限關聯

令每個U為同一N1串流下的下一筆 `[0,1)` 偽隨機抽樣：

- 憤怒2-1、焦慮2-2、疲勞2-3採 `100×U²`，一般較低但仍容許接近100的狀態。
- 其餘個人原始欄位逐欄獨立抽樣：25%使用 `100×U`，75%使用 `50×(U1+U2)`。
  此為每欄分布混合，沒有個人人格模板，也不保證每班有多少極端、好或壞人物。
- 家庭共同7-x及班級／校園數值使用 `100×U`。班級數值不平均全班人格，不直接由教師決定，也不窄化至50。
- 先生成40位學生各自特質，再以獨立structure串流建立家庭配置。後續學生以18%機率共享已建立家庭，
  否則另建家庭；每家庭1／2／3位照顧者按相對權重3／5／2抽取。這些是本批可調工程參數，不是正式校務人數或家庭好壞配額。
- 每位學生／照顧者先有獨立原始個人值，再一次性套用家庭背景：個人感受7-x為
  `0.75×個人原始值 + 0.25×家庭共同背景`；責任／衝動／同理／原則各為
  `0.875×原始個人值 + 0.125×相關背景`，依序引用7-4／7-2／7-1／7-4。
  其他欄位保留獨立生成值。公式不讀家庭人數、婚姻／照顧形式或角色標籤。

個人感受是有個別差異的狀態，共同背景只保存一次；不把原始抽樣值另存為第二套運行中狀態。
所有凸組合沿用N1 weightedMean，輸出保持0～100，不逐步取整，不為統計結果回頭篩選人物。
這是遊戲初始化模型，不宣稱人口或心理測量的實證分布。N4不得再次呼叫withFamilyContext累加這次初始化效果。

### 定向關係、聲望與延遲建立

初始關係只在已有家庭、同班、導師／照顧者對應班級或呼叫端提供的相識根據下建立。
同班／班級分派是初始期待的根據，不代表已成朋友、已互動或曾發生重大事件。
令R為新的0～100均勻抽樣；S為同家庭的7-1背景，非家庭情境則另抽一筆R：

| 欄位 | 初始加權平均的來源／相對權重 |
|---|---|
| 信任5-1 | R、發起者同理1-3、對方溝通3-1、反向發起者焦慮2-2、S；8／2／2／2／2 |
| 親近5-2 | R、發起者愉悅2-4、S；12／2／2 |
| 尊重5-3 | R、對方判斷3-2、對方溝通3-1；12／2／2 |
| 不滿5-4 | R、發起者憤怒2-1、焦慮2-2；12／2／2 |

A→B與B→A分開抽取，信任與不滿可同時高；陌生並不強制信任0。
開局只建全部有效照顧連結的雙向關係，以及40位學生與導師的雙向關係：`E=2×careLinks+80≤320`。
家長↔教師、學生↔學生及其他相識者可延遲建立。首次抽取即寫入world，再呼叫不抽樣。
一旦存在，新增另一個相識根據不會替換原本結構根據或使關係重抽。

對已初始化的NPC→玩家關係，額外保存8-1／8-2初始期待，分別由
`weightedMean([R,同理1-3],[3,1])`、`weightedMean([R,焦慮2-2],[3,1])`生成；不代表客觀歷史或申訴次數。
`playerEvaluationSources`從這些評價及既存5-x關係產生可追溯的N2相容檢視，不另保存數值副本。
**N3不啟用這些來源、不與bootstrap疊加**，N2初始聲望40及其他初值均保持原樣；
N5接管來源權重／啟用／bootstrap退場時再整合，不能把30／50先驗複製成NPC觀點。

```js
import { createWorld, restoreWorld, ensureNPCs, withAcquaintances,
  ensureRelationships, playerEvaluationSources } from './src/world/world.js';

let world = createWorld({ seed:7, player:career }); // career為N2已確認生涯
world = ensureNPCs(world,[{id:'counselor-identity',roleIds:[4,28]}]);
world = withAcquaintances(world,[{a:'counselor-identity',b:career.current.playerId,
  reference:'caller-supplied-existing-contact'}]);
world = ensureRelationships(world,[['counselor-identity',career.current.playerId]]);
const available = playerEvaluationSources(world); // 檢視來源，不自動改聲望
world = restoreWorld(JSON.stringify(world));       // 只驗證／恢復，沒有抽樣
```

四串流由world seed經N1派生，完整保存每個snapshot。people延遲生成不消耗environment或structure亂數。
恢復不根據seed重建世界；輸入及呼叫順序相同則包含後續延遲初始化都可重現。
API回傳新世界、不修改輸入；世界為普通可驗證資料，日後N4可用N1更新各自底層record後驗證／保存。
單次API需複製及驗證目前世界，因此多筆使用批次介面，避免逐筆整個世界複製造成額外平方成本。
沒有自行實作儲存服務、備份防竄改、生命周期或每日更新。

### 年資、練習與退步

年資只在上層明確提供下一學年實際開學標示時增加，不按天數、6月底或8月1日自動增加。
名目年度成長傾向為 `g(1)=0`、`g(y≥2)=2.4/[1+(y−2)/6]`；第2／5／10／20／30年分別為2.4／1.6／1.029／.6／.424。
第1年沒有額外年資獎勵，但仍可出現一般能力噪聲的成長或退步。

玩家可練習底層為3-1～3-4（c=1）、6-1（c=.6）、1-3（c=.35）；其他人格不加正向年資項。
練習準備程度由更新前3-4推導 `r=.25+.75×(3-4)/100`，不是新增第49項或保存另一套狀態。
啟動機率p=.08，啟動時加入 `g(y)×c×r×(1−x/100)/(365×p)`，再加雙向噪聲。
3-x噪聲半幅.6、6-1為.4、1-3為.25。邊界外的近似年度期望為 `g×c×r×headroom`；
這是名目365日的速率單位，實際365／366日學年仍依上層逐日輸入，不發固定年度獎勵。

準備程度及headroom使成長依既有底層條件而不同；不保證低能力追上高能力，不保證每年增加，也不把所有人推至100。
NPC沒有被自動賦予教師年資或正向成熟傾向。所有改變先作用於底層，再由完全相同的N2公式衍生12面板；
面板不回寫、不另加年資分數、開始後能力總和不再固定240。

玩家普通短期變動在最終提交時乘 `s(y)=.35+.65/√y`，第1年為1、第30年約.4687，長期仍不低於.35。
s是正係數，所以正負變化同樣縮小；連動與自身提案合併後只乘一次，不重複減震。
只用於2-x、4-x、7-x、9-3／9-4及11-x等短期渠道，不縮放長期練習、NPC、關係或評價。
N6可重用stabilizeOrdinaryDelta，但重大直接衝擊不得呼叫它；N4沒有重大事件免疫或危機權重修正。

### 單層快照連動及提交順序

先從更新前世界計算每個持有者／欄位的自主、有界提案Δ0，然後只讀取這批提案做一次連動：

- 玩家疲勞 += .18×個人工作負荷Δ0 − .12×個人時間餘裕Δ0 + .12×個人焦慮Δ0。
- 人物焦慮 += .12×該人物疲勞Δ0；只讀自主提案，不讀上一條已連動結果。
- 有實際班級歸屬的學生，以玩家工作連動係數的25%讀取校園工作提案；照顧者與無關NPC不憑角色標籤推定校園工作接觸。
- 同家庭人物的各個人感受7-x += .25×對應家庭共同背景Δ0，沒有重套N3初始化或覆蓋成家庭值。
- 個人工作／校園時間餘裕 += −.25×自身工作負荷Δ0。

不適用或尚未設定的來源不產生提案，連動直接略過該來源，沒有把其數值當0／50；不建立不存在的目標欄位。
最後合併各欄位變動、對玩家短期渠道乘一次s，再以N1自然反射提交至新世界。沒有遞迴、同輪重算或無限連動。
輸入世界不修改；上層只應原子保存整份回傳封裝。失敗或無法保存時，不應宣稱新狀態已成立。

### 日期、重現及使用方式

```js
import { startEvolution, advanceDay, advanceDays, restoreEvolution } from './src/evolution/time.js';

let state = startEvolution(world, {seed:7,date:'2026-08-28',
  schoolYearId:'school-year-1',openingId:'caller-supplied-opening-1'});
state = advanceDay(state, {date:'2026-08-28',serviceYear:1,
  schoolYearId:'school-year-1',openingId:'caller-supplied-opening-1'});
state = restoreEvolution(JSON.stringify(state)); // 不抽籤、不重建、不再加成長
```

首次更新必須是提供的baseline日期；後續只接受下一個連續民用日期。同日同學年／開學ID重複輸入回傳相同值，
不消耗亂數；倒退、跳日、同日改年資或不一致標示均拒絕。批次advanceDays仍須提供每個日期，不自行跳過假日。
上層如在新的實際開學日同時提供下一serviceYear及新的schoolYearId／openingId，才會進入下學年。
N4不判定該日是否真為開學、不選定固定開學日，也不建立學年重試流程；上層對這項標示負責。

日期採明確UTC Gregorian民用日解析，不讀裝置現在時間或本地時區。
每次成功提交只推進演化根串流一筆，再以日期、持有者ID及欄位經FNV-1a命名派生N1串流；
雜湊只用於定址，不是另一套PRNG。根snapshot及日期足以續算，無每人物／每日無限成長的亂數表。
不受JSON遍歷順序或新增無關NPC影響；32位有限精度與碰撞可能性仍受N1非密碼學PRNG限制。
載入應使用restoreEvolution，不應丟棄clock後重新startEvolution；N3舊世界仍可原樣restoreWorld，再由上層明確指定baseline日期接入。
保存完整開學封裝再重新運算可重現數值，不累加已撤銷嘗試；不代表已實作儲存交易、防竄改或正式重試。
