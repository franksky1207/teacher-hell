# 《教師荒謬地獄》T／G／P事件量產工作區

> **唯一長期量產分支**：`content/events-production-v1`。以正式`main`的故事量產V1規格為唯一依據；這裡只負責放草稿及成品，不自行發明另一套SOP／T20日期／種子／進度帳本。

## 從哪裡開始

1. **寫故事**：先讀 [正式03創作SOP](../../docs/story-production-v1/03-故事創作精簡SOP.md) 與 [04五區塊範本](../../docs/story-production-v1/04-五區塊故事稿範本.md)。
2. **人物與時間**：使用 [01四碼人物資格](../../docs/story-production-v1/01-人物數值與四碼資格.md)、[02事件分類](../../docs/story-production-v1/02-事件分類與時間資格.md)、[T20唯一日期表](../../docs/T1-T6-特定故事20主題與觸發日期.md)。
3. **內容與鎖定**：以 [05品質驗收](../../docs/story-production-v1/05-故事品質與驗收契約.md)、[06唯一帳本管理](../../docs/story-production-v1/06-種子與量產管理.md)操作原本的CLI，不重建帳本或自創腳本。
4. **帳本**：唯一正式T／G帳本在 `data/story-production-ledger.json`；**目前進度以該帳本即時內容為準**，不在此複製可能過時的revision或篇數。P不使用此帳本及種子。

## 資料夾怎麼看

| 路徑 | 用途 |
|---|---|
| [草稿/T](./草稿/T/) | T草稿，尚未核准、可修改 |
| [草稿/G](./草稿/G/) | G構想與草稿；T648鎖滿前不得正式`propose`／`lock` |
| [草稿/P](./草稿/P/) | P類設計構想；P管理格式未定案 |
| [正式成品/T](./正式成品/T/) | T六學期→20主題→28故事池 |
| [正式成品/G](./正式成品/G/) | G以批次分類，不以11個可重疊題材分類 |
| [正式成品/P](./正式成品/P/) | P1～P6六類；先分類，未定案前不正式鎖定 |

**正式的判準是帳本`locked`，不是檔案位於「正式成品」就算已完成。** 草稿在審查通過後移至最終路徑，再使用CLI正式`lock`；路徑和審查JSON的SHA256會被記錄，鎖定後不可任意修改。必須同一Git提交保留稿、審查JSON及更新的唯一帳本。

## 命名規則（簡單易懂）

- T主題／池資料夾同時包含**正式代碼＋中文名稱**，例如 `T1-高一上/T1-3-高一上家長日/活動前`。
- 一篇故事的稿與審查檔以同一個**草稿識別碼**配對，例如 `T-DRAFT-0001.md`、`T-DRAFT-0001.review.json`；`G-DRAFT-0001`同理。正式ID只能由`lock`配號，禁止提前改檔名為故事正式ID。
- G以`第001批`、`第002批`等存放，約100篇為整理參考，**不是強制篇數或合併門檻**。
- P依P1～P6中文名稱，**不套用T/G五區塊、種子或帳本**。
- `work/`受到根目錄`.gitignore`忽略；長期草稿一律放本工作區的`草稿/`，才能正常受到Git管理。

## 量產與合併原則

- **T648完成並鎖定後，才開始正式登記G1752**。T、G共用2,400組固定種子與唯一正式帳本。P為另外的被動事件分類，不計入2,400。
- 一批一批在本長期分支提交，逐篇依03～06審查與鎖定、CLI`audit`確認，不為每批重新寫SOP、分出一堆歷史報告。
- 不因完成固定篇數就自動建立PR或合併`main`；**只有專案負責人明確要求合併時才啟動PR與合併驗收**。
- 不主動讀取舊暫存分支及歷史候選研究；除非使用者明確要求歷史追溯。遊戲引擎、UI、校曆與部署不在本量產分支的日常編輯範圍。
- 現行故事量產專用CI只驗離線工具與既有測試，**不代表新故事的GPT語意審查完成**。正式進度只看唯一帳本。

本工作區已有正式故事；請以唯一帳本的有效`locked`數量確認進度，`revoked`是保留歷史而不占配額的撤銷稿。量產遇到的實際問題及處理結果統一維護於[量產問題與優化紀錄](./量產問題與優化紀錄.md)。
