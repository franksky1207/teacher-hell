# 第15-B批｜學生六表情製作風格、自然度與失敗案例準則（student-001 實作歸納）

> 2026-11-07 實際製作 student-001 的經驗整理；本文件是 [B1～B23 正式美術規範](./15-B-正式美術原型規範.md) 的表情細則，操作步驟以 [單張製圖 SOP](./15-B-單張製圖驗收與交付標準流程.md) 為準，實際檔案狀態以 [美術進度簿](./15-B-美術素材命名與製作進度簿.md) 為準。不得把原型素材、使用者審美接受、圖層驗證、遊戲整合混稱為同一完成階段。
>
> 核心品質順序：**像同一個人 → 表情情緒讀得對 → 自然且好看 → 幾何／透明度／錨點正確 → 實際顯示切換可用**。各關卡都要通過；程式無法自動證明審美合格。

## 1. 統一人物、畫風與素材結構（固定基準）

1. **固定基礎母圖就是 calm（平靜）**：一個學生 ID 的基礎母圖使用正面、放鬆、自然且不含明顯喜怒哀樂的神情。不得另外為同一原型製作重複的 `expression-calm.png`。完整六表情原型以 **1 張基礎母圖＋5 張其他表情候選**完成；若未來改用真正表情分層，仍保持 calm 為預設及缺圖回退。
2. **固定不能亂改的內容**：原母圖臉骨架、五官基本間距與位置、頭部大小、膚色、髮型髮色、髮飾、校徽、短袖制服及領結樣式、身形、姿勢、畫布中心、人物視覺高度、透明留白。原型 `student-001` 為兩枚銀色髮夾、長直深棕髮、白色短袖襯衫、酒紅條紋領結、東字校徽、深色百褶裙；別把它重新畫成紫色緞帶、白色外套、紅色大蝴蝶結。
3. **畫風**：精緻日系校園 AVG，柔和但有辨識度的線條、細膩明暗、比例自然，呈現臺灣私立高中的生活感。表情以日常情緒為主，避免搞笑顏藝、劇烈扭曲、過度淚光、貼圖式符號、文字及漫畫怒氣／驚嘆圖標。
4. **原型畫布**：目前 student-001 使用 1024×1536 RGBA PNG，人物完整裙襬入鏡、雙腳不必出現，四周留有透明區；這是目前已用尺寸，不代表所有未來資產尺寸已封版。所有同一人物表情維持相同畫布與人物錨點，且手機與桌機使用同一套人物圖。
5. **製圖前務必先讀核准母圖的實際像素**：文字敘述／新生成的「同一女孩」不能取代參考母圖。新生成整身圖可當**臉部情緒參考**，不能原封不動當成同一角色的正式表情素材；不引入其背景、制服、髮型、髮夾或符號。
6. 本階段五張表情是**整張人物 PNG 候選**，以原母圖保留基底並局部修改臉部；即使服裝與 Alpha 完全一致，也**不是獨立可換嘴／眼的分層素材**。正式分層、換裝與兩裝置切換需另行驗收。

## 2. 六表情的動漫自然度規格

| 表情 | 眉眼與臉頰 | 嘴型與情緒判讀 | 退件風險 |
|---|---|---|---|
| calm 平靜 | 放鬆、自然視線、沒有明顯眉壓；作為所有定位基準 | 小幅自然閉口微笑或中性嘴型，不顯得僵硬 | 太開心、太冷漠或已明顯帶有其他情緒 |
| happy 開心 | 眉眼柔和、下眼瞼與臉頰自然上提，可閉眼笑但眼型要好看 | 柔和圓弧笑嘴，嘴角**不尖銳**，可自然微露牙／開口但不可誇張 | 只貼笑嘴、左右嘴角尖得像刀、嘴巴拉太大、眼睛沒有笑意 |
| surprised 驚訝 | 眉毛上抬、雙眼比平常睜大，視線集中；臉紅不應成為主訊號 | 略張開、非完美圓孔的自然「啊」嘴，帶口腔形體與輕微嘴角轉折 | 圓洞 O 嘴、眉眼沒變、眼神游移或過度臉紅而像尷尬 |
| angry 生氣 | 眉頭適度內收、眼神較銳利，但**保留漂亮眼型、正常眼距與臉部美感** | 內斂不悅以輕抿嘴、輕微下壓為優先；非必要不張嘴吼叫 | 眉壓太重、雙眼太擠、責罵大開口、怒氣符號；技術合格但不好看 |
| sad 難過 | 眉內側略抬、眼神低落、眼瞼自然下垂、柔和的低張力 | 嘴角小幅下壓、克制失落；不用每次都畫眼淚 | 眼睛滑出臉頰、對齊失敗、下巴雙影、五官錯位、流淚過度 |
| embarrassed 尷尬 | 眼神稍游移、眉眼有困窘感，臉頰可較明顯泛紅 | 小幅猶豫、欲言又止的嘴型；非哭泣、非驚訝 | 和 surprised 混淆；嘴巴太大、羞紅過頭或臉部不自然 |

**情緒分辨檢查**：縮小至遊戲實際顯示大小、不看檔名，只看臉部應能辨識目標情緒；特別檢查 surprised vs embarrassed、sad vs embarrassed、angry vs 嚴肅。若無法辨識，退回調整眉眼及整體神情，而非只改嘴。

## 3. 最有效的製圖方式：以固定原母圖受控「整臉局部編修」

1. **原圖鎖底**：以最新被使用者接受的 `student-XXX-base.png` 為底，先取出基準頭部／眼部／眉部／嘴部的相對位置；記錄重要參考點（左右眼中心、眼距、眉位置、鼻嘴與下巴距離、臉部輪廓、外側髮際線）。
2. **先定情緒，再取得臉部參考**：表情不是換一個圖形。眉、眼、眼瞼、鼻口周圍、臉頰須整體配合；若參考整張生成圖意外更換服裝、髮飾或眼色，僅擷取可用的**情緒形狀參考**，完全不採用其它部位。
3. **先對五官幾何再合成**：對照原母圖雙眼中心與眼角、鼻尖、嘴巴中心與臉部外緣；必要時對左眼／右眼、眉毛、口部個別縮放定位，不得因只整張臉拉伸而讓雙眼超出臉頰。保留原圖頭部外輪廓，不把參考圖新的下巴或輪廓硬貼進去。
4. **局部柔邊遮罩**：只改變眉眼、臉頰、嘴部合理範圍，沿自然陰影／膚色過渡柔邊；避免頭髮、鼻梁或下巴出現多條重影、色塊或突兀膚色。不能限制到只改數十像素嘴巴，但也不能讓整張制服、裙襬或髮型被新圖覆蓋。
5. **品質不夠就改策略，不硬湊**：若反覆合成產生重影、越界或審美下降，應重新取得更適合的臉部素材、調整遮罩／對齊方法，或使用可真正鎖定原圖的編輯方式；不可用「透明度一致」掩蓋難看的臉。
6. **不要誤用單一量化參數**：不同人的臉型不同，原 student-001 的合成框座標、眼距、RGB 差異數或 Alpha 清理門檻只作案例，不得原樣套到 student-002～004。
7. **原母圖品質先穩定**：先讓新學生 calm 造型與臉型獲關鍵核准，再製另外五張；若原母圖本身不適合局部表情替換，提早修正，而不是做完六張再全數報廢。

## 4. student-001 已發生的失敗案例 → 實際防呆

| 發生過的問題 | 根因 | 後續阻擋條件 |
|---|---|---|
| 六宮格、製作排程圖、驗收比較圖取代應製作的人物 | 生圖目標混入流程與多素材資訊 | 生圖時只要求一張獨立角色／單一情緒；**驗收採程式與文字**，絕不讓圖片生成工具畫驗收報告 |
| 同一學生忽然換成白外套、紅大蝴蝶結、紫髮帶、波浪髮 | 直接重畫整張人物並依文字猜外型 | 只能以原母圖作真正底層，生成圖片只可輔助提供新臉表情 |
| happy 僅貼嘴、嘴角過尖、眼睛仍保持平靜 | 只優化局部像素一致 | 規定眼眉／眼瞼／臉頰／嘴角同步自然改變，先看完整神情 |
| surprised 畫成硬 O 嘴、像害羞或尷尬 | 情緒設計不完整且臉紅過重 | 上抬眉、睜大眼、自然張口並降低害羞感；不用漫畫驚嘆符 |
| sad 眼睛超出臉頰、雙眼疊影、下巴重影 | 臉部縮放／平移錯誤，遮罩跨到臉輪廓 | 左右眼獨立對齊，檢查眼角在臉內；遮罩不得重畫下巴外線 |
| angry 眼睛越界；修後雖合規卻醜、擠眼、張嘴怒吼 | 為解幾何問題而過度擠壓眉眼，且誤以怒吼才是生氣 | 以美感優先的內斂怒意、保留眼距與眼型，閉嘴／輕抿優先 |
| 圖像似有透明背景卻有暗光暈 | 透明殘留／背景混入 | 檢查 Alpha、有無低透明光暈及明暗底下的邊緣；僅針對必要像素修復 |
| 上傳同名檔後混淆核准版與舊版 | 沒核對 GitHub 真正 blob | GitHub tree 路徑＋大小＋Git blob SHA；只有實取檔案內容才可宣稱 SHA-256 同一 |
| 生成完圖片就停住，未檢查交付 | 漏了 SOP 尾段 | 一次完成品質檢查、正確檔名、可下載連結、GitHub 目標資料夾、進度記錄；若不合格直接說明，不交付 |
| 開心、驚訝、難過、生氣等已被使用者退件 | 只看技術成功、不看情緒是否自然漂亮 | 退件不得上傳／重用；更正同名檔案、記錄新版與舊版狀態，**使用者最後核准優先於歷史上傳狀態** |

## 5. 四道品質關卡與一次交付

**關卡 A｜人物身份與畫面**：同一學生的固定臉型骨架、髮型、髮飾、制服、校徽、身形、同構圖；無比較圖／水印／背景殘物；臉部與髮飾不能跳位。

**關卡 B｜情緒與美感（不得只靠程式）**：一眼看得懂情緒，日系 AVG 美感自然；嘴角不能尖銳怪異；眉眼嘴不僵硬；不因情緒而失去原本人設；眼睛不得伸出臉部外輪廓，無重複眼皮、眉毛、下巴，沒有合成接縫。「符合尺寸／透明度但不好看」必須退回。

**關卡 C｜技術精準驗證**：確認 1024×1536（或該人物明定基準）、RGBA、Alpha 邊緣、可見包圍盒、中心線、眼嘴關鍵座標和區域差異；與母圖服裝、身形及髮飾區域一致，必要時比對 RGB／Alpha。若僅有 GitHub blob 與大小，不能宣稱本地整套像素檢查已通過。

**關卡 D｜交付與狀態**：檔案先以**最終正確命名**輸出，單張供下載＋開發分支**上傳資料夾直達連結**；使用者說「好了」→程式查 GitHub 路徑、大小、blob SHA→更新進度簿→繼續唯一下一張；**不生成任何圖片驗證圖**。使用者接受的是「美術候選」，不等於正式圖層／手機與桌機遊戲內切換已驗收。

### 新的學生製作建議順序

1. 先做新的 `student-002-base.png`（calm），核准固定容貌／制服／構圖；**不製額外 calm 圖**。
2. 依序製作 happy、surprised、angry、sad、embarrassed 的單張候選，各自通過 A～D；可依實際需要先做最能測試表情幅度的兩張，不因先前 student-001 的修改順序強制所有角色相同排序。
3. 對新原型以不同臉骨架／髮型／必要配件建立辨識差異，不將 student-001 重新換髮色當成 student-002。
4. 在規模擴張前精準驗證至少 **4 種有差異的學生原型，且其中至少 2 名完成六表情**；同時測試真正圖層相容、人物切換、手機／桌機顯示及服裝共用。未通過仍停在 15-B 原型驗收階段。

> **決議與實測分界**：這份準則會減少已知的失敗原因，但不是「下一位學生保證一次成功」的承諾；是否可以真正減少全部素材張數仍取決於圖層相容與遊戲接線實測。
