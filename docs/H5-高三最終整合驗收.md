## 正式流程與資料契約

- `src/runtime/progression.js` 的 `nextProgression(world)`／`planProgression(context)` 是原交易的唯讀操作規劃器，不計分、不改日期、不另建時間引擎。原 `prepareWorldSequence` 使用相同 context。按保存的 `calendarVersion`／模式處理課程、模考、招生、學期及學年切換。
- 畢典沿 H4 `school-action`；班級摘要與最多三位代表敘事由保存的 `graduationSummary` 分頁呈現。畢典後沿 `nextAftercareOperation`／`aftercare-week`。一般高三課程操作停止，其他年級課表由 H4 同一授課資格判定保留；空格不加「教師善後」字樣。
- 到 2029/6/29 最後合法時段完成後，先顯示原未讀學期報告，閱讀以原 `read-semester-review` 保存。預約及到期故事優先處理；原唯一 `settle-school-year` 產生年度成功、T3 封存與 N7 三年結局，同一 CAS 發布。規劃器不直接執行結局；完成後不再提供推進按鈕。
- 原三槽保留完整世界；完成槽顯示保存的評級，再由原筆記本查閱正式結局、分類學籍名單、已公布升學及六月歷史。沒有第四槽或新的三年紀念庫。
- `web/progress-worker.js` 僅包裝既有 IndexedDB／storedSession 與公開讀取投影。推進、故事、報告閱讀、讀檔、槽摘要及筆記本查閱於背景執行，先顯示處理訊息。UI 接收已驗證世界的唯讀副本；opening 仍完整保存在原存檔，沒有傳到每個資料窗，也沒有刪除。筆記本投影核對原槽 token，快取隨 session 更換失效；錯誤可重試，真正重送及故障回復仍由原交易負責。

## 筆記本與結局來源

- `web/notebook-roster.js`：在校時讀正式名冊；完成後讀 T3 `cohort-completion.outcomes` 與保存的 registry／careLinks。人物、家長、學業及事件來源名稱共用此名單，不從清空的在班人數推斷學生消失，也不重建人物。
- 六學期按 `semester(...).start` 排序，學年度依正式春秋學期標示。高三下考試欄仍由 `examSchedule` 提供，權重讀同一政策的 `readAssessmentWeights`（40／30／30），沒有第三考或假零分。
- 學期成績、學分、五月資格、未完成補救及招生資料仍由 H2／H3 原公開讀取提供。未公布分數及確認結果不從隱藏欄位顯示；「已公布結果項目」包含正備取及未錄取，不能叫作全部錄取。
- `web/senior-summary.js` 整理已保存的畢典、少數代表、善後週、T3 個別資格與 H3 公開進度，與原 N7 保存結局一起呈現。不改舊 `career-completion` 格式、評級或文字重播，不將新增的六月頁當作第二次結算。所有資料截止於保存世界自己的日期；七月分科及八月分發維持未知。

## 舊存檔與原核心

H1 校曆、H2 政策、H3 日期、H4 接續及存檔 schema 均不改版。已越過畢典但尚未接續的舊檔，只在 UI 提示當前善後階段，下一筆正式交易仍由 H4 追加 late-adoption；不改歷史或補造典禮。舊六月終點直接選原年度入口，不再補跑一週。原校曆／其他年級／30 年不啟用高三特例。

唯一必要效能上游修正為 `academicTermStatus`：從原 journal 投影複製學期旗標與名冊識別供逐時段條件檢查，避免只查是否關閉卻反覆複製六學期完整成績。`academicState` 的分離副本與還原獨立逐筆驗證不變；有原批次／個別交易世界與收據全等測試及可變別名測試。
