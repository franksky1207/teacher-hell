# 第18-B T03 主控內容初審：全局缺口與局部修稿

> 2026-11-16。這是**全批初審／缺口登記**，不是190+篇故事逐件人工核可單，也不取代 18-B 唯一 SOP。實際保留件數以工作分支來源檔為準，工程驗收以相同 SHA 的 Actions 為準。

## 第一輪量化檢查（僅定位風險）

- 八小主題合計曾有 **198** 件工程隔離初稿、**804個基本選項**（其中包含單篇第二階段的額外選項）；30×8＝240個探索候選。數量可能隨去重與新稿變動，不能冒充已通過審查件數。
- 對選項後果文字做初步篩查：有 **394** 個選項包含「尚未／尚待／準備／仍需／不保證」等未完成語句；這不是自動判為錯誤，但要確認四個行動真的有不同且合理的已實行結果，而不是整批只有待辦。
- **161** 個選項結果提到科任／教務／承辦／家長／同學／組員等其他人物；要分清是學生轉述、導師準備聯絡、已實際聯絡，或真正得到回覆。當正式 `world` 只綁定 teacher／participant 時，不能把第三人自動知情、已同意、關係已改變當作既定世界結果。
- 最初全部稿件多為兩頁單階段四選項、幾乎零數值變化與零加權結果；目前已有少數合理的個別加權變化與兩階段互動修稿，但遠遠不等於整批內容深度已合格。18-B **不要求各稿必有數值或跨日**，只要求採用時語意與世界實際結果一致，且不同故事的玩家體驗有生命與變化。

## 需優先處理的制度資格

1. `T03-05` 的轉入、轉出、休復學、班級異動、正式資料移轉等故事，必須確有相應的合法在籍與歷史／行事曆前提。現行 `eligibility.enrollment` 的 `enrollmentEligibility` 檢查的是指定 **school-enroll 操作能否執行**，並非「此人曾轉入／復學」的歷史鑑別；不可誤用它當已轉學證據。找不到已存在的精準資格則隔離，記錄所需契約。
2. `T03-06` 的長期請假返校，需明確的「曾長期缺課／近期回校」可稽核史實或既存資格；目前不得只用 `people=['student']` 抽給任何一般在籍學生。請假返校不是依法休學後復學，不能混成同一筆學籍操作。
3. 特教合理調整、評量、設備安全及個人資訊只由既有正式法規、校內程序與權責確認；不因故事敘事而自行改動 N1～N8、正式成績或適法評量。

## 故事品質的真正審查問題

- **起因相異**：與T01/T02 390核可事件及本題其他起因比較，確認不只是換名字、時段、服裝、同義敘述、不同情緒配色。
- **每個選項有實際行動**：辨認「查證」「提出／準備」「已聯繫」「收到回覆」「已完成」各自階段；不能把未發生的後續寫成完成。
- **人物知情與世界**：不允許未接觸的科任／家長自動知道；傳聞不是客觀定罪。若現有內容資料不足以表達第三人知情，列出工程缺口或將敘述維持為已確認的當事人意向。
- **玩法深度**：尋找真正因行動和人物數值不同而產生可辨識結果的事件；需要時用合法 `variants`、即時效果、累積問題或後續階段。不要為讓每個故事都有數值而任意發送獎懲。
- **安全與自我倡議**：學生本人同意優先，導師不替學生決定揭露特殊需求或向同學公布私人醫療、家庭、文化與學籍資訊。
- **工程與版本**：新修稿仍為 `engineering-test`，來源JSON與生成JS需一致，`validateStory`／`validateEventDefinitions`／實際CI有效。最初的原始版本不能因新稿數量增加便自動提升ready。

## 本輪處置

- 以**工程隔離、主控初審未結**為整批狀態。已發現的重複題材與非法表情已進行局部修正；對真正有情境依據的個別事件補合法加權結果與數值，並開始同事件第二階段設計。
- 現階段**不批量簽核、不合併main、不部署**。下一步先逐主題審查具體事件文字、世界／知情與資料資格，留下每篇放行或隔離的事件 ID；必要修正集中進行，不因本文件存在就將 `reviewed` 計成198。
- 直到每個小主題有至少20件**實質不同、已經主控內容審查通過且工程可接入**的故事，才可考慮按既有發布契約提出正式放行；外部獨立審稿仍是使用者選用，非門檻。
