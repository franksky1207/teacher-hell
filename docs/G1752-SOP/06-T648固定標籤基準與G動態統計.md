## 四、兩種統計的唯一責任與去重

- 正式核准統計只存於[`data/g1752-tag-statistics.json`](../../data/g1752-tag-statistics.json)：`tBaseline`凍結T648；`gAccepted.acceptedBatches`保存階段三已核准24篇批次及逐篇ID、最終標籤、Markdown Git blob SHA、驗收證據路徑；`gAccepted`與`combined`保存正式累計。
- 全庫規劃預估只存於既有[`data/g1752-story-topic-index.json`](../../data/g1752-story-topic-index.json)的`planningEstimate`；`stories`為唯一題材索引條目，格式與查重流程見[07](./07-G故事主題與摘要規劃.md)。每個故事ID始終只有一筆，階段三G核准時以正式標籤及內容取代原規劃條目，不另新增一筆。
- 全庫預估＝凍結T＋索引內所有已有有效規劃或正式核准的G，每篇只計最新有效版本；正式累計＝凍結T＋階段三正式已核准G。**兩者不得相加**；摘要規劃及**階段一、階段二未完成工作草稿**均不得提前寫入正式帳本。
- 每篇同一標籤只算一次，可有多個實際成立的G01～G11。分母是標籤出現總次數，不是故事篇數。目標與容許區間仍以本文件第二節及正式帳本`targetBands`為準。
- 1,752篇摘要規劃已完成；正式橫向創作（階段一～三）沿用既有規劃，不因正式累計暫時偏低而擅改後續已規劃題材或於階段一／二反覆重算11類標籤；僅因定向回修調整標籤時，處理受影響故事及全庫預估差額。
- 最終正式T＋G全庫才按正式容許區間驗收，不將單批比例當成硬性門檻。

## 五、正常施工一律增量更新

1. 新增或修正規劃故事：依07處理索引及標籤差額。正式橫向創作階段一、二工作草稿不更動正式帳本；僅於定向回修改變摘要或標籤時，依原有效標籤集合與新集合比對差額更新索引與`planningEstimate`。
2. 階段三正式首次核准：24篇均通過04且獲使用者授權晉升V1，核對批次ID、24個固定故事ID、最終標籤、blob SHA及驗收證據；同批次ID或故事ID已入帳即拒絕重複追加。寫入一次`gAccepted.acceptedBatches`，正式G批數加1、篇數加24，只累加本批有效標籤；索引原G條目原位更新為`accepted`，預估統計只計新舊標籤差額，不增加已規劃篇數。
3. 正式已核准故事修稿：只替換原批次該ID的blob SHA、證據路徑及最終標籤；按原／新標籤集合差額更新正式累計及預估累計，兩邊都不增加篇數或批數。標籤未變不重新統計。未核准修稿不得覆蓋既有正式紀錄。
4. 每次以受影響條目的原值與新值計算差額，更新各自11類計數及標籤總次數；僅由11類累計及固定T計算合併總數、百分比。預估`gStoryCount`等欄位見07；正式仍須符合G篇數＝24×核准批數、標籤合計及T＋G合計。不得任意改總數、不得負數、不得重複ID。更新前確認本次所依版本未變動，衝突則重新取得受影響條目後計算，避免重試重複累加。
5. 規劃MD、索引條目與預估累計須同步提交；階段三正式核准時另同步正式帳本及驗收證據。正式發布仍按[04](./04-G品質與驗收.md)同步兩處預覽，不把帳本入帳當成發布完成。

**不做例行全庫重算**：正常新增、修改、核准均只處理新增及受影響條目。不重新讀數百篇故事、不每批從所有明細重新加總標籤，也不重新比對所有舊故事彼此。僅在資料不一致、損毀重建、使用者明確要求全庫稽核、全部規劃完成的最終預估核對或全部正式創作完成的最終正式驗收時，才以程式從既有JSON明細完整重算；疑似來源不一致才讀必要原稿。T凍結資料不因例行重算而變更。

**版本追溯**：核准故事用Markdown Git blob SHA，不記錄包含帳本自身的最終提交SHA。修稿複驗後替換原紀錄，不能把修改當作新故事。
