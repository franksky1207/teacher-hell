### 教師四狀態 V3（唯一正式數值驗收來源）

教師四狀態固定順序為 **精神、熱忱、情緒、掌控**。掌控指對班級現況、事件發展及處理局面的掌握，不等於權威、壓制學生或教師能力；取代體力，不新增第五資源。六能力不變。

**先數值、後故事**：已有事件核心、合法人物及四個行動後，從 A～E **實際隨機抽取四組且不得重複**，分別指定給精神、熱忱、情緒、掌控；將四組的八個值隨機排進 R1～R8，先機械驗證 8×4 的32格，再依固定數值反向創作八個共用R結果（R編號不按好壞排序）。必要時可用 `scripts/story-state-matrix.mjs`。此流程是**創作順序與選組規則**，不改 A～E 既有數字、每欄平均−0.5、每R最多兩個0、NPC增減或四選項權重。

| 組別 | 八個數值（高至低） |
|---|---|
| A | +1、+1、0、0、−1、−1、−2、−2 |
| B | +2、0、−1、−1、−1、−1、−1、−1 |
| C | +1、+1、0、−1、−1、−1、−1、−2 |
| D | +2、+1、0、−1、−1、−1、−2、−2 |
| E | +1、+1、+1、0、−1、−2、−2、−2 |

每欄必須恰符合所選組別的多重集合；總和固定−4、未加權平均固定−0.5。每R四狀態最多兩個0。選組由完整數值唯一辨識，報告 `byState.<狀態>.group`；不另增重複必填欄位。V3取代V2的單R±6、平均±2、每R至多一個0規則；NPC四碼單R±8及4×8矩陣其餘限制不變，NPC八R平均±3已取消，不得改動既有故事機率。

五組完全平等，沒有A優先；**同篇四狀態使用四個不同組別**，不設跨篇指定比例、最少／最多正負列數、整列全正／全負禁令或多輪最佳化。先以程式排除不合法矩陣，避免浪費故事創作；**合法矩陣選定後不回頭重抽、重排**。結局創作完成後只做一次明顯缺乏加扣分線索的審查，必要時**局部修改該R結局一次而保持32格不變**，核對相應四選項連結即可；若仍有實質硬矛盾，標為未通過，不得強行核准，也不為追求文采完美無限迴圈。

新稿第1區必填 `| state_rules_version｜數值規則版本 | 3 |`。新製作預設V3；舊稿需明確使用 `--state-rules-version 1` 或 `2` 做歷史檢查，歷史通過不代表V3通過。歷史驗收請對照原Git版本與審查報告。V1／V2原規則可從Git歷史 f3169d9 查閱。

機械報告提供完整性、各欄組別／零數／正負次數／平均與重複排列供審查，**V3另驗四欄組別互不重複**；不新增跨篇分布配額。內容審查應能從八R敘事指出各四狀態加扣分的明顯原因，尤其**熱忱不可僅憑工作疲累扣分**；不是每項都須另加一段故事。

**結果權重的精確意思**：一個教師選項的八項相對權重逐項加總為該選項自己的分母，將各格除以分母後得到該選項下R1～R8機率；**4／2／1不是固定機率百分比**。同一R不論從哪個可達選項抽到，其結果文字及數值相同；老師選擇當下**已採取的行動事實另行保存**，不能被R取消。

**本批不處理的抽選權重**：舊「負面K1.6／中性K1.0／正面K0.7」已**完全取消**，且尚無新事件「選哪一篇故事」配置；不得重新引入或擅自補成等機率。四碼偏正／偏負是**NPC選角方向**，與K及4×8完全不同。

## 3. GPT實質品質七道審查（全通過才可核准）

### 3.1 `storyAndRoles`：故事與合法角色

- **人物配置前後一致性**：正式創作前讀取該篇規劃與E欄提醒；完稿對照預定與實際常駐／背景槽位，逐人確認獨立行動、在籍、親屬、職權、知情及完整持碼。保留、轉背景、取消或增槽若有變動，將**變動角色及具體原因**記入既有 `characterAudit` 並同步修正規劃；完全一致不需重複造一份差異報告。數值角色取消後，仍須逐碼確認有合法持有人及真正因果，否則本篇不得核准，不得讓無數值背景角色代結算或為湊人數新增角色。
- **多人獨立因果**：每位常駐NPC依本人實際知情、行動與對導師的反應判斷各碼增減；同一導師決定可使不同角色同向、相反或不變，不能無證據複製整套NPC數值，也不要求所有NPC每R都變動。其餘持碼表與數值限額仍依01及本契約，不新增格式欄位。


- 故事必須具有真正的教師抉擇，不能被單純公告／照辦制度取代；T依附核定時段、G不可偽裝T。以臺灣私立高中自然對話、可讀短頁、合理的制度成本與行動取捨為準，不靠悲劇或字數充實。
- **從開場、四選項、八結果反向盤點重要人物**：確認每人的獨立利害、實際行動、知情、在籍／家庭身分、職權與可能的長期關係變化；教師只能決定自身行動，其他人物保有自主反應，已完成客觀事實不可被結果抹去。
- **人物由因果決定，而非固定兩名學生**。當前學生、本班家長／照顧者、任課教師和其他校內常駐人物都須按01資格與故事實質作用判斷是否建數值槽位；不為多樣性硬加成人，也不將真正有獨立數值影響的合格成人習慣性降為背景。單篇角色數量與類型不設比例配額。
- 數值角色須符合01的完整四碼資格；40名開局學生、正式轉入者與76名開局照顧者的實際身分不得假設。無數值情境人物不建立正式ID／持碼／跨篇固定熟人；只作本篇文字身分。審查證據記入既有`characterAudit`，不是另增格式欄位。

### 3.2 `fourCodes`：四碼不是硬湊

- 四碼來源必須完全符合已占用S種子；四碼各自能在**起因／核心衝突／人物反應／八結果**中指出具體作用。
- 常駐NPC若參與四碼數值選角與自身結算，**本人必須合法持有四碼全部**；教師本人只持30個人碼。四碼至少都有合法持有人，不能靠無名路人填缺口。
- 四碼即時值只可依01規格影響**NPC選角**，不乘進R抽選機率；無因果的數值變動必須刪除，不能用非種子碼補差額。

### 3.3 `fourChoices`：四個不同且真能執行的教師行動

- 最終**恰好一個`emotional=true`**，其餘三個為實質不同的普通策略；每項都有玩家可見行動、教師當下已完成的客觀事實、可理解的利益與代價。不得只換語氣、時間、人物或操作順序，也不得把別人的反應當作教師既成事實。
- **情緒選項是受情感影響的真實行動，不是專為犯錯設計的選項**：動機應符合當事人及教師處境，可正向、負向或混合；不等同暴怒、違規、愚蠢、必敗，也不要求它必然有吸引力。審查「此刻為什麼真的可能這樣做」及其取捨，避免刻意設計一個明顯錯項搭配三個陪襯；確有現實可能的明顯失當反應仍可存在。
- 先產生1情緒＋6普通候選，將合格普通候選**實際隨機抽取3個**，再將四個行動**實際隨機排列A～D**，保存第4節`ordinaryChoiceSelection`；正文`emotional`、`finalChoiceMap`與4×8矩陣列須對應一致。保留既有機械映射檢查；選項是否真正不同、情緒動機及實際隨機操作仍由GPT內容審查，不設定情緒類型／位置配額，不因連續相同位置退件。

### 3.4 `eightResults`：八個真正不同的共用R及NPC結算

- 八R須在人物反應、責任、客觀發展或結算上真正不同，不照好壞排序、不寫四套專屬結果；同一R對各可達行動維持同一文字與結算，不取消玩家已完成的事實。
- 每R只結算原四碼的合法相關人物及玩家四狀態。NPC每人每碼**先由明確反應判斷正／負／0，再決定幅度**；單R±8，取消NPC八R平均±3限制。負向關係碼增加不代表好感增加；不得把對學校制度的評價直接當成對導師的關係，也不得為數值平衡憑空寫事件。
- 教師精神／熱忱／情緒／掌控先按V3五組**隨機不重複選四組、排合法32格**，再創作能自然支持方向與幅度的結果。**精神負值可反映心力消耗，不自動代表熱忱下降**；熱忱須具體涉及投入教育的動力。禁止沒有劇情線索的非零值。對照八R與跨篇排列是否無理由重複，**按因果複查，不設數值樣式配額**。
- 完整稿檢查器的`details.npcAudit`包括人物數、實際有變化的人數、四碼正負零統計、全零碼／人物、完全相同排列與單人故事等警示；**警示不是禁止條件**。V3正式驗收須保存`characterAudit`（重要人物反向盤點）、`npcDeltaAudit`（逐人逐碼因果）與`npcWarningReviews`（各警示ID對應`retain`判定及至少40字具體證據）。機械只驗格式、警示ID對應與證據存在，**不保證推論正確**；完成實質複查後才可核准。

### 3.5 `causal32`：故事優先、32格一次性因果判定與重審

**教師四狀態採「數值優先，反向寫R」；4×8結局權重採「故事優先，因果決定數值」。** 兩者是不同的32格，不得混用。完成開場、四項教師已完成行動、八個共用R及客觀後果後，才判定權重；不預設0數量、4／2／1分布，也不依結果好壞或教師四狀態配置權重。

**第一次判定順序（同一篇一次完成）：**

1. **列明既成事實**：逐項列明當下已知、教師A～D已完成的客觀行動、人物自主反應與職權、時間及必要前提；R不得撤銷既成行動，也不可無故替教師執行另一個選項。
2. **先建32格因果表、暫不填權重**：每格判斷**相容／敘事待補／客觀互斥**、**促進／中性／抑制**，並指出具體機制；注意他人或環境可獨立引發結果，不能將「教師沒選這項」等同不可能。
3. **先處理故事缺口**：因果跳接、時間、程序或物品位置不清時，局部補充共用R或相關前提；真正互斥而無合理路徑者才判0。不得編造未寫入原稿的中介事實替已定稿件放行。
4. **再填4／2／1／0**：4須有明確促進機制或特別容易發生的具體情境理由；2表示結果自然可達且影響不明顯；1須有明確抑制或較不尋常但合理的發展；0僅限客觀互斥、無合理路徑。**沒有具體理由不得僅為製造差異將2改成4或1**，2也不得是跳過分析的預設值。
5. **交叉驗收**：橫向逐一檢查四個選項各八R；縱向比較同一R在四行動後的相對可能性。不同選項可有相同權重，**不強制配出不同分布**。逐一核實所有0理由、所有4／1的實質促進或抑制依據、所有2經判定而非複製；再驗每列0≤2、每欄0≤1、各列至少一正權重。各列自行正規化，4／2／1不是固定百分比。

**32格因果紀錄（正式驗收證據）：**

| 欄位 | 內容 |
|---|---|
| `choice` | A／B／C／D |
| `result` | R1～R8 |
| `compatibility` | 相容／敘事待補／客觀互斥 |
| `causalDirection` | 促進／中性／抑制；0另說明互斥 |
| `reason` | 指出該教師行動、人物或環境如何影響此R及**為何給這個權重** |
| `actionPreserved` | 教師既成行動是否保留且未與R矛盾 |
| `weight` | 4／2／1／0 |

正式驗收工具可比對32格齊全、欄位及權重與正文一致。GPT 須真正核對因果，逐格提出具體說明。證據可於正式驗收時以獨立紀錄保存。

**0的排除與退件規則：** 已採取預防措施但他人可能不配合、結果雖低機率仍自然可達、教師未主動促成但他人可自主促成、或只是缺少合理後續過程，均**不得直接判0**。若同一共用R僅依賴特定選項才成立而使同欄超過一個0，先修共用R的事實或必要前提；**不能把真不可能硬填1**，也不能為了湊0把可能結果硬判不可能。無0合法。

**改稿後完整重審：** 只要任一共用R的**故事文字、客觀後果或必要前提**改變，即重新閱讀四選項與全部八R，**完整重判32格相容性、因果方向、具體機制及相對權重**，更新32格紀錄；原值仍合理者可保留，**不得只將原本的0改成1便宣稱通過**。修改教師選項時至少全面重判該選項的八格並檢查相關八欄的相對關係；若修改選項造成共用R變更，仍依本條全32格重審。**重新審查權重不等於重抽、重排教師四狀態。**

**停止條件：** 一次完整32格判定＋一輪橫縱交叉驗收；只有具體因果矛盾、修稿或新證據才局部修正。若修改共用R則依法重審全部32格，**不是重寫全部32個數字，也不是無限制反覆重配**；無法合理修正則標未通過。沒有新增具體理由，不得因「再看一次感覺不同」隨意改判。

### 3.6 `timeAndLaw`：合法播放窗口與當局知情

- T必查T20原表的主題、**活動前／後合法共用池**，不能把稿件 `quota_date`當唯一播放日；前池不能放到後池，反之亦然。重疊主題創作配額共用當天6篇。
- **玩家年級**有正式考試或任何固定校曆活動的日子，整天不得再抽T/G；一般上課日、寒暑輔上課日才考慮T/G。已知／傳聞／未知、成績公布／錄取公告先後、在班／在校、必要時段及職權逐項核對。
- 教師選項不得把學生輔導、性平、校安、霸凌或保護措施寫成無視法定義務亦無後果，也不能因法定程序就新增另一篇正式T/G。**真實法規適用仍須依作品設定當時生效的制度核查**，不得只靠熟悉的敘事套路。

### 3.7 `duplicates`：摘要／全文兩關＋整主題完稿驗證

- **第一關摘要**：比對同批、既有 Markdown、T與G同題材及可用的拒稿參考，檢查起因、核心衝突、教師困境及獨特性；程式相似提示只是候選線索。
- **第二關全文**：比較教師實際行動、人物的獨立作用、八R分歧、時間節點與責任。反查是否重複套用「固定兩個學生提出相反要求→導師協調」或「情緒選項明顯犯錯」等結構；**只有因果真不同才算不同故事**，不是要求每篇人物數量、情緒種類或故事形式平均。公式化則回第2／5／6步改實質內容，不能靠添成人、換姓名、換情緒名稱或字母過關。
- 記錄對照的故事ID、疑似原因、本稿具體差異與退件結果。工具未命中只代表本次檢索未命中，不能宣稱全庫語意排重完成；`duplicates`目前不做遠端向量語意搜尋。
- **整主題第三層總驗證（內含於上述實質查重，非另增機械門檻）**：一個T／G／P大主題完成或使用者說「驗證／驗收」該主題時，GPT須主動合看此主題全部正式稿；即使前後分批創作（如前12篇＋後18篇），仍須在整主題完成後做一次橫向檢查。對 **T／G** 比較**事件的具體成因／教師真正不同的策略／八R是否重用相同衝突與轉折／NPC互動與結算邏輯／32格相容性與促進抑制的依據／常見套版句**；對 **P** 則依自己的故事格式評估跨篇重複，不套用T／G的四選項、八R、種子及矩陣規則尤其注意不同道具包裝同一抉擇、不同標籤包裝同一結果。發現過度套版直接修原稿及相應數值／證據，若改R須重新評估完整32格；合理共通的校園處理原則可保留，**不得強制每篇零重複、刻意增加人物或靠改字詞交差**。在主題自己的 `驗收紀錄/` 記錄查到的相近組合、何以成立不同故事、實際改動篇數與保留理由，不新增大型測試、專用新工具或單篇重複報告。

## 4. 六個普通候選→隨機取三個：獨立審查留痕

正式驗收紀錄保留六個候選、中選三個編號及正文選項映射。使用選用的 `audit --evidence` 檢查時，以 `ordinaryChoiceSelection` 提供這些資料，七個 `reviewEvidence` 欄位及型別維持原契約。第09批已將此結構納入正式證據檢查，保留七個文字欄位（各至少16字元），並驗六候選、三個中選ID、四鍵映射及與正文情緒標記一致。這不證明候選語意不同或真的執行亂數；第12批已用合成證據驗證完整隔離流程及反向案例。核准者須為非空字串，工具檢查其格式。

```json
"ordinaryChoiceSelection": {
  "ordinaryCandidates": [
    {"id": 1, "action": "普通行動候選一，具體可執行且與其他候選不同"},
    {"id": 2, "action": "普通行動候選二，具體可執行且與其他候選不同"},
    {"id": 3, "action": "普通行動候選三，具體可執行且與其他候選不同"},
    {"id": 4, "action": "普通行動候選四，具體可執行且與其他候選不同"},
    {"id": 5, "action": "普通行動候選五，具體可執行且與其他候選不同"},
    {"id": 6, "action": "普通行動候選六，具體可執行且與其他候選不同"}
  ],
  "selectedIds": [1, 3, 5],
  "finalChoiceMap": {"A": "emotional", "B": 3, "C": 1, "D": 5}
}
```

- **結構硬約束（第09批已機械驗收；語意不同仍由GPT審查）**：`ordinaryCandidates`恰6項、ID為1～6各一次、描述非空且語意不同；`selectedIds`恰3個**互不重複**、都來自1～6的ID；`finalChoiceMap`恰有A～D四鍵，其中**只有一鍵值為`"emotional"`**，其餘三鍵為中選的三ID各一次。五區塊正文中四個最終選項與此對應，不應出現第五個選項。
- **隨機抽取要求**：必須有實際隨機挑選三個合格普通候選的動作，不能因喜歡某三項就偽稱隨機；若抽中候選與情緒選項實質重複或違法，先重整候選集合，再執行新的隨機選取，不能偷偷固定三個編號。**此格式保存結果與可供審查的對應，並未承諾可由selectedIds單獨重現亂數過程**。
- **保存位置**：六選三證據保存於正式驗收紀錄，五區塊故事稿只填最終選項，也不建立另外三篇候選故事／R結果。若將來需另附32格詳細審查，引用附件時記錄所審故事ID與Git版本。
- **未定／不可自行升級**：不建立第二AI簽章、跨AI共享分散式鎖、語意分數自動通過門檻；單一GPT即可製作與審查，但必須提出可核對的比對內容。

## 5. 正式退件與修稿規則

## 6. 核准所需的證據清單／不做的事情

- **必備**：同一正式 ID的五區塊完整版Markdown、`summary／choices／full`可重現的機械檢查結果（依所對應階段）、GPT 正式審查的核准結論、審查者及七項具體理由、六候選留痕，另有對應的完整32格**相容性／方向／具體機制／權重**因果核對（可單獨附件並引用；修改任何共用R後須全32格重判）、摘要／全文兩關跨批差異證據。
- 選用 `audit --evidence` 時，將 GPT 的核准結論與審查者分別放在 `verdict="approved"` 與 `reviewer="ChatGPT"`。日常創作、修訂及預覽使用同一份 Markdown。
- **正式核對**：確認故事 ID、所審 Git 版本、摘要與標籤、種子、T 主題、池與配額歸屬日，以及審查證據。依[06](./06-種子與量產管理.md)執行正式檢查。
- **已完成的機械驗收**：第09批核驗恰一個情緒選項、六候選留痕與正文映射。第10批實作T活動前後池及日期資格查詢，第12批完成隔離閉環。全32格因果、法律真實性、候選實質差異、隨機過程與換皮仍由GPT審查。
