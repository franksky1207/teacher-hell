### 教師四狀態 V2（唯一正式數值驗收來源）

教師矩陣是 **8個結果×4項狀態**，與選項權重 **4個選項×8個結果** 不同；後者4／2／1／0及其零上限完全不變。保留教師四狀態整數、單項−6～+6、各狀態八結果等權平均−2～+2；不新增A～D機率加權平均限制。NPC原四碼單項−8～+8、平均−3～+3不變。

- 每個R1～R8最多一項教師狀態為0，違反回報 `state_zero_row`（含R編號）。因此四項全0也不通過。
- 每項狀態跨八結果最多兩個0，違反回報 `state_zero_column`（含狀態名稱）。上述為硬門檻，違反即 `mechanicalPass=false`；32格最多八個0由此自然成立，不另設重複檢查。
- 不得隨機補值、把0一律改成±1，或修改結果描述假裝合格；不合格須回查數值與真實劇情因果。

| 絕對值 | 每個結果、每項狀態的影響程度 |
|---|---|
| 0 | 沒有足夠因果支持變化 |
| 1 | 輕度、短暫影響 |
| 2 | 明確、可察覺影響 |
| 3 | 顯著影響 |
| 4 | 強烈影響 |
| 5 | 非常強烈影響 |
| 6 | 極端影響 |

幅度依每項實際後果決定，不是預先把整篇分成輕微／中等／重大三級。不得強迫每篇使用±5或±6，也不能保守求穩固定使用0、±1。

機械報告 `details.stateDistribution` 提供零值總數、各狀態零數、各結果零數、絕對值0～6分布、各狀態正／負次數與八結果等權平均，以及完全相同排列的結果群組和結果數（計算所有參與重複的R，不是配對數）。格式錯誤的R不計為解析成功；不完整時標示 `complete=false`、平均為null，不據局部資料產生欄零數或平均連帶錯誤。分布只是審查線索，並非配額；全32格±1或排列重複可有獨立警示，不影響通過。不新增至少幾格±3、正負比例或必須±6等限制。

新創作、修訂候選及未來 `full`／`lock` 一律採V2，沒有作者可選的V1繞過參數。既有locked／revoked原稿及審查SHA、歷史驗收紀錄維持原樣；`audit`是歷史完整性稽核，不是用V2重新核准舊稿。新lock在帳本記錄 `stateRulesVersion: 2`，歷史記錄不回填；第二批另行處理原30篇，不因本次升級重鎖或變動計數。

**結果權重的精確意思**：一個教師選項的八項相對權重逐項加總為該選項自己的分母，將各格除以分母後得到該選項下R1～R8機率；**4／2／1不是固定機率百分比**。同一R不論從哪個可達選項抽到，其結果文字及數值相同；老師選擇當下**已採取的行動事實另行保存**，不能被R取消。

**本批不處理的抽選權重**：舊「負面K1.6／中性K1.0／正面K0.7」已**完全取消**，且尚無新事件「選哪一篇故事」配置；不得重新引入或擅自補成等機率。四碼偏正／偏負是**NPC選角方向**，與K及4×8完全不同。

## 3. GPT實質品質七道審查（全通過才可核准）

### 3.1 `storyAndRoles`：故事與合法角色

- 必須確有**不可由單純公告／制度程序取代的教師行動抉擇**；T核心必然依附核定20主題之一，G核心不能偷用專屬T節點。
- 核對教師能決定的只有自身行動，其他學生、家長、同事能依合理自主性反應；已完成通知、申訴、保護措施等不能因結果差就被抹掉。
- 角色只分合法常駐數值槽位、無名無數值文字情境角色。40位學生、正式轉入者、76名開局照顧者等資格依法定班籍及家庭資料。**無數值人物不能冒持碼或在下一篇當固定熟人**。
- 以臺灣私立高中導師日常、可讀短頁、對話自然、可行的責任衝突為品質基本要求；不以長篇或悲劇性增加分數。

### 3.2 `fourCodes`：四碼不是硬湊

- 四碼來源必須完全符合已占用S種子；四碼各自能在**起因／核心衝突／人物反應／八結果**中指出具體作用。
- 常駐NPC若參與四碼數值選角與自身結算，**本人必須合法持有四碼全部**；教師本人只持30個人碼。四碼至少都有合法持有人，不能靠無名路人填缺口。
- 四碼即時值只可依01規格影響**NPC選角**，不乘進R抽選機率；無因果的數值變動必須刪除，不能用非種子碼補差額。

### 3.3 `fourChoices`：四個不同且真能執行的教師行動

- **最終恰好一個情緒行動**，無「情緒必輸」規則；其餘三個為真正不同的處理策略。每項有**玩家可見行動、當下完成的客觀事實、取捨**。
- 不能只改講話時間、語氣、人物姓名、處理順序或換標點來充數；不能把別人的反應寫成老師已決定的結果。
- 先產生一情緒＋六普通候選，依下一節**另存六選三留痕**。玩家正式看到的A～D不固定情緒位置。

### 3.4 `eightResults`：八個真正不同的共用R

- 結果需在後續反應、責任、客觀影響或數值上的發展實質有別；不只是同一結局換語氣。R編號無好壞順位。
- 每R相同文字／結算對各可達選項一致；選項已採取的合法事實不能被否定，若共用R不合理先修改結果或選項。
- 每R只結算原四碼的合法相關人物與玩家直接四狀態，且通過單R及八R等權平均。禁止為追求平衡而憑空寫反向結果。

- 每個結果的四狀態變化均須有具體因果，非零值的方向與幅度須符合實際後果；不能習慣性只填0、±1。
- 不得為零值上限捏造額外負擔或情緒；審查須明確檢查是否無中生有。對照同篇八結果及跨篇數值，檢查單一狀態長期不變、±1集中或排列高度重複等模式，依劇情判斷而非以分布配額核准。

### 3.5 `causal32`：32格逐格有因果證據

對**A～D各8格**逐一審查並在內部表格或審查附件留判定（共32個；不必把32段全文塞入玩家故事）：

| 欄位 | 內容 |
|---|---|
| `choice` | A／B／C／D |
| `result` | R1～R8 |
| `weight` | 4、2、1或0 |
| `reason` | 此行動後該結果為何高／中／低可達，或為何**客觀不可能** |
| `actionPreserved` | 教師已完成的客觀行動是否保留、不與R矛盾 |

**不需要硬填0**；如果0會超過每列2或每欄1，先修R、行動或前提，不得把真不可能的結果硬設1。不要把「沒有選它我不喜歡」、「發生率低」當作0的理由。審查JSON的`causal32`欄至少要有**完整32格已核對的具體摘要與異議處理**；詳細逐格判定可在獨立審查附件存放、明確引用，不可只寫「32格都合理」。

### 3.6 `timeAndLaw`：合法播放窗口與當局知情

- T必查T20原表的主題、**活動前／後合法共用池**，不能把帳本歸屬`date`當唯一播放日；前池不能放到後池，反之亦然。重疊主題創作配額共用當天6篇。
- **玩家年級**有正式考試或任何固定校曆活動的日子，整天不得再抽T/G；一般上課日、寒暑輔上課日才考慮T/G。已知／傳聞／未知、成績公布／錄取公告先後、在班／在校、必要時段及職權逐項核對。
- 教師選項不得把學生輔導、性平、校安、霸凌或保護措施寫成無視法定義務亦無後果，也不能因法定程序就新增另一篇正式T/G。**真實法規適用仍須依作品設定當時生效的制度核查**，不得只靠熟悉的敘事套路。

### 3.7 `duplicates`：兩次跨批實質查重

- **第一關摘要**：四欄摘要初審時，查起因／衝突／導師困境，對既有候選（`proposed`、`reserved`、`locked`）、T及G中的同題材和已拒稿參考庫（若另有保存）做語意比較；程式相似片段排名只當**疑似候選提示**。
- **第二關全文**：四選項及八共用R完成後，按實際教師抉擇、已執行行動、結果分歧、核心人物責任、T與G對應活動窗口再次比對；同題材可以有新因果，但只換人名或配角**不等於新的篇章**。
- 記錄比較的既有故事識別、疑似理由、**本稿實質差異**與是否退件。即使工具回傳0筆，也只能寫「本次檢索未命中」，**不能宣稱所有歷史故事語意重複已自動排除**。工具的`duplicates`目前不會自動從遠端向量語意搜尋。

## 4. 六個普通候選→隨機取三個：獨立審查留痕

**第07批文件格式決議**：保留七個既有`reviewEvidence`**必要欄位與型別不變**，另外於**同一份獨立審查JSON**增列`ordinaryChoiceSelection`物件，讓六候選及中選三編號在同一個SHA256封存的檔案中追溯。第09批已將此結構納入`lock`機械硬門檻，保留七個文字欄位（各至少16字元），並驗六候選、三個中選ID、四鍵映射及與正文情緒標記一致。這不證明候選語意不同或真的執行亂數；第12批已用合成證據驗證完整隔離流程及反向案例。核准者須為非空字串，工具檢查其格式。

```json
"ordinaryChoiceSelection": {
  "ordinaryCandidates": [
    {"id": 1, "action": "普通行動候選一，具體可執行且與其他候選不同"},
    {"id": 2, "action": "普通行動候選二，具體可執行且與其他候選不同"},
    {"id": 3, "action": "普通行動候選三，具體可執行且與其他候選不同"},
    {"id": 4, "action": "普通行動候選四，具體可執行且與其他候選不同"},
    {"id": 5, "action": "普通行動候選五，具體可執行且與其他候選不同"},
    {"id": 6, "action": "普通行動候選六，具體可執行且與其他候選不同"}
  ],
  "selectedIds": [1, 3, 5],
  "finalChoiceMap": {"A": "emotional", "B": 3, "C": 1, "D": 5}
}
```

- **結構硬約束（第09批已機械驗收；語意不同仍由GPT審查）**：`ordinaryCandidates`恰6項、ID為1～6各一次、描述非空且語意不同；`selectedIds`恰3個**互不重複**、都來自1～6的ID；`finalChoiceMap`恰有A～D四鍵，其中**只有一鍵值為`"emotional"`**，其餘三鍵為中選的三ID各一次。五區塊正文中四個最終選項與此對應，不應出現第五個選項。
- **隨機抽取要求**：必須有實際隨機挑選三個合格普通候選的動作，不能因喜歡某三項就偽稱隨機；若抽中候選與情緒選項實質重複或違法，先重整候選集合，再執行新的隨機選取，不能偷偷固定三個編號。**此格式保存結果與可供審查的對應，並未承諾可由selectedIds單獨重現亂數過程**。
- **保存位置**：本物件位於審查JSON，**不出現在04五區塊故事稿**，也不建立另外三篇候選故事／R結果。若將來需另附32格詳細審查，引用附件仍須可追溯且不繞過主JSON的核准與SHA。
- **未定／不可自行升級**：不建立第二AI簽章、跨AI共享分散式鎖、語意分數自動通過門檻；單一GPT即可製作與審查，但必須提出可核對的比對內容。

## 5. 正式退件與修稿規則

| 不合格類型 | 應退回步驟與動作 | 重新驗收範圍 |
|---|---|---|
| T/G分類或窗口錯誤、非法活動日 | 退回03 SOP第1步／第2步，修摘要與情境；不得擅改T20資料 | 摘要、時間知情、若故事已展開則四選項／R／矩陣全部受影響部分 |
| 摘要換皮、沒有教師困境 | 回第2／3步**重新構思核心衝突或教師決策**；若與原候選實質不同，帳本需用`revise`同步或`reject`重新建候選 | 再次摘要查重及後續受影響區塊 |
| 四碼沒有合法持有人／缺因果 | 回第4／5步修種子或角色；必要時`release`、另選未占種子 | 持碼、選角、四選項、R與數值 |
| 四選項重複／情緒數量錯誤／六選三留痕不合 | 回第6步重寫差異或補審查候選；選項若改動，須重核其8條R因果 | `choices`、全部受影響矩陣格及獨立審查JSON |
| 八R不共用／互相同義／數值超限 | 回第7步局部改R與結算；重核各選項到該R的因果 | `full`、八R等權平均、對應矩陣與GPT審查 |
| 32格權重／0理由不合法 | 回第8步先改結果或選項前提，不能靠把0寫1矇混 | 全矩陣及既成事實、必要時重跑`full` |
| 跨批全文換皮 | 回摘要核心重構或退件，不靠換人名／對話 | 兩次語意查重、受影響全部段落 |
| 程式檢查未過、審查不足、帳本revision變動 | 先定位格式／證據／帳本衝突；不得直接無條件重寫整篇 | 相關stage／七證據＋六選三／帳本預覽與SHA核對 |

**禁止自我放水**：不能因已寫很多頁、難找到合法四碼、T主題配額快滿、需要趕2,400篇就允許例外；必要時使用`release`或`reject`，留下可追查原因。所有V1硬上限均**沒有單篇例外**；若小樣確實無法執行，須回報使用者再決議規格V2，不能由GPT自行改。

## 6. 核准所需的證據清單／不做的事情

- **必備**：同一`draft_ref`的五區塊完整版Markdown、`summary／choices／full`可重現的機械檢查結果（依所對應階段）、獨立JSON含`verdict="approved"`、`reviewer="ChatGPT"`及七欄具體理由、六候選留痕，另有對應的完整32格因果核對（可單獨附件並引用）、摘要／全文兩關跨批差異證據。
- **最後對帳**：正式稿、摘要與標籤、種子S、T主題與配額歸屬日、審查JSON、正式帳本revision、SHA256、是否fixture；**只要一處不符就不可lock**。詳細CLI程序依[06管理文件](./06-種子與量產管理.md)。
- **已完成的機械驗收**：第09批核驗恰一個情緒選項、六候選留痕與正文映射。第10批實作T活動前後池及日期資格查詢，第12批完成隔離閉環。全32格因果、法律真實性、候選實質差異、隨機過程與換皮仍由GPT審查。
