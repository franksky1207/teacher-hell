# 《教師荒謬地獄》15-C｜背景圖 SOP

> 2026-11-13 討論定案。本文件為背景圖正式製作、六批 Codex 與美術預覽介面契約。與舊文件的「約 30 張背景」「同一張背景跨直橫式裁切」牴觸時，背景以本文件為準；學生立繪仍維持原共用素材規則。背景正式劇情接線屬 15-D，不在本次執行。

## 一、規模與格式

- **41 個場景版本 × 2 種構圖 = 82 張正式背景**：校內 23、私人 4、一般校外 5、校外教學 3、畢業旅行 6。41 是圖片場景版本數，不是實際場所數。
- 橫式候選 1920×1080（16:9），直式候選 1080×1920（9:16）；第一張核准後鎖定輸出尺寸。背景不透明，不需透明 PNG；優先嘗試 WebP，依首張品質／壓縮結果定稿。
- 畫風與已核准學生立繪一致的精緻日系動漫風格；臺灣私立高中環境、設備、招牌、室內格局合理。原則上不繪固定可辨識人物，不在背景畫出特定學生、劇情真相或遊戲文字。
- **正式圖片只有** `web/assets/backgrounds/desktop/` 與 `web/assets/backgrounds/mobile/`；兩方向同檔名、不同資料夾。不建校內、私人、畢旅等子資料夾，也不建 H01/H02 等正式批次資料夾。
- 命名 `{場所代碼}-{版本}.webp`，例如 `school-classroom-day.webp`；唯一權威機讀清單是 `web/background-scenes.js`。Codex 產圖必須與之逐項對應。
- 季節不做四套版本、天氣不做晴陰雨三套；已有白天／傍晚／夜晚圖依實際月份、時間及照明選用。夜間教室與辦公室應合理開燈。

## 二、結構參考與母圖

1. 製作前建立校園結構參考：校門、中庭、操場、教學大樓、行政大樓、禮堂相對位置，走廊／樓梯、門窗、裝修、照明與設備統一；以及同一住所的客廳和臥室位置、牆面、地板、門窗、家具語言。**這些只是製圖參考，不是遊戲正式背景，也不計入 82 張。**
2. 先製作每個場所橫式基礎母圖；同場所的傍晚、夜晚、特殊裝飾版由母圖衍生。黑板、桌椅、窗框、公告欄、燈具、門的位置不得漂移；聖誕晚會是在**同一禮堂**加夜間節慶裝飾，不是新禮堂。
3. **先全部 41 張橫式核准，再用對應橫式與結構參考製作 41 張直式。** 直式允許重新取景與補出合理上下空間，不能只是暴力裁切，也不能將原場景重設為另一處。
4. 場景重要特徵應在畫面與人物、對話框重疊後仍能辨識；最多兩位 NPC。先用代表性母圖試驗實際橫／直顯示，避免全批完成才返工。
5. 三次校外教學各自獨立白天場景（高一上冬 A、高一下夏 A、高二上冬 B）；高二春季畢旅三天兩夜：首日遊覽車→文創園區→飯店公共空間；次日遊樂園全天→飯店晚會；第三天老街→遊覽車→校門。畢旅服裝夏 B／夏 C／夏 D。校外教學具體景點類型屬美術提案，日後若調整需同步名冊，不擅自當作校曆既定名稱。
6. 午餐與留校晚餐都沿用教室，不做餐廳圖；校內活動善用操場／禮堂／中庭。私人只有同住家的客廳與房間。校外罕見場所無專用圖時使用中性背景加文字，不以不相關場所冒充。

## 五、每批簡化驗收

1. 依清單、場所結構參考及全域畫風製作候選；相同場所先母圖後衍生。
2. Codex **自行檢查並修正到可用**：場景與時段正確、光線合理、同一建築與家具不變、無畸形物件／亂碼／錯誤招牌、符合比例尺寸、人物／對話框不遮蔽必要場景特色。不要像人物製作那樣檢查表情、手指、透明 Alpha。
3. 在同一美術預覽頁測橫直、場景切換及缺圖；必要時檢查單人／雙人遮擋。每批只做**輕量相關測試**，不重跑遊戲三年模擬或全專案重型驗收。
4. 候選、失敗、過程圖在 Git 追蹤以外的暫存區；使用者核准後再一次提交正式圖片，不以 `v2`、`backup` 等平行路徑累積 Git 大型二進位檔。按需下載與適當快取，不一次下載全部 82 張；缺圖顯示提示而非改用錯誤方向。

## 六、美術預覽頁契約

- 沿用首頁「美術素材預覽」，保留既有「學生立繪」「NPC 剪影」，加入「背景圖」分類。
- 背景**五分類 → 場所文字清單 → 該場所有效時段**。桌機左側可捲動清單、右側大型完整預覽；手機上方收合式清單、下方大圖。不要 41 張縮圖九宮格或 82 項長下拉框。
- **任何裝置都能手動切橫式／直式**，同時切換預覽容器比例；正式遊戲電腦只採橫式、手機只採直式，不提供玩家選擇。
- 上一張／下一張逐項瀏覽 41 張（方向獨立切換）；提供大圖檢視。預設純背景；選用單人／雙人與對話框的簡易遮擋測試，不影響遊戲資料。
- 預覽直接依 `web/background-scenes.js` 與正式資源目錄載入，圖檔未生成、檔案錯誤或方向不符時**清楚提示缺圖／尺寸錯誤，不偷用另一種方向**。
- 本批只做預覽，不把背景正式映射到事件。15-D 才依合法 `sceneKey`、當時季節、時段及裝置顯示對應圖片，不能由玩家輸入或事件自由文字任意拼接檔名。

## 七、正式 UI 美術後續待辦（不屬於本次預覽修改）

目前開發預覽的對話框、人物姓名框、選項按鈕、各種視窗、選單與狀態顯示仍以功能測試為主，**不是正式遊戲核准美術**。後續正式介面開發須統整日系 AVG 介面設計系統（配色、字級、間距、框線、互動回饋、手機與電腦閱讀性），以玩家長時間遊玩舒適度為優先；此階段**不要順手重製正式遊戲 UI 或修改事件、數值、存檔**。

## 八、GitHub 與發布界線

預覽應引用正式 `web/assets/` 唯一來源，不新增拷貝素材。現有 `phase13-preview-publish.yml`／`scripts/deploy-preview.sh` 沿用；預覽頁接線完成不代表圖片已經完成。更新本 SOP 與預覽後，部署也只對修改相關項目做輕量確認。


## 九、第15批整體美術定位與 UI 順序（2026-11-14 補充）

本 SOP 只處理 15-C 的背景美術與預覽接線；**第15批整體**仍須完成正式遊戲 UI 美術，而非把介面留到文字劇情大量生成之後。現有 `/preview/` 將逐步由功能測試介面發展為接近正式遊戲的版本，包括首頁與各類文字框、按鈕、視窗的一致視覺設計。

**先後順序鎖定：15-C 41 組／82 張背景圖完成後，再啟動正式 UI 的設計討論和實作。** 目前不要順手修改正式遊戲 UI；第七節「後續待辦」是指 **15-C 之後但仍屬第15批**，不是延至劇情開發完成才處理。具體 UI 規格、批次編號與製作方式暫不定案，屆時再討論。背景圖 SOP 既定六批及預覽接線規則均不變。
