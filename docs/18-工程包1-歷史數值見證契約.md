# 工程包 1：歷史數值見證修正

本文件只記錄 PR #61 的見證儲存及完整性修正，不改寫 18-B SOP，不授權工程包 2～5。

## 三種相容分派

- 故事編譯契約 v1：原有格式、digest、輸入、數值收據與完整性驗證不變。
- 故事編譯契約 v2＋`numericWitness.version=1`：原 PR #61 的完整數值世界快照。維持原讀取及驗證分派；不重寫已確認歷史，不自動遷移。
- 故事編譯契約 v2＋`numericWitness.version=2`：新操作產生精簡見證。舊、新見證可存在同一歷史，包含 retained attempt 的舊紀錄。

兩個版本號各自代表故事契約及讀取證據格式，不以修改故事內容版本號代替相容處理。runtime v1、save v2 外殼不變。

## 精簡格式

`numericWitness.version=2` 保存：

- `attemptId/cursor/eventId/operationId/beforeOrder/contentDigest`：當次編譯上下文。
- `trust: captured-input-v1`：明示不可獨立重建的輸入仍有信任邊界；不是安全簽章。
- `reads[]`：實際條件／變體查詢的定向 `target/code/value`，同欄位去重。
- `fields[]`：編譯器確認結果欄位存在所需的 `target/code`。不把欄位存在誤當成讀取其數值，不額外保存其值。
- `panel`：僅確認選項時保存 N2 真正需要的玩家欄位，以及當時已解析、帶權重與身分的評價來源；其他操作為 null。

翻頁／暫選若沒有讀取數值，`reads/fields` 皆為空，沒有數值世界快照。無 registry、無關人物、完整關係表、隨機流或世界日誌副本。面板仍使用現有 `derivePanel` 公式，沒有新增結算器。

歷史編譯透過這些輸入重播，精簡分支的數值世界設為 null；缺少必要讀取、重複、互相矛盾或未被使用的資料均拒絕。不得改用最終世界補缺。

## 完整性分三層

1. **歷史邊界與上下文**：`beforeOrder` 從已提交的 action、不可變故事內容及第一筆實際後果求出，不從見證自己的邊界或可編輯 operations 清單反推。核對 attempt、cursor、event、operation、內容 digest；既有世界驗證繼續核對 cursor 與日曆、提交、事實與收據所有權。
2. **重編譯一致性**：精確消耗讀取集合；重新判斷資格、變體與結果。與既有 inputs、state、operations、事實及數值收據比較。面板來源使用嚴格的必要欄位集合。
3. **與其他權威來源交叉核對**：必要輸入若與該次 effect 的 before observation 重疊，必須一致；effect 必須對應既有 attempt 的 numeric receipt、提交所有權、日期、序號與變更，且 before／after 符合原數值公式。這一層比「見證與其自己的 inputs 相同」更強，但 observation 本身不是完整的歷史來源證明。

## 可證明的有限來源錨定

只有下列條件全部成立時，才把已保存數值與權威數值終點進一步核對：

- 同一 attempt、同一自然日，且有交易語意能證明當時已完成該日自然更新；不採信見證自行聲稱的自然更新狀態。
- 到數值終點之間只有已逐一理解的日誌類型，沒有未知數值或結構寫入。
- 逐筆核對既有收據及 observation 鏈；飽和截斷導致不可逆時停止來源證明。
- 關係可能在後續 contact 才建立時，不據其終點證明過去已存在。

最終數值只用作**驗證已存見證**的有限來源錨點，不作編譯判斷的輸入，不在驗證失敗時補寫或替換見證。可核對時有矛盾即拒絕，沒有可信來源時不宣稱已證明。

`auditStoryNumericWitness` 回傳 `endpointChecks/observationChecks/capturedOnly`，供區分來源錨定、其他紀錄的一致性，以及仍只能信任擷取過程的數值；這是即時計算的診斷，不另存第二套數值權威。結構欄位、來源選擇與權重的完整重建也受下列限制，這些計數不是全來源認證。

## 信任邊界與尚未達成的證明

目前沒有每欄位的自然更新前值／後值完整日誌，也沒有可獨立復原所有人物／關係／評價來源變化的歷史。因此：

- 跨日自然演化、未知寫入、截斷、另一 attempt 的 retained 歷史，以及來源不足的結構資訊，仍依賴原子交易在當時合法世界擷取的輸入。
- 舊完整快照格式保留原信任邊界；載入時不把舊格式冒稱為新來源證明，也不強迫舊檔補造資料。
- 初次擷取值／結構與所有相關存檔權威資料被協同修改，無法只靠未簽章的本機日誌全面偵測。格式標記、digest、內部一致性均不能代替可信來源證明。
- 本次沒有新增可獨立修改的權威數值、重新計算舊數值收據或重寫歷史。若結案標準要求全部歷史輸入都能由獨立來源重建，工程包 1 **仍不能宣稱達標**；須先決定是否接受上述明確信任邊界，或另行設計更完整的來源紀錄。
