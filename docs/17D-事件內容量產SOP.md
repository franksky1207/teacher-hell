# 第17-D｜《教師荒謬地獄》正式小事件製作與驗收SOP

> 狀態：2026-11-14，第17-D起草並以少數正式可執行案例驗證。本文件是**內容製作契約**；實際事件額度、存檔、N1～N8、K與人物資格，均以既有權威程式及docs/02、03、05為準。**不代表2,560個小事件已完成**。

## 一、產量與抽選的不同層次

- **16類×8主題＝128個主題**，每主題先以**20個起因／情境或因果實質不同的小事件**為最低製作基準（約2,560個）；不限上限、不能用換姓名、換同義句、換背景灌數。以`Txx-yy`為主題，個別可玩事件須各自有**唯一且穩定**的`definitionId/resourceId/version`，不能讓同一ID在新版本暗中變成另一個事件。
- **小事件不是固定長篇小說**：一個子事件可以含分支、多階段、四選項、合資格替換、同選項多結果和跨日後續；只有真的不同的原因／可處理責任／情境／人物資訊／因果，才算不同子事件。累積事件數不是玩家一局必定看到的數量。
- 建立「主題登記簿」記錄：主題碼／精確名稱、子事件ID、起因、人物角色、客觀事實來源、情緒基調、事件型態(direct/cumulative)、日型與時段、資格與互斥、可能後續、內容版號、已驗證狀態。初期可採一份人工可檢閱的表格，後續再按內容量拆檔；**優先按相依性和業務領域分模組**，不需128個主題就建立128個程式檔。

## 二、每個小事件的撰寫順序（不能反過來硬湊選項）

1. **先定客觀起因**：例如「學生主動交出拖延的讀書規劃」、「同學為班級活動找不到負責人」、「學生分享自己完成的作品」。寫清楚**已知、未知、傳聞**，誰在何時從何處知道什麼；禁止用作者視角判定尚未查證的動機或心理。
2. **定主題和玩家職責**：導師可以問、提醒、協調、轉介、做合法紀錄，不能保證行政裁定／升學錄取／學生服從／其他家長決定。平靜日常、溫馨成就與一般意見不合都可以是事件，不以負面危機為預設。
3. **定合資格人物與合法時段**：用學生目前學籍與年級、家長／科任可接觸資訊、歷史、關係、行事曆、保護時段決定是否進池；三年40位原班學生有公平的實質出場**機會**，不能輪流強塞、讓已離班學生在校內憑空出現、替沒知情的人預先揭露秘密。
4. **寫可見場景與逐頁短文字**：實體位置必須是`src/runtime/story-scenes.js`的合法鍵，符合日型、時間、行程；電話／訊息用其原有呈現模式。場上同時0、1或2位NPC；六表情只在角色有可觀察反應時自然更換，不能固定每事件輪播六張；不創造第三人在畫面上同時站立。
5. **四個真實有差別的導師選項**：四個基本選項都隨時合法且可選。至少一個含蓄、自然的情緒語氣（可關心、欣慰、疲憊、無奈、幽默，不預設惡劣），其餘也需合理；情緒不固定第四格，畫面隨機排列且保存。若資格使導師可做更有針對性的處理，只能以`replacement.requires`**取代其中一格**，保留四格、基本方案能回退、同格情緒分類一致。選項不得只有措辭不同而效果等價。
6. **逐一寫「可成立的後果」**：每項選擇的`outcome.fact`是**確認後真正成立的客觀事實**；`claims`是來源人物的主張／看法，不能變成大家都知道的事；`changes`只依既有合法數值欄位；`historyCodes`只有確實成立的分類；`next`寫合理待續時間，不能在結案後無故倒敘。至少在代表小樣示範`variants`及其**正數權重**，讓同一教師選擇可能有多種不同、合理的結果。不是每個選項都必須複雜多結果。
7. **對連鎖負責**：若要跨日／跨週，明示第1段結果留下哪項未完成的客觀事情及誰會在下一段重新接觸；每段的後續不冒充新的每日事件，不額外佔正式新事件名額，不強迫每次導師成功都招來報復。成功、未解、暫緩、意外協助都可能平靜結案。
8. **裝入既有引擎**：先`validateStory`（真正四選項、圖論、表情、物理位置、合法效果及可達性），再建立對應`validateEventDefinitions`的六數值（同主題3個核心一致＋3個附加）、權重及來源、`eligibility/repetition`，用既有`register-event-catalogue`→`draw-events`→`admit-event`→`story`交易，不能在UI建立平行事件結算器，也不能偷跳正式日型額度。
9. **校對實際文字**：全部採臺灣高中語境，與108課綱、私校校務、導師／輔導／教務／學務分工一致。校園霸凌、性平、身心危機等高風險主題的責任與程序必須另做專項內容審查，不能把未查證指控寫成客觀定罪，也不能把敏感題材只用「加重懲罰」處理。

## 三、複製前的最小驗收表

- [ ] `topicId`真的出自T01-01～T16-08，內容與該主題有實質關聯；沒有讓舊E碼同號變義。
- [ ] 新的`definitionId/resourceId/version`唯一、可定位、完成`validateStoryReference`；內容狀態`ready`才正式可抽，`unwritten`不灌可玩數。
- [ ] 有已知的事件起因、敘事時段、原始接觸／知情來源；主張和確定事實不混淆。
- [ ] 所有有選項的階段固定四格，≥1自然情緒選項；條件替換不改四格，沒有靠固定位置給提示。
- [ ] 不同選項、後果、合理加權與跨日因果至少在當批代表案例有精準測試；重整／重複提交不會重抽，操作與結果只交既有交易。
- [ ] 角色有名字及合法身分，起始40位學生的曝光只由**真實確認的實質互動**計次；沒內容就回報沒內容，不搶出現機率。
- [ ] 場景對應既有背景素材，表情有情緒線索；校外教學／畢旅必須和行事曆資格相符。
- [ ] 過程無強制補滿每日事件、不改K 1.6／1／0.7、不改N1～N8或待定難度係數。
- [ ] 精準跑**本批新小事件及其核心相容測試**，不做完整三年／30年反覆模擬；錯誤只修正本批及真正相關的問題。

## 四、編輯品質的五個「非換皮」判準

各子事件至少需要**不同的客觀成因、教師處理責任、可取得資訊、人物關係／衝突結構、或合理後續因果**之一，並解釋其差異；如果僅更換人物名、日期、立繪、背景、表面正負情緒，而四項策略與事實結果完全等價，**不可額外計數**。同一個小事件內以不同人參與時，選項後果可因其既有性格與信任差異而變化；這是內容深度，非新的子事件數。

## 五、17-D代表素材與下一批交接

- 本批先建立少量、且**真正由正式引擎解析的**可玩小樣：T01-01（學習拖延但不預先定罪）、T10-04（學生作品與同儕正向協作）、T14-01（臨時行政交辦與工作界線）。這三件示範負／中／正以外更細緻的基調，**不代表全主題覆蓋或三個等量類別配額**。
- 第18～20批沿用此契約編寫所有128主題，每主題≥20個不同的事件；第21批才觀察三難度六學期存活率、40人曝光、重複率、因果與內容品質。不拿本批3個樣本的結果推估正式通關率。
