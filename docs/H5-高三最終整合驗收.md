# H5 高三制度最終整合與六月結局

基準：`bb1a598a6245c28336d10fdb51f470521f316504`。僅在 `integrate/phase3-web-20261105` 開發；不合併 main、不部署、不開始下一階段。本文測試結果於驗收完成後填入；未完成前不代表整體結案。

## 正式流程與資料契約

- `src/runtime/progression.js` 的 `nextProgression(world)`／`planProgression(context)` 是原交易的唯讀操作規劃器，不計分、不改日期、不另建時間引擎。原 `prepareWorldSequence` 使用相同 context。按保存的 `calendarVersion`／模式處理課程、模考、招生、學期及學年切換。
- 畢典沿 H4 `school-action`；班級摘要與最多三位代表敘事由保存的 `graduationSummary` 分頁呈現。畢典後沿 `nextAftercareOperation`／`aftercare-week`。一般高三課程操作停止，其他年級課表由 H4 同一授課資格判定保留；空格不加「教師善後」字樣。
- 到 2029/6/29 最後合法時段完成後，先顯示原未讀學期報告，閱讀以原 `read-semester-review` 保存。主畫面保留「閱讀學期報告」入口，可重開同一份強制閱讀視窗，不讓視窗遺失或疊窗導致無法繼續；未確認仍不可推進。預約及到期故事優先處理；原唯一 `settle-school-year` 產生年度成功、T3 封存與 N7 三年結局，同一 CAS 發布。規劃器不直接執行結局；完成後不再提供推進按鈕。
- 原三槽保留完整世界；完成槽顯示保存的評級，再由原筆記本查閱正式結局、分類學籍名單、已公布升學及六月歷史。沒有第四槽或新的三年紀念庫。
- `web/progress-worker.js` 僅包裝既有 IndexedDB／storedSession 與公開讀取投影。建立／覆蓋、匯出匯入、刪除、推進、故事、報告閱讀、讀檔、槽摘要及筆記本查閱於背景執行，先顯示處理訊息。UI 接收已驗證世界的唯讀副本；opening 仍完整保存在原存檔，沒有傳到每個資料窗，也沒有刪除。筆記本投影核對原槽 token，操作時停用舊控制項；原 `storedSession.execute` 的可選 `expectedToken` 同時核對顯示時的 token，拒絕另一分頁同 revision 匯入後的舊畫面寫入，已提交的相同請求仍由原交易核對內容並去重。離開頁面釋放顯示快取，快取隨 session 更換失效；錯誤可重試，真正重送及故障回復仍由原交易負責。

## 筆記本與結局來源

- `web/notebook-roster.js`：在校時讀正式名冊；完成後讀 T3 `cohort-completion.outcomes` 與保存的 registry／careLinks。人物、家長、學業及事件來源名稱共用此名單，不從清空的在班人數推斷學生消失，也不重建人物。
- 模考與考試標籤直接讀當前正式校曆時段；上午／下午、第一次段考與畢業考均不附未公布分數。六學期按 `semester(...).start` 排序，學年度依正式春秋學期標示。高三下考試欄仍由 `examSchedule` 提供，權重讀同一政策的 `readAssessmentWeights`（40／30／30），沒有第三考或假零分。舊 H1 尚未接續 H2 的存檔明示政策待接續，不假填權重；原粗略升學階段可讀但不推定新制錄取；缺少升學明細不顯示假的零人確認。五月已審查但尚未完成的資格仍顯示實際未完成原因。
- 學期成績、學分、五月資格、未完成補救及招生資料仍由 H2／H3 原公開讀取提供。未公布分數及確認結果不從隱藏欄位顯示；「已公布結果項目」包含正備取及未錄取，不能叫作全部錄取。
- `web/senior-summary.js` 整理已保存的畢典、少數代表、善後週、T3 個別資格與 H3 公開進度，與原 N7 保存結局一起呈現。不改舊 `career-completion` 格式、評級或文字重播，不將新增的六月頁當作第二次結算。所有資料截止於保存世界自己的日期；七月分科及八月分發維持未知。

## 舊存檔與原核心

H1 校曆、H2 政策、H3 日期、H4 接續及存檔 schema 均不改版。操作規劃器在舊六月檔入場前先走 H4 接續，讓原課堂預約依既有 retirement 契約停用；不先嘗試入場已應停用的預約。已越過畢典但尚未接續的舊檔，只在 UI 提示當前善後階段，下一筆正式交易仍由 H4 追加 late-adoption；不改歷史或補造典禮。舊六月終點直接選原年度入口，不再補跑一週。原校曆／其他年級／30 年不啟用高三特例。

必要的上游修正均不改既定制度：

- `isCampOpeningPosition` 讓課表準備、未來一學期驗證、學籍升年及其歷史審查依保存校曆的正式第一時段判定。完整流程發現高三暑輔首日 2028/7/24 是模考上午；舊寫死 early 的入口會卡住。日期、游標與 H1 模考沒有改動，非第一時段仍拒絕。
- 學業補救在分組／學習階段按實際課程與申請建立暫時索引，保留去重後第一匹配、原人物／課程順序、15人門檻、各種法定時數與 RNG。`h5-support-pre-index.json.gz` 的8組完整學業狀態／結果／亂數見證由 H4 原 API 產生，索引版全部逐欄／SHA相等；真實群體沒有硬造專班，另由原A1十五申請人測試覆核專班及每日兩節。這是數值相容向量，不能代替完整三年證據。
- 世界還原檢查按原有暫時索引方式增加事件／事實查找，仍逐行校驗所有來源；同步校驗結束及異常時立即釋放索引，後續可變物件讀取仍即時查找。沒有永久快取或略過驗證。
- 故事歷史驗證只為當筆編譯複製可改動的事件、數值世界、游標與歷史容器；大型不可改寫 journal 仍逐筆核對，避免每個故事動作複製整份三年紀錄。凍結原資料的完整分支及竄改拒絕測試確保成功／失敗均不修改來源；不是跳過重播或略過來源驗證。
- 學期報告事件摘要在單次查詢建立事件、按事件排列的事實及已公開資訊索引；保留原事實順序、玩家可見性、學期邊界、分數、前十同分規則。原5項報告回歸及真實保存報告的嚴格重播保持不變。
- 年度授課證據把同一個事件／結果的重複成員查找改為查詢內索引；不改授課分母、實際完成數或年度公式。原12項年度回歸保持通過。招生仍由原 `nextEntranceOperations` 在當日最後合法時段執行；呼叫前先核對同一日末邊界，避免每節課複製完整六學期投影。
- `academicTermStatus`：從原 journal 投影複製學期旗標與名冊識別供逐時段條件檢查，避免只查是否關閉卻反覆複製六學期完整成績。`academicState` 的分離副本與還原獨立逐筆驗證不變；有原批次／個別交易世界與收據全等測試及可變別名測試。
