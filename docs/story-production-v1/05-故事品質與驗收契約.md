# 《教師荒謬地獄》｜故事品質、AVG 接線與驗收契約

> 本文件只定義**什麼叫合格、如何證明、失敗如何退回**；不再複述製作步驟。唯一操作順序見 [03 一條式主流程](./03-故事創作精簡SOP.md)，原稿固定欄位見 [04 五區塊格式](./04-五區塊故事稿範本.md)，人物及時間硬規則分別見 [01](./01-人物數值與四碼資格.md)、[02](./02-事件分類與時間資格.md)。機械測試與 GPT 內容審查是**兩種不同的證據**，不能互相冒充。

## 一、完成狀態是逐關卡判定，不是單一「已完成」

| 狀態 | 合格時必須已有的證據 | 未完成時禁止宣稱 |
|---|---|---|
| **S1 原稿完稿** | 五區塊＋合法角色、四碼、四個選項、八 R、矩陣及對應語意 | 內容／AVG 已通過 |
| **S2 原稿核准** | 七項實質審查、合法數值、32 格因果、必要查重與實際執行的相關 CLI 證據 | AVG 已接線或已發布 |
| **S3 AVG 編排完成** | P 開場與八 R 有合法演出分頁、場景、人物、表情、特殊介面與配樂 | 內容及資料驗證已通過 |
| **S4 內容與技術驗證** | 逐 R 對照原始事實與知情、全部頁面編譯、必要人物進退場及定向測試 | 已發布最新版 |
| **S5 發布版本已確認** | 故事索引及單篇 JSON 來源提交一致、P／R 匯出資料可讀 | 正式遊戲主引擎已接入 |
| **S6 正式遊戲整合** | 另經核准的主分支接線、真實玩家世界事件抽選／存檔／結算測試 | 當前工作分支單憑 AVG 就算 S6 |

**交付門檻**：一批故事 AVG 製作完成須符合 S1～S5 的相應內容與資料驗收；正式遊戲接線另行核准後才進入 S6，不得提前觸動 main。每篇以 ID、Git SHA 與實際驗收證據記錄，修稿後不得冒用舊證據。

## 二、原始故事：不得破壞的機械硬規則

| 關卡 | 必須成立 |
|---|---|
| 五區塊及類型 | 04 的五個 `## 1｜`～`## 5｜`、必填欄位、四欄摘要；T/G/P/H4 依02各走本身制度，T/G 正式種子不可被 P 借用 |
| 唯一故事 ID | 同一 Markdown、檔名、`story_id` 一致；正式 ID、已占用種子與配額不任意洗牌；一局同 ID 只出現一次（正式引擎待另接線驗收） |
| 人物與四碼 | 只用 2400 組既有 S 種子的原四碼；每碼有合法持有人及具體因果；無數值文字人物不可持碼或結算；玩家只用本人合法碼 |
| 四個行動 | A～D **恰四個實質不同且可行的教師行動**，只有一個 `emotional=true`、另三個 false；選項已完成的教師行動不得被 R 推翻 |
| 先行候選 | 先有一個合理情緒候選及六個互不重複的普通候選，實際隨機取三個，再實際隨機排列 A～D；候選與映射只保留在審查證據 |
| 八個 R | R1～R8 共用於 A～D，真正不同、客觀後果清楚、人物自主反應合理，不按好壞排序、不替其他教師或學生擅自決定 |
| NPC 數值 | 僅合法持有人及原四碼，單人單碼單 R 幅度 **−8～+8**；NPC 八 R 均值 ±3 限制**已取消**；警示要實質說明但非機械禁令 |
| 結果權重 | 每個 A～D 對八 R 各填 4／2／1／0；每列 0≤2、每欄 0≤1、每列至少一個非零；**0 只限客觀互斥，沒有 0 完全合法** |
| V3 四狀態 | **精神、熱忱、情緒、掌控**，先抽四組不重複 A～E 數值再反向寫八 R；每 R 最多兩個 0，各欄八 R 總和 −4、平均 −0.5；不能冒用已退役的體力版或 V2 門檻 |
| 時間與主題 | T 必須符合核定時間、合法前後窗口、配額、在籍及知情；不同 T 主題相同日期共享單日 6 篇創作配額。G 不可用通用情境冒充 T，P 不套用八 R |
| 禁止復活 | 已取消的 K 類／1.6、1.0、0.7 抽篇倍率不能恢復；**選哪篇故事的未定抽選配置**不得擅自補成等機率 |

### V3 四狀態的五個唯一合法組別

每篇從 A～E 隨機選**四個不同組別**，對應四種狀態；每組的八數值可隨機分配給 R1～R8，必須保持原組別多重集合，不能為故事文采反覆重抽。來源 `state_rules_version=3`；歷史版另依原版規格檢查。

| 組別 | 八個合法值（由高至低） |
|---|---|
| A | +1、+1、0、0、−1、−1、−2、−2 |
| B | +2、0、−1、−1、−1、−1、−1、−1 |
| C | +1、+1、0、−1、−1、−1、−1、−2 |
| D | +2、+1、0、−1、−1、−1、−2、−2 |
| E | +1、+1、+1、0、−1、−2、−2、−2 |

每欄總和均為 −4，等權平均 −0.5，**不是依選項權重計算期望值**。精神降低不自動表示熱忱降低，掌控不等於壓制或教師專業能力；每個非零狀態都要找到具體事件理由。NPC 單 R ±8 是另一個數值機制，不得混同。

### 4×8 的三十二格因果：不能拿數字倒推故事

1. 先列 A～D 教師**已完成**的客觀行動與八個 R 的必要前提，再對每格判「相容／敘事待補／客觀互斥」及「促進／中性／抑制」。
2. 逐格提出具體機制：4 為確有顯著促進、2 為自然可達、1 為有合理抑制但仍可達、0 為客觀互斥。**教師沒選某行動、另一人可能不配合、機率很低都不等於不可能**。
3. 檢查每列及每欄，權重只是相對值；每列以自己八項加總正規化，4／2／1 無固定百分比。每個 R 在不同合法行動下仍必須保持相同文字與數值。
4. 只要 R **原始故事、客觀後果或必要前提**改動，立即重審全部 32 格的相容性、方向與機制，合理的原權重可保留；若只修改第 4 區 AVG 演出且事實完全沒變，應核對不變項，不重抽教師四狀態或機械重判所有權重。
5. 正式證據每格至少包含 `choice`、`result`、`compatibility`、`causalDirection`、`reason`、`actionPreserved`、`weight`。不可以空泛的「合理」「有機率」取代具體因果。

## 三、GPT 必須真正審閱的七項品質門檻

| 證據鍵 | 通過標準 | 典型退件 |
|---|---|---|
| `storyAndRoles` | 校園情境、教師困境獨立；人物有其自身需要、職權、知情與合法身分，不硬套固定兩位學生 | 臨時背景人物擅自變常駐角色、教師知道不可能知道的事 |
| `fourCodes` | 原種子四碼都能指出具體情節作用與合法持有人，NPC 選角／增減因果可信 | 為湊四碼硬加毫無關聯的 NPC 數值 |
| `fourChoices` | 四個行動真有不同已完成事實／利弊；情緒行動自然可理解而非假錯項；六選三與映射一致 | 四選項只換語氣或教師行動變成別人的反應 |
| `eightResults` | 八 R 共享且轉折不同，人物有自主反應、事件有發展與合理收束；逐人逐碼與四狀態有因果，**不能替導師指定與可達選項互斥的後續行動** | 後段縮水、八 R 同義換語氣、每篇都由老師宣導原則結束、結果取消既成行動 |
| `causal32` | 三十二格逐一分析相容、方向、具體原因與實際權重 | 不可能結果硬填 1、為湊差異把 2 改成 4 |
| `timeAndLaw` | 核定窗口、當日校曆、學生在籍與資訊先後、法定程序及任課教師權責成立 | 活動日違規抽 T/G、導師擅改別科評分、私下資訊洩漏 |
| `duplicates` | 摘要及全文兩關與同池／相近 T/G 類型實質比對，整主題完稿合看全部故事 | 換姓名與道具卻重複相同衝突、選項、R 與數值機制 |


### 現代情境與年代一致性專項審查（七項品質門檻的必要子項）

這是 **`storyAndRoles`、`timeAndLaw`、`eightResults` 的跨項語意檢查**，不是第八個機械分數或新 JSON schema。每篇開場、四個選項及八個 R 都要查，AVG 同步查演出媒介：

| 檢查角度 | 核准條件 | 應修正的例子 |
|---|---|---|
| 時代與地點 | 對應故事實際年月、臺灣校園及角色所在位置；未知未來規則不冒充已知 | 2026 年高中生私下聯絡卻無理由一律寄紙本長信；預言未公告制度 |
| 日常聯絡方式 | 私人聯絡、班群、校務正式窗口分清楚，考慮是否已有聯絡方式和同意 | 未加好友卻突然收到私訊；把正式承辦郵件改寫成私下催學生 |
| 科技與數位習慣 | 手機、截圖、平台、AI、翻譯、支付、資訊查證符合當時功能及使用限制 | AI 回答當保證、截圖當校方核准、每人必有付費手機功能 |
| 校園與家庭生活 | 教學、考試、行政流程、作息、消費、交通與家庭情境自然且不越權 | 導師擅改科任評量；所有學生家庭經濟或數位資源相同 |
| 人物話語與文化 | 台灣繁體中文、身分與年齡口吻、跨文化禮儀、隱私及人際界線可信 | 為追流行塞過時梗；把對方沉默解讀為必須秒回 |
| 前後因果與 AVG | 同篇 P／R、四選項、R 客觀後果、正式原稿與 AVG 的聯絡媒介一致 | 原稿說手機草稿，AVG 演成寄出書信；尚未交換帳號就演出私訊 |

**判定方式**：需指出具體句子、故事 ID、開場／選項／R／AVG 頁面、違和理由及替代寫法；不要只做關鍵字黑名單。紙本與手寫卡有實際用途可以保留；制度或通訊方式因角色條件不同而合理，也不退件。確實修正後按 03 的局部修稿流程同步正文／AVG，對任何改動的事實及必要前提重新核對受影響的 4×8 因果，維持原有證據格式與測試節制。

### 唯一字數與創作品質規範（適用開場 P、八結果 R 與 AVG）
 
**唯一計數法（創作、原稿檢查、AVG 驗收共用）**：只算玩家可見的**實際創作正文**（台詞、訊息正文、必要旁白；含標點、不含空白）。以下**全部一律算 0 字**，不得因其長度而提高開場或結局字數：
- **程式變數**：`{{student_a.name}}`、`{{guardian_a.name}}`、`{{teacher.subject}}` 等所有 `{{...}}`，包含大括號與變數名稱，**整段刪除、不換算任何實際姓名**。
- **AVG 演出／控制欄位及其值**：人物進場 `enter`、退場 `exit`、說話者 `speaker`、表情 `expression`、姿勢 `pose`、場景 `scene`、配樂 `music`、呈現方式 `presentation`；人物 ID、表情代碼、場景代碼、陣列符號等也不算。
- **技術結構**：P 頁碼、R 編號／標題與標籤、`avg` JSON 的鍵名與格式符號、Markdown 排版標記（如 `**`）、連結網址（保留可見連結文字）、圖片／影音指令、HTML 註解、程式區塊／行內程式碼與其他非正文欄位。**若技術文字錯誤進入玩家對話框，應另判演出資料錯誤，不能把它當成創作字數。**

**先擷取正文再計數**：原稿開場合計所有 P 頁冒號後的文字；`- **P01｜旁白**：`、`- **P02｜{{student_a.name}}**：` 等整段頁碼／說話者標記一律 0 字；結局各 R 只取「玩家可見結果」冒號後的正文；AVG 只讀每頁 `text` 值並合計，**絕不能把整包 AVG JSON 序列化文字直接拿去計數**。正文裡的合法故事文字照常計入，即使恰好與技術欄位名稱同字（例如人物在台詞中說出「音樂」）。分頁不影響總字數。唯一實作 `scripts/story-visible-length.js`：`storyVisibleText` 移除技術記號、`storyVisibleLength` 計正文、`storyAvgVisibleLength` 計 AVG 頁面 `text`，所有創作審核、原稿檢查與回歸測試須沿用，不另設第二種算法。
 
| 項目 | 計數後字數 | 審閱級距（不是機械合格證明） |
|---|---|---|
| **故事開場 P（全部 P 頁合計）** | 少於 90 | 優先複核是否缺事件起因、人物互動及教師困境 |
| | 90～109 | 加強審查完整度 |
| | **110～140** | 一般參考範圍 |
| | 超過 140 | 檢查節奏、是否重講已知資訊，非硬性違規 |
| **每個 R 結局** | 少於 70 | 優先複核 |
| | 70～89 | 檢查人物反應、轉折與收束 |
| | **90～129** | 一般參考範圍，達底線不等於內容合格 |
| | 130 以上 | 檢查節奏和資訊密度，**不是字數上限** |

**創作及品質審查的優先目標**：**故事開場優先接近 140 字（一般參考 110～140），每個 R 優先接近 130 字（一般參考 90～130）**。先完整寫出人物對話、衝突、反應與收束，再依劇情自然修訂；不得以 110／90 字等下緣當成 AI 量產交稿目標。審查須特別關注長期集中在參考區間低端、卻欠缺人物互動與轉折的稿件；達到高端也不代表自動通過。**140／130 是優先創作與審查方向，皆非硬性上限、硬性最低門檻或要求湊字的配額**；確實完整的短稿可說明理由保留，必要的 150～200 字以上亦可保留，不能為求符合區間刪掉重要戲劇。已驗收故事不因計數法修正自動判不合格。

**三項最高原則（開場／結局一體適用）**：①**不重複敘述**：每頁須有新資訊、人物反應、情緒推進、動作或必要收束；已說過的事不再讓旁白／下一個人再說一遍，八 R 不可僅同義改寫。②**人物對話優先**：現場對話、通訊／電話應符合角色在場與知情；能合理演出就不要用旁白代講，禁止角色朗讀第三人稱。③**字數不能掩蓋偷工減料**：不能瞄準 90 字、為湊約 130 字灌水，或後四個 R 越寫越短。字數警示只觸發**內容複核**，不能單靠字數、speaker 數量或檢查器通過宣稱劇情品質合格。每批統計開場、各 R、90～110 字集中情形和前後批差異，僅對確實缺戲者局部修稿並同步 AVG／因果驗收。

**七項是實質判斷，不是七個保證準確的程式分數**。僅格式正確、關鍵字找到、或機械腳本成功都不能代替逐篇內容審查。G01～G11 標籤須依完稿的題材實質複核：有依據的保留，漏貼的補上，僅因出現家長、設備或教師便貼的要移除；不為全庫比例硬湊標籤。

**六選三證據格式維持程式契約**：`ordinaryChoiceSelection` 含 `ordinaryCandidates`（ID1～6、各一個不同的普通行動）、`selectedIds`（三個不同合法 ID）、`finalChoiceMap`（A～D 恰一個 `"emotional"` 及三個抽中 ID）。這些資訊、`characterAudit`、`npcDeltaAudit`、`npcWarningReviews` 及 32 格證據放正式審查紀錄，不增第六故事區塊；現有證據檢查器有既定欄位與文字長度要求，**應直接依現行程式格式輸出，不得另造不相容 schema**。審核者與結論在既有 `reviewer`、`verdict` 欄位，證據必須對應現稿 Git SHA，不可用歷史證據冒充。

### 跨日共用池逐日語意驗收（七項品質門檻中的時間／故事／結果跨項硬性檢查）

**不得只因日期欄合法、禁語搜尋沒命中、JSON 可解析或 Actions 綠燈，就判定池內各日可播放。**依 [02 正式時間規則](./02-事件分類與時間資格.md) 核對每篇 `required_window` 的**全部合法日期**；並在每一合法日期以「真的這天抽到本篇」進行語意試算：

| 審查層 | 每一合法日期都要成立的事項 |
|---|---|
| 標題、四欄摘要、必要資格 | 事件尚未／已經發生的相對階段、實際人物在籍／在場／知情、題材前提 |
| 第 4 區開場 P、四個選項 | 日曆相對詞、教師權責、選項已完成事實、現場資訊與活動前後順序 |
| 第 5 區 R1～R8 | 結局標題與正文、客觀後果、人物獨立反應、四碼因果與不可預知資訊 |
| 同篇 AVG | 開場及全部八結局每頁的時間敘述、行動與原稿事實對應，不因分頁或改寫重新引入限定日 |
| 證據與測試 | 逐篇記錄池 ID、合法日期全集、各日可用結論與例外原因、修正項目／Git SHA、AVG 同步核對、必要定向測試 |

**退件與修正閉環**：任一合法日不成立即退件；先判斷是表述限定日、故事核心需要額外時間資格，還是活動前後分池錯誤。前者同步修正標題／摘要／開場／四選項／八 R／AVG 與相關證據；若修改 R 事實或人物反應，依既有 32 格因果及數值規則重判受影響範圍。核心只能某日成立者不得假裝共用池合格，須依 02 重新確認資格。修正後**重新逐日查完整池**。文字禁語測試是防回歸輔助、非語意合格證明。沒有實際逐日人工／GPT 語意核對就明記「待驗」，不得宣稱全部通過。

## 四、AVG 內容與資料驗收：每一個結果的每一頁

| 類別 | 必須逐篇／逐 R 驗證的條件 | 可自動驗的範圍 | 必須語意審查的部分 |
|---|---|---|---|
| **原稿不變** | 原第 5 區 R 文、客觀後果、NPC 增減、教師狀態、4×8 不因純演出改寫而變 | 與基準提交逐字比對 | 是否真的保留事件的相同含意 |
| **對話／旁白／重複** | 優先以合法角色的自然台詞推進；已演出的事件不逐頁重述，必要旁白才保留。R 第五區與 AVG 須是同一套事件 | `text` 非空、`speaker` 與 `presentation` 合法；直接分頁稿可逐字比對；字數僅依上節唯一計數法 | 逐頁確認對話自然、沒有重複敘述／空泛補字、事實與知情不被演出篡改 |
| **分頁** | P 開場與 R1～R8 可獨立翻頁、前一頁、回 R 首頁；每篇唯一 `avg` 必須在 `### 開場` 前，**不可把 JSON／程式區塊印到玩家 P 頁** | `results.R*.pages` 非空、R 隔離、演出標記位置與玩家可見文案掃描 | 是否把過多敘述塞進一頁、是否在正確位置斷頁 |
| **人物與演出位置** | 現場說話／動作者須合理在場；退場後再出現須重新入場；遠端或單純被旁白提及的人不強制現場入鏡；NPC 同框≤2，各 R 獨立 | 合法角色 ID、登場狀態、進退場、同框人數 | 旁白焦點是否需要切換、遠端與現場的差異、表情與姿勢自然性 |
| **場景、特殊格式** | 背景、服裝、時段、表情／成人姿勢依情節；遠端通話用 phone/chat；家長不因被提及就站到教室 | 合法場景及表情、姿勢枚舉 | 電話與現場是否混用、演員位置及實際圖像正確性 |
| **人物知情／事件順序** | 誰先說、誰後來知道、親師秘密是否外洩、教師與任課教師是否曾真的見面 | 僅能檢查預先明列的情境斷言 | 逐 R 原文對照：順序與職權不可被台詞篡改 |
| **事件配樂** | 每篇只有一個 `music`，整個 P／R 不依結果換曲 | 音樂代碼與不存在逐 R 曲目 | 配樂情緒是否符合故事內容 |
| **正式資料版本** | 索引、故事 JSON 的 sourceCommit/sourceBranch 一致；不得用舊資料冒稱成功 | 匯出結果與來源版本核對 | P 與八 R 是否對應正確故事內容 |

**驗收證據邊界**：結構化資料回歸及版本核對不能取代逐篇劇情、角色知情、人物進退場及 AVG 台詞語意審查。

## 五、批次驗收證據與退件標準

正式審查證據使用既有 schema（含六選三、角色、NPC、32 格 `choice/result/compatibility/causalDirection/reason/actionPreserved/weight` 等），每篇對應現稿 SHA；**32 格逐格判斷、所有八 R 與合法日期的語意核對都不可抽樣或以程式綠燈代替**。具體原因須足以識別行動、既成事實與結果機制，不能以公式化空話填充。原稿事實變更須重核 32 格，純演出呈現變更僅核對不變的原稿事實與受影響資料。

每批在主題 `驗收紀錄/` 只維護**一份總報告**，正式機器證據可獨立附檔，報告不重複展開全部逐格文字。總報告最低包含：故事 ID／工作 SHA／實際核准階段、逐篇開場與八 R 正文字數（依唯一算法）及異常警示、R 與 AVG 對應狀態、人物與數值、32 格與合法日期完整通過情形、整批內容重複檢查、實際修正與未通過項目、已執行定向命令與通過數、Node 環境及必要 CI 紀錄、已發布時的資料來源版本。字數統計與十篇分段趨勢可以自動產生；只對異常、退件、改編與需要裁決的情節寫詳細說明，無須以大段重述堆砌已存證據。

**退件硬條件**：新稿有未核准的故事核心、選項互斥與 R 矛盾、人物知情／權責錯誤、不合法四碼或 V3、32 格無具體因果或漏格、日期不相容、八 R 明顯套版／縮水、原稿與 AVG 事實不一致、AVG JSON 外露或人物進退場不合理，均不得標為內容全數通過。已知錯誤必須直接修正並依變更影響範圍複核；不能把沒有執行的檢查、歷史 SHA 的成功紀錄或非本批 CI 綠燈當成本批通過證據。

## 六、局部修稿與測試節制

內容核心重複→回摘要、人物與情節；選項事實改動→核對該選項與八 R 的因果及相關資料；R 客觀事實或必要前提改動→重判全 32 格並同步 AVG／數值與正式證據；純 AVG 表情、立繪、無事實改動的旁白調整→只核對受影響演出頁面與資料。每次只重跑受影響的本機定向檢查；同一 SHA、相同輸入與相同檢查項目已通過者不重跑，遇到真錯仍修至合格。

本文件定義**驗收標準**；創作階段 `summary/choices/full`、`audit --evidence`、PR／Actions、發布的先後及按需執行規則僅見 [03 主流程第四節](./03-故事創作精簡SOP.md)，CLI 清單見 [06](./06-種子與量產管理.md)。不得因本段交叉引用再執行一輪相同檢查。P 事件及 H4 使用各自制度，不直接套用 T/G 八 R、四碼與 V3 公式。
