# 未定案事項與設計更新原則
> 本文件保留尚未確認的提案；不能當作已定規格。

## 待討論
- 起始學校環境與班級設定。
- 動態時間推進的細部排程與經營比例。
- 核心學生／家長／校內角色名單與數量。
- 數百個隱藏數值的正式欄位、公式、上下限與測試方式。
- 事件庫規模、文字製作流程、圖像美術與手機桌機介面。
- 筆記完整歷史的儲存格式、容量、備份匯出與還原。
- 教育現場制度與法規事件的引用、更新和查證方式。
- GitHub Pages、Actions、程式架構、實際開發時程。

## 文件管理原則
1. 只有使用者明確確認的選項才能更新至「已定案」。
2. 助理提供的範例、假設數值及推薦不等於使用者已同意。
3. 修改既有決策時需說明取代內容與原因，保留 Git 歷史。
4. 設計階段不自行啟用網站、部署、CI，也不寫遊戲程式。
5. 後續可在 ChatGPT 討論後更新相關文件，不要求每次重寫全部規格。

## 設計文件控制規則（2026-10-29 使用者明確要求）
- **以既有的六份 `docs/00` 至 `docs/05` 文件為主；優先修改對應既有章節。**
- **不要無止盡新增文件**；只有內容無法合理歸入六份文件時，才評估新增，並先交代原因。
- 每次統整應去重、提煉通用原則，避免將每個示範案例存成一份新規格。
- 真實素材研究由助理負責整理公共事件、來源與制度限制；使用者主要驗證教師選項和行為邏輯，**不需要無止境回答案例題**。
- 當新例子無法帶來新的核心設計能力，停止追加案例，轉向驗證已整理的共通規則。
- **研究對話可複選以協助理解使用者的行動組合；正式網頁遊戲的玩家選項一律單選。** 不得再混淆兩種用途。
- 僅實際獲得使用者確認的方向列入已定案；建議中的引擎細節及技術資料格式仍屬草案。

## 仍需規格化（新增追蹤）
- **正式遊戲為單選**；仍待規格化的是「單一選項內可包含的複合處理流程」、事件分階段銜接及文字呈現。
- 沒有即時 AI 的預寫模組化劇情如何組合出自然且不重複的回應。
- 現實新聞、法規與教師觀點如何去識別、查證、避免主觀樣本被視為普遍規則。

## 2026-10-29 已由使用者確認，應從「待討論」移出
- 正式決策節點 **3～8 個單選選項**；可有單選的複合處理方案。
- **雙類事件＋自然連鎖**、**事件驅動動態時間**、**平衡型學年節奏**。
- 相同條件與選擇仍有合理機率分歧；玩家一旦確認就鎖定結果，重整或關閉重開不能重選、重新抽籤；未選時回原事件選項畫面。
- **所有新生涯從第 1 年開始**、同一高中任教、年資等於在校資歷；**高一至高三三年一輪**，可有合理學生流動。
- 能力與群體評價由歷史逐漸累積、年資影響事件但不等於能力；生涯上限**暫定 30 學年**，可重試當前學年或另開全新生涯。

## 仍需後續決定
- 各屆班級具體人數、核心學生及家長的數量、角色與初始校園背景。
- 事件庫正式規模、每學年實際事件及決策數、事件配比、排程冷卻與抽取權重；過往建議量級及比例**均非定案**。
- 教師能力及各類評價的具體數值、演算法、上限與成長幅度；30 年為**暫定**而非不可變更的成品要求。
- 生涯完成時結局呈現、學年結算細節、歷史全文儲存與匯出備份、跨裝置同步技術。
- 美術音效、介面、開發工具、Pages／Actions 及實際開發時程；目前仍只設計，不寫遊戲程式或部署。
