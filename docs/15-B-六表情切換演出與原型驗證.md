# 第 15-B 批｜student-001 六表情原地切換：動畫規格與精準原型驗證

> 2026-11-07 依使用者要求：**人物在同一位置，隨劇情對話切換表情；最低標準淡出淡入，優先採更自然的交叉淡化**。原型 HTML 見 [student-001-expression-switch.html](../artwork/prototypes/student-001-expression-switch.html)。該 HTML 為隔離測試，不接正式遊戲、不改事件／存檔／世界數值、不代表已完成真正臉部分層。
>
> 權威來源：[B1～B23 美術規範](./15-B-正式美術原型規範.md)、[六表情美術品質準則](./15-B-學生六表情製作風格與失敗案例準則.md)、[美術進度簿](./15-B-美術素材命名與製作進度簿.md)。

## 一、定案方向與切換視覺

1. **原地固定**：角色容器、橫向站位、上下錨點、縮放比、裙襬底線及人物中心都不動；不為每次換表情執行進場滑動、彈跳、縮放、鏡頭移動或整體重繪。
2. **短交叉淡化（crossfade）**：舊表情漸淡，新表情同時漸顯，暫採 **180ms ease-in-out** 作第一版候選，後續可比較 120／180／240ms 的主觀感受。比「舊臉完全消失才顯示新臉」更連續。這是**測試參數，尚未完成真機封版**。
3. **固定基底避免整身閃暗**：原型保留 `student-001-base-uniform-summer.png` 當**永不淡出的底圖**，其上兩張同畫布 PNG 圖層交錯切換；原圖與表情圖的髮型／制服／身形 RGB 和 Alpha 必須保持一致，否則交叉疊色仍可能造成跳動。因為完整人物 PNG 不是實際臉部圖層，這只是**過渡方案**。未來真實眉眼嘴／臉部圖層可僅對改動區域淡化，身體維持一張固定底圖，視覺更佳且資源更省。
4. **說話者亮度與表情動畫分離**：對話中最多兩名 NPC；亮度變換只影響說話者／聆聽者的整體呈現，不需要重新載入圖片，也不能把說話者改變誤判為表情更換。旁白時雙方正常亮度。
5. **進場與退場不同規則**：角色首次出現、離開場景才能針對整體角色淡入或淡出；同一角色連續對話只換表情。電話不顯示遠端立繪，聊天與公告依既定 UI，不強行套人物淡化。
6. **尊重降低動態效果**：`prefers-reduced-motion: reduce` 時直接切換表情，無須等待動畫；圖片尚未解碼或缺圖時保持既有畫面、顯示 calm 或中性替代，而不短暫黑畫面。
7. **只在表情鍵改變時播放**：同一角色同一表情，翻頁不應重播；回上一頁應呈現該頁合法表情，不偷讀未來劇情。快速連續點擊時以最新合法頁為準，取消／取代尚未完成的切換而不是排隊演出，不能因此阻擋故事或影響選擇確認。

## 二、已查到的正式網頁現況與必須解決的問題

- `web/story-scene.js` 的 `projectStoryScene()` 已使用 `page.cast` 的合法 `actorId`、`expression`、`position`、`speaker` 投影；`renderStoryScene()` 目前仍輸出 CSS 人物占位圖，沒有讀取這批 PNG，也沒有固定的人物圖片 DOM。
- `web/story-view.css` 的 `.story-actor` 目前採 `story-cast-in .2s` 進場動畫；若在表情更新時重建元素，此動畫可能每頁重播。正式接線時須以「actorId + 合法位置」做穩定識別，將登場動畫和表情更換動畫拆開。
- `web/game.js` 的 `showGame()` 呼叫 `set()`，而 `set()` 透過 `app.innerHTML = ...` 重建整個畫面；**只增加 CSS transition 無法跨 DOM 重建產生平滑交叉淡化**。正式整合需保留場景人物 DOM、或在更新前後接力既有合法圖片狀態（包含取消中的動畫）來轉場。不能靠未經確認的全頁重新掛載假裝「原地」。
- `artwork/` 原始美術檔現在沒有被網頁 build 複製；**隔離原型的相對 PNG 路徑只適用於有正確資料夾結構的本地靜態伺服器**。正式 15-D 應由已核准資產進 `web/assets/`，以 manifest 維持相對 URL；本次沒有偷偷修改正式資產位置或部署。
- 現有 `appearance.variant % 6` 僅是占位色調，不是真正學生外貌映射。不能為示範 student-001 擅把任意 NPC 永久指向同一張學生圖。

## 三、原型範圍與執行方式

新增 `artwork/prototypes/student-001-expression-switch.html`，只驗證切換機制：

- 使用一張 calm 基礎母圖＋同資料夾的五張已接受表情 PNG，選擇按鈕分別切換 calm／happy／surprised／angry／sad／embarrassed。
- 角色位置與顯示尺寸不隨表情改變；背景固定；底層 calm 長駐，兩張覆蓋圖交替淡入淡出。
- 圖片先嘗試預載，缺圖不切、畫面保持原樣；快速操作只處理最新選擇；降低動態偏好改為直接切換。
- 這個原型沒有遊戲事件、正式 NPC、對話翻頁、儲存或選項，**不能把原型檢查合格直接寫成正式遊戲通過**。
- **執行注意**：以可讀取完整儲存庫 `artwork/` 路徑的本地 HTTP 靜態伺服器打開 HTML 才能載入原圖；單看 GitHub 檔案頁不會播放動畫。尚未合併 main、未部署 Pages。

## 四、必要精準驗收（不產生任何驗證圖片）

| 項目 | 檢查方式 | 通過標準 |
|---|---|---|
| 六圖齊全 | 程式讀取 PNG metadata／資產清單 | 1 calm+5 表情，路徑都存在、尺寸相容、可解碼 |
| 角色固定 | 同一個容器前後的尺寸、位置、中心線 | 表情更換不移動、變大、跳入或跳出 |
| 交叉淡化 | 本地瀏覽器快速切換並目視動畫 | 只有表情順暢變化，人物服裝不變暗或閃白 |
| 不重播 | 同表情翻頁、相同說話者連續頁 | 人物不再做進場動畫 |
| 反覆切換 | calm→happy→sad→angry→surprised→embarrassed→calm、快速連點 | 最終顯示最新表情，不殘留重影或堆積動畫 |
| 身分穩定 | 兩名 NPC 分別切換表情及說話者 | 不交換人物臉、位置或錯用亮度；只動畫有變化的一方 |
| 手機／桌機 | 手機直式、桌機橫式 | 文字框與選項可讀、主要臉部不受遮擋，不截斷關鍵部位 |
| 無障礙／故障 | 減少動態偏好、缺圖、網路慢、回頁 | 不中斷故事，回退平靜、不讀取未來資訊 |
| 相容性 | 正式接線階段 | 不改世界數值、存檔 schema、故事操作／頁碼／選項 |
